# 上线检查清单

本清单从项目的审计、合并、故障复现和验收记录中提取通用项，保留原数据库与性能检查，并补齐构建、鉴权、协议、计费、交互及部署生命周期。整理日期：2026-11-15；来源见下方索引。它是每次发布重新执行的模板，不表示当前工作区已经通过验收。

每项记录 **通过 / 失败 / 未执行 / 不适用**、证据位置和执行人；只有通过才勾选。不适用必须注明业务或协议依据，不能把环境不可用、上游不支持或测试跳过记为通过。每次发布都须盘点全部功能、页面、后台任务、API 和配置，既有功能与新增功能同等重要，不得仅以变更范围或 AI 请求相关性决定是否纳入验收。从小到大执行各层回归；变更及其关联路径补充专项。数据库迁移等条件项按实际适用范围执行；历史通过结果必须核对源码、产物、配置和环境是否仍适用。

**集成验收要求（2026-11-15 修订）：AI 接口的调用方式由客户选择，浏览器、SDK、命令行、服务端和第三方应用都是独立验收入口。** 不得要求客户先登录管理页面、保留浏览器会话，或仅在页面不支持某协议时才测试外部客户端。管理配置入口、AI 请求入口和结果核验入口分别记录，不要求三者使用同一个客户端。

每次发布同时覆盖以下链路，接口测试通过、页面测试通过，不能合并推断业务集成通过：

- **页面功能集成：** 真实浏览器操作 → 实际后端保存/鉴权 → 配置生效 → 由适用客户端发送 AI 请求 → 上游行为及异步结算/日志 → 浏览器结果回查。待测页面操作必须实际执行，不能用 API 写入替代；AI 请求可由 SDK、命令行或其他客户端发起，即使页面已有对话入口也一样。
- **独立 API 集成：** 已生效配置与模型 API 凭据 → 无管理页面会话的实际客户端 → 真实服务路由/上游 → 客户端实际消费结果 → 账本、日志和任务终态核验。可以通过授权管理 API 准备配置、查询结果；无需先打开或回查浏览器。此结果证明 API 链路，不能抵作页面功能验收。
- **混合与状态变化集成：** 浏览器或授权管理 API 修改配置/权限，同时由多个客户端持续调用，验证生效范围、进行中和新请求、重试及最终账务。存在多个管理入口时分别覆盖其合同，不能相互替代。

不可能穷尽客户使用的所有软件版本和网络组合。覆盖范围应按本次支持的协议合同、客户端行为、配置和接入拓扑建立可扩展矩阵，保留未覆盖项；不能把几个客户端通过写成“任何客户端、任何情况均通过”。

## T. 测试颗粒度与执行顺序（每次发布，从小到大）

每层单列用例和结果；小粒度测试便于定位，大粒度测试验证实际组合，互不替代。以下客户端和系统集成运行于隔离预发布环境；底层可以使用 fixture，完整业务集成使用真实后端、数据库及实际启用的 Redis，涉及页面时使用真实前端，仅上游服务使用受控 mock。

- [ ] **T1 — 字段、函数与规则。** 覆盖解析/序列化、表单映射、校验、策略选择、协议转换、用量归一化和价格计算的正常值、等价类、边界、缺省/空值/显式零、非法输入及独立条件分支。断言可观察业务合同，不以行覆盖率替代正确性。
- [ ] **T2 — 组件与模块协作。** 前端验证真实表单组件、状态管理、校验、保存协调和查询缓存的协作；后端验证模块内真实调用链、配置快照、重试状态和生命周期。覆盖旧数据编辑、部分失败、并发刷新及清理；逐项标明 mock 边界，组件测试不冒充浏览器端到端。
- [ ] **T3 — API 与实际存储集成。** 经真实路由、鉴权、中间件、服务、数据库/缓存验证读写、权限、事务回滚、发布和失效。覆盖正常/拒绝/故障结果以及生效前后状态；已有数据库矩阵要求见 C 组，单独调用 handler 或 mock GORM 不替代本层。
- [ ] **T4 — 实际客户端业务端到端。** 分别记录页面功能集成、独立 API 集成及混合链路的结果。页面场景用最终前端产物完成真实登录、导航、填写、确认、保存及结果回查；独立 API 场景使用 P 组客户端，以模型 API 凭据完成请求、响应消费及后台对账，验证无浏览器登录或 cookie 仍可使用。两类场景都必须关联实际请求与最终业务结果；不得拦截接口伪造成功，也不能把独立脚本与无关联截图相加认定通过。
- [ ] **T5 — 跨配置、跨模块与协议组合。** 在 T4 各类适用链路上组合用户/令牌/分组/渠道/全局配置、重试切换、权限变更、协议转换及计费。按 M/P 组逐项和成组验证所有支持的入口与协议；覆盖成功、拒绝、异常、中断、恢复，以及配置生效和撤销后的反向验证。
- [ ] **T6 — 并发、故障与部署生命周期。** 对完整链路执行混合负载、慢客户端、后台任务竞争、依赖故障、配置并发更新、多节点传播（部署适用时）、升级和启停恢复；高并发 AI 流量与实际浏览器管理操作同时存在。按 I/J 组核对吞吐、尾延迟、账本和资源收敛。前序正确性失败先归因修复，再重跑失败层及受影响的上层链路；容量通过不能覆盖功能失败。

## U. 全部功能与页面覆盖矩阵（每次发布，2026-11-17 补充）

- [ ] **U1 — 全部功能有名册。** 双向核对设计文档、菜单、实际路由、页面/分区注册、弹窗/抽屉/标签页、API 路由、配置注册和后台消费者。列出所有业务模块，既有和新增功能使用同一验收标准。组件文件存在或可被 import 不等于页面有入口；默认标签页打开不等于全部分区已集成。设计待确认、明确暂缓、API 专用和已废弃能力分别注明当前代码依据，不能混作已实现。
- [ ] **U2 — 每个字段有完整映射。** 对每个应提供界面的字段，记录实际入口、控件、读取/提交 key、权限 scope、默认值、合法边界、持久化字段、运行时消费者及生效时机。特别查找只有 schema/defaults/types、没有渲染控件的字段，以及 UI 接受但运行时静默截断的数值。明确 API 专用或内部配置的入口及理由；无前端字符串引用只是线索，需追踪别名、动态字段和实际代码后定性。
- [ ] **U3 — 每个操作有用例和结果。** 逐页面列查询、筛选、排序、分页、详情、新建、编辑、删除/禁用、批量操作、导入、导出/下载、任务状态和恢复等实际适用操作，展开条件显示的控件、弹窗和抽屉。真实页面操作后核对实际后端结果，再刷新/重新进入回查；涉及异步任务时等待终态并验证产物。每个未执行操作保留独立条目，不能用同模块其他操作通过覆盖。
- [ ] **U4 — 权限、状态和布局有交叉覆盖。** 分别验证匿名、普通用户、员工、有/无对应权限的管理员及 Root 的可见性和服务端拒绝，覆盖跨用户/跨客户访问。检查默认、已有数据、空态、失败、加载、取消、重复提交、过期会话和并发刷新；记录桌面/窄屏、浅/深主题、全部支持语言的实际范围。自动检查页面无横向溢出不能替代对控件遮挡和交互可用性的检查。
- [ ] **U5 — 旧测试与当前合同一致。** 为功能和字段关联具体测试编号、断言、mock 边界、候选源码/产物散列和原始证据。检查既有用例是否仍匹配当前业务合同；合同冲突先查明原因，保留失败，不通过删除断言、改成页面文本非空或忽略失败获得绿灯。语言文件之间 key 对齐还需加源码实际使用 key 和占位符检查。
- [ ] **U6 — 放行逐项判断。** 页面可达、控件存在、业务保存、运行时生效、独立 API 和混合集成分别记录。HTTP 200、文字长度、截图、构建或单测通过不能合并推断功能集成通过。缺少依赖、凭据、fixture 或目标环境时记未执行/受阻及原因；未解决缺陷或未完成必测项不得标记全量通过。先前报告的宽泛“通过”需按实际断言重新分类。

## M. AI 请求逻辑与配置覆盖矩阵（每次发布完整盘点）

- [ ] **M1 — 配置逐项有映射。** 从当前路由/适配器、`setting/` 注册项、配置权限注册、前端设置分区及用户/令牌/渠道表单双向盘点，列出每个相关配置 key、入口、默认值、合法范围、继承/覆盖关系、运行时读取点及测试编号。不能只检查本次改动的页面或已有测试；后端有配置而应有界面入口缺失、界面保存字段未被消费、逻辑没有覆盖用例，都必须记录。仅后端或部署配置写明入口与理由，不伪造 UI 覆盖。
- [ ] **M2 — 单项、组合与状态转换。** 每项先测默认、各枚举/开关、边界、继承及恢复默认，再检查相互作用；对等价维度可用成对组合扩展覆盖，但权限、路由、超时/重试、预扣/退款等明确依赖链必须覆盖实际条件路径及多项同时触发。列出已测组合和缺口，不能用“选了几个代表值”宣称所有组合已过。
- [ ] **M3 — 生效证据与隔离。** 执行前写明每阶段的预期结果；每个场景保留初始配置、实际配置入口与提交值、后端持久化/生效值、请求客户端及版本、关联用户/令牌/渠道、request_id/任务 ID、上游观察、客户端收到的响应和账本。页面场景另保留浏览器操作及页面结果；纯 API 场景注明结果查询方式。使用同一场景标识贯穿全链路；客户端重发、网关重试及异步阶段分别记录 ID 映射。用可区分的配置前后值及正反对照证明行为改变，并验证其他用户/渠道不被串改；收尾恢复后复测。

## P. 客户端、传输与接入覆盖（每次发布）

客户端类别与协议是两个维度。同一协议经自写 HTTP 脚本通过，不代表 SDK 的序列化、事件解析和自动重试已经通过；同一 SDK 通过，也不代表所有协议、版本和第三方应用均兼容。以下类别用于盘点，具体版本、接口和组合写入本次记录；存在能力差异时按实际支持范围填写，不伪造调用入口。

| 客户端类别 | 必查场景与边界 |
| --- | --- |
| 浏览器 | 本站对话/测试入口、第三方网页直接调用 API 分开验证；覆盖同源/跨域、流式读取与主动取消，使用独立测试凭据 |
| SDK | 记录本次支持的官方或兼容 SDK 名称、版本、语言及运行时；覆盖适用的 Python、JavaScript/TypeScript 客户端，实际调用其请求构造、流式迭代和异常处理 |
| 命令行与 HTTP 脚本 | curl 等直接 HTTP 调用，无登录态、无 cookie、无 Origin/Referer；覆盖 JSON、流式、文件上传下载，命令及输出不含明文凭据 |
| 服务端与自动化 | 后端服务、批处理、Agent/工作流通过 API 调用；覆盖连接复用、并发、长请求、定时任务和进程退出，不依赖人工打开页面 |
| 桌面、移动端及第三方应用 | 按支持范围和已知客户场景记录应用/版本、原生网络或 WebView；覆盖切后台、网络切换、取消/重连、应用代理及自定义 Base URL；未运行的应用保留缺口 |

- [ ] **P1 — 可追溯的客户端矩阵。** 为“客户端/版本/运行时 × API 入口与协议 × 凭据方式 × 配置场景 × 网络路径”建立用例映射。浏览器、实际 SDK、命令行和服务端均须有独立基础结果；第三方应用按声明支持范围补验。相同语义使用可比输入和已知上游输出，核对响应、usage、路由与账务；发现差异先检查 SDK 默认参数、重试和客户端配置。未知客户端按公开协议合同验证，不能靠 User-Agent 白名单或伪装浏览器才能使用。
- [ ] **P2 — 独立 API 凭据与会话边界。** 仅使用有效模型 API token，在无 dashboard 会话、无 cookie、无 Origin/Referer 时完成允许的 AI 请求；分别改变/省略 User-Agent，验证调用不依赖特定客户端标识。按路由核对 Bearer、Claude `x-api-key`、Gemini header/query、WebSocket 子协议等实际支持方式及多个凭据同时出现的优先级；禁止将某入口的兼容方式推及所有接口。覆盖失效/撤销/越权和缺失凭据，dashboard Bearer、管理 PAT、模型 API token 按各入口授权合同使用，不能互相冒用或提权；会话刷新/登出的来源保护不能误加到模型 API 上，也不能为兼容 API 关闭后台会话保护。URL、WS 子协议及代理日志中的凭据同样脱敏。
- [ ] **P3 — 浏览器专属约束。** 第三方网页使用真实浏览器执行 OPTIONS 预检与实际请求，核对 Authorization/厂商自定义头、Content-Type、允许方法和需读取的响应头；分别记录不携带 cookie 与显式携带 cookie 的行为及支持边界。`Access-Control-Allow-Headers: *` 不能替代对 Authorization 的显式允许，携带 cookie 的跨域响应不能使用 `Access-Control-Allow-Origin: *`，按 [Fetch CORS 规范](https://fetch.spec.whatwg.org/#http-cors-protocol)实测。WebSocket 另测 Origin、升级及子协议认证；curl 返回 200 不证明浏览器能读取，CORS 放行也不替代服务端鉴权。
- [ ] **P4 — 真实接入与代理链路。** 同时验证隔离环境直连和与目标部署等价的域名/TLS → 实际 CDN/WAF/反向代理（如有）→ 网关链路，记录拓扑与配置。核对 Base URL/路径前缀、重定向、证书校验、DNS、实际启用的 IPv4/IPv6 和 HTTP 版本、授权头保留、SSE 缓冲/压缩/空闲超时、WS Upgrade、上传大小和产物下载/Range；不能关闭 TLS 校验或只测容器端口就判公网入口通过。结合 `TRUSTED_PROXIES` 验证真实来源 IP、伪造转发头、IP 限制及共享出口场景，错误页和缓存不得混入 AI 响应或泄露其他用户结果。
- [ ] **P5 — 客户端超时、重发与断线恢复。** 记录并分别执行客户端自动重试关闭及实际启用策略；覆盖客户端截止时间早于/晚于网关、429/5xx、响应丢失后的重发、流式取消/停读、WS 多轮与重连、移动端切后台/换网，以及任务提交成功但回包丢失。分别计数业务操作、入口 HTTP 请求、网关尝试和上游调用，关联每次日志/账本，检测重试叠加和额外费用。一次逻辑操作可能产生多个独立请求；只有接口明确支持幂等键时才按其去重合同断言，不能假设所有相同正文自动去重。断线后的继续执行、停止、退款及恢复依实际策略验证，不一律要求退款或无缝续传。
- [ ] **P6 — 客户端实际可消费。** 使用客户端自身解析器核对 JSON 返回对象、SSE 增量/终态、WS 事件、multipart 上传、二进制下载及异步轮询。验证分片、UTF-8 边界、工具参数、usage、Content-Type、HTTP 状态和协议内错误均可正确消费；管理 API 的 HTTP 200 + `success:false` 与 AI 协议错误分别处理。连接建立、SDK 未抛异常、网关成功 Write/Flush 或浏览器出现文字都不单独证明完整交付；将客户端实际收到的数据、上游完成事实和结算依据分别保存，并核对取消后资源回收。

- [ ] **A1 — 固定候选。** 记录分支、完整提交号、未提交及新增文件清单/散列、前端构建输入、最终二进制 SHA256、Go/Bun/Node 版本。核对实际运行文件散列；HEAD 相同不代表工作区或运行版本相同。

- [ ] **A3 — 保留完整结果。** 留存命令、退出码、环境、原始失败及修复后结果；区分单次全量、分包复测、定向测试和测试专用 overlay。测试跳过、夹具/顺序污染、标准入口失败和替代命令结果均单列，不用放宽断言、删失败或合并计数制造“全绿”。

## B. 构建、依赖与上游合并（每次发布；专项按变更触发）

- [ ] **B3 — 独立模块与插件。** 修改 `relaykit/` 或其公开 API 时，在该目录设置 `GOWORK=off` 后独立 build/test/vet；其他受影响独立模块同样验证。修改任务插件或宿主时核对 `docs/plugin-api/v1.md`、schema/类型声明，并运行 `bun run lint:plugins`、`bun run format:plugins:check`。
- [ ] **B4 — 依赖安全。** 对最终 Go 工具链、模块和前端锁定依赖运行漏洞检查（如 `govulncheck`、`bun audit`），审阅发现及可达路径，区分生产运行、浏览器产物和开发依赖。JSON 扫描退出码为 0 不等于没有漏洞；保留修复、适用性核查或未解决项的证据。
- [ ] **B5 — 上游基线。** 合并上游或进行 main 对照时获取最新官方 main，记录 revision/二进制散列，部署测试栈及测试前再次核对远端。保护的五个 `web/src/lib` 认证/HTTP 文件与所采用上游版本逐字节一致；上游测试遵循仓库保护规则。核对渠道枚举及 Go、前端、插件中 58–63 等硬编码，防止编号错配；本地旧 `main` 名称不能代替已核验的官方基线。

## C. 数据库与大数据量（数据库行为、查询或清理受影响时）

- [ ] **C1 — 迁移和索引盘点。** 列明表、列、类型、默认值、索引、ORM/驱动及连接协议变化，核查线上实际索引列和顺序。检查同名但定义错误的旧索引是否会被修正，例如审计表四个历史不完整索引；不能仅凭索引名字存在认定迁移完成。统计大表行数、大小和剩余磁盘。
- [ ] **C2 — 目标 schema 演练。** 在隔离库加载目标服务器 schema-only 副本，核查真实数据是否冲突于新增唯一约束，并以代表性数据量演练升级。记录每条 DDL、总耗时、锁等待和磁盘增长；不支持的在线 DDL须安排预部署迁移窗口，不能忽略启动拒绝。升级基线须对应线上旧版，而非任意本地 HEAD。
- [ ] **C3 — 真实数据库矩阵。** MySQL、PostgreSQL 分别验证新库、旧版应用升级和连续两次启动，第二次不得重复 DDL；使用本次选定的新版稳定数据库，记录服务端确切版本及镜像摘要。按用户 2026-11-15 要求，本轮不使用旧版数据库；项目最低版本兼容承诺不等于本轮已验证。另按生产环境（本地记录：`docs/production-environment.md`）完成主库与独立日志库组合的全应用验收，单库测试不能替代。SQLite 不纳入检查；未启用的 ClickHouse 专项记为“不适用”。单方言、mock、编译或定向迁移函数测试不替代全应用启动验收。
- [ ] **C4 — 存储语义。** 验证 NULL/false/true、零值、默认值、字符串补空格/编码、Scanner/Valuer 和历史数据保留。涉及 ClickHouse 时覆盖新表、缺列旧表、Nullable(UInt8)/Nullable(Bool) 身份三态，并检查原生 TTL 与应用保留设置一致；永久保留不能仍被数据库 TTL 删除。
- [ ] **C5 — 查询计划和写入成本。** 用代表性数据分布核对 EXPLAIN、时间边界、游标/分页、排序及联合索引；LIMIT 不等于扫描量有界。检查新索引对持续写入、删除和磁盘的成本，避免跨主库/日志库 JOIN 假设或无界历史聚合。
- [ ] **C6 — 原子性和缓存。** 对管理批量更新验证权限集合、混合/无效 ID、并发冲突、事务超时回滚和缓存发布。渠道无变化提交不写 channels/abilities、不重建缓存，备注及日限额不重建能力；状态与日限额标记原子更新。不能出现部分提交却报告全部成功，或提交失败后发布新缓存。
- [ ] **C7 — 大量存量数据升级启动。** 升级前为所有受影响的业务表及共享的大表准备大量数据，覆盖主库、独立日志库、关联子表、历史/近期数据和热点分布；记录逐表行数、大小、数据跨度及与生产的差距。配置表、单例状态表按实际基数准备，并列明原因。新表先验证首次创建，再填充大量数据验证再次升级与启动。空库、小样本或只给单张表造数不能替代本项；必须测完整应用从进程启动到就绪的时间、各条 DDL、锁等待、数据保留和第二次启动的重复 DDL。
- [ ] **C8 — 风险标注与生产确认。** 每项有问题或仍有风险的数据库操作必须列出编号、代码位置、触发条件、表/索引、影响、已测规模、生产待确认条件和处理方案。明确区分“代码问题已修复”和“生产风险已验证”。建表/加列/改类型/建索引/重建索引、历史回填、大批量更新删除及共享连接池竞争均须核查。发布负责人依据线上实际版本、schema、行数、索引、长事务、写入速率、磁盘与复制情况逐项确认并填写证据；未确认或超出预算时阻断上线，不能以本地通过代替生产确认。当前风险登记见 数据库性能审查（本地记录：`docs/design/database-performance-review-20261115.md`）。

## D. 鉴权、敏感操作与审计（每次登录冒烟；相关变更执行完整矩阵）

- [ ] **D1 — 凭据和权限矩阵。** 登录、刷新、登出及失效凭据实际走 HTTP 验证；区分 dashboard Bearer、管理 PAT 和模型 API token，结合 P2/P3 验证各入口的会话与来源边界。相关接口覆盖匿名、普通用户、只读/普通管理员、root，检查 scope、跨用户/跨员工/跨渠道归属、批量操作和直接调用 API，不能只验证按钮是否隐藏。认证相关变更按本次最新 [OWASP ASVS](https://asvs.owasp.org/)、[Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html) 和 [Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html) 核对适用控制并记录版本与未解决项。
- [ ] **D2 — 生命周期和并发。** 认证改动覆盖过期、撤销、权限收回、账号禁用/删除、刷新竞争/重用和跨标签页同步。密码恢复/二次验证覆盖一次性消费、并发重放、重新发码、改密后旧凭据失效及多实例/重启行为；令牌校验通过不能代替提交时的状态复核。
- [ ] **D3 — 提交后故障。** 注入密码、权限等敏感事务提交前后的缓存/会话清理失败，核对数据库、实际认证结果和响应一致性；不得把“接口失败”直接解释成“数据没改”。确认用户可恢复操作，未完成的撤销或清理可追踪。
- [ ] **D4 — 审计事件合同。** 核对网页、PAT、批量和匿名恢复等入口的成功/失败事件、操作者、目标、实际变更字段及告警规则一致。HTTP 200 还须检查 `success`；日志存在不等于告警已触发。后台告警合并不得覆盖管理员并发提交的处理状态和版本。
- [ ] **D5 — 敏感信息和外部访问。** 检查响应、日志、诊断、审计及测试报告中的密码、验证码、令牌、密钥、DSN 和签名地址脱敏。涉及插件/内容代理/通知/第三方查询时，验证允许目标、重定向和超时边界，防止本站凭据被带到无关域名；用本地 fixture 验证通知成功、拒绝、取消和连接回收。

## E. 配置与前端集成（每次发布覆盖全部功能；逐项范围见 U 组）

本组验证产品页面及其后续业务效果，不限定客户发送 AI 请求的工具。页面操作必须实际完成；独立 API 场景按 T4/P 组另行验收，不要求先完成页面操作才能发请求。

- [ ] **E1 — 设置完整链路。** 核对前端字段 → API key/module → scope 注册 → 服务端校验 → 持久化 → 运行时 getter → AI 请求实际行为。通过浏览器保存后 API 读回、刷新回显，并用已知输入触发预期路由、超时、拒绝或计费变化；按热配置/重启生效约定验证。覆盖单键、分组及批量入口，保存成功和读回正确不能代替运行时验证。
- [ ] **E2 — 草稿和失败重试。** 检查同页保存覆盖全部可编辑分区、无权限字段不提交、无变化不请求、重复点击只提交一次。后台刷新不覆盖草稿；部分失败只更新成功部分的基线，失败字段可重试；确认取消、loading 和只读状态符合实际请求结果。
- [ ] **E3 — 默认值和覆盖优先级。** 覆盖缺省/继承、显式 false/0、开启/关闭、旧配置迁移及非法边界。对全局/渠道/用户覆盖核对优先级，重试切换渠道重新取策略，单次尝试使用一致快照，不因设置读序或运行中变更混用配置。
- [ ] **E4 — 生产前端验收。** 检查真实发布包首页及引用的 JS/CSS 可访问且散列一致；浏览器完成登录和 U 组全部页面的适用操作，核对控制台错误、窄屏、浅/深主题及各角色可见性。逐页确认预期标题、入口、控件和真实请求结果，识别 404、登录重定向、权限页及条件未满足的空壳。静态资源 HTTP 200、组件测试或静态审查不替代浏览器交互。
- [ ] **E5 — 文案和错误。** 全部实际使用文案覆盖 en、zh、zh-TW、fr、ja、ru、vi，插值占位符和静态键一致；同时核对源码 key 与各语言资源，不能只检查语言文件互相对齐。涉及后端用户文案同步实际语言资源。错误、空态、等待和导出进度给出用户可执行的提示，不泄露 Go 错误、服务器路径或无权限诊断。
- [ ] **E6 — 同一场景的界面与请求闭环。** 浏览器创建/编辑本次用户、令牌、渠道和相关设置后，使用这些对象执行 F2 链路，再到真实日志、钱包、渠道状态或任务页面验证结果与后台事实一致。AI 请求可由 P 组任意适用客户端发起，必须包含外部客户端使用页面保存配置的场景，不以界面是否支持该协议为前提。已有对话/测试页面自身另做浏览器验收；`/pg` 会话调用不能代替公开 AI API token 路径。初始化 fixture 可用 API，待测页面操作仍须真实执行；纯 API 链路单列于 T4/P 组。
- [ ] **E7 — 失败与恢复也要集成。** 在隔离环境触发保存拒绝、会话过期、部分保存失败、并发刷新或后台延迟；核对界面提示/草稿、实际持久化值和后续 AI 请求仍采用哪份配置。重试保存或恢复权限后，再次验证实际请求和结果页，不能只断言错误 toast。

## F. 主链与协议（每次发布基础矩阵；相关变更扩大覆盖）

- [ ] **F1 — 主链影响审查。** 在设计中明确同步/异步工作、功能开关及故障降级。逐项搜索共享 DB 表、Redis 命名空间、内存缓存、连接/worker 池和文件资源；确认没有新增热路径同步写入、无界 goroutine、跨上游调用持锁或等待非关键后台任务。
- [ ] **F2 — 实际渠道验收。** 使用客户端 → 本分支已配置渠道 → 最新官方 main 已配置渠道 → 鉴权 mock 的真实部署链路；核对 mock 到达证据，逐层保存响应、usage 和落库结果。对照须使用相同跳数和有效输入，不能把内层 main 已规范化的回包当成原始 mock；内存 handler 测试不替代此步骤。
- [ ] **F3 — 协议覆盖清单。** 同时盘点本分支实际路由/适配器与本次 main 的协议清单，枚举 JSON、SSE、WebSocket、multipart/二进制和异步任务，再与 P 组客户端交叉映射；本分支特有入口不能因 main 不支持而漏测。新增协议缺 fixture 时报告缺口；main 无法承载的特有能力另走隔离鉴权 mock 专项，注明边界，不能冒充或替代 F2 兼容验收。覆盖原生与转换入口、文本/工具/推理/音频/图片、正常及异常终态、分片/末行、错协议、非法/缺失/零 usage；适用时检查 StreamOptions 与可选字段显式零值往返。未实现/禁用接口核对稳定错误且不误调用上游、不收费，不能仅凭路由注册就计为支持。
- [ ] **F4 — 错误与交付。** 覆盖 HTTP/业务错误、空体、坏 JSON、截断、EOF/RST、慢头、空闲/总超时、慢读/停读客户端、取消及 Write/Flush 失败。分别核对上游完成、下游实际交付、错误来源和最终计费，不能因 HTTP 200 或收到终止标记就认定全部成功。request ID 是各请求独立生成的诊断信息，验证其记录及关联，不能因 ID 或错误消息尾部的 ID 附注不同判失败；排除该动态字段后仍严格比较状态、错误类型/代码、业务消息、usage 和事件顺序。官方参考本身不符合协议时单独归因，不要求候选复制参考缺陷。修正验收误报时保留原始响应与散列，并区分离线重放和重新部署测试。
- [ ] **F5 — 重试与时序。** 校验总预算、单次超时、重试次数/状态码、渠道切换及已交付后的重试边界；资源不足不得误封渠道。与 P5 的客户端自动重试及代理超时组合执行，分别计算各层尝试次数，不能将 SDK 重发误认为网关同一请求重试。两层截止时间相同时增加 main/main 对照和收发时间线，区分时序竞争与候选差异；受控补测不能抹去原始失败。
- [ ] **F6 — 开关与资源回收。** 严格/兼容模式分别验收：关闭时比较 main 的状态、事件序列、usage 和账单，开启时验证协议拒绝及原收费合同。覆盖 body 预算/帧大小边界、磁盘满、读写失败、重复关闭和配置下调，确认请求结束后内存预算、文件、连接及 worker 归还。

## G. 计费与账务（每次发布基础矩阵；相关变更扩大覆盖）

- [ ] **G1 — 独立复算。** 依据本次请求的计价快照独立计算表达式、分组/渠道倍率、阶梯边界、工具附加费、固定/免费价格和整数舍入；核对公开价格、编辑值、模型别名/映射及实际结算优先级。不能用同一实现算出的结果互相证明，也不能要求不同配置的两层绝对金额相等。
- [ ] **G2 — 用量口径。** 核对输入/输出、缓存读取、缓存创建及 5m/1h 明细、音频等细分，区分缺失和显式零、上游确认和估算。分别追踪提供方原始用量、官方 main 返回与结算、本分支返回与结算、本站最终钱包净额，定位首次丢失及责任层；公开字段、内部计费用量、消费日志和钱包实扣不能互相替代。按协议归一化，检查合计/明细矛盾、重复 usage 及负/非法字段；负 token 与负扣费分别报告。按用户 2026-11-15 的本轮范围，仅将已确认本站少记用量或少收费列入用量修复；多收保留证据、不作本轮修复，不能为对齐公开字段或 main 而降低已有计费用量。两分支相同也须排查共有缺陷，金额比较须使用各自价格快照。
- [ ] **G3 — 资金闭环。** 等待异步结算稳定后，以 request_id/任务 ID 和时间窗口关联实际响应、各层日志、用户余额、token 余额/used_quota、渠道用量及相关成本/提成。消费减退款应与对应余额变化一致；没有重复日志、日志公式正确均不能单独证明钱包只扣一次。
- [ ] **G4 — 预扣与幂等。** 覆盖强制预扣、信任跳过预扣、余额不足、失败退款、客户端中断、重复终态/多轮 Realtime、重复回调及结算重放。核对每一步净额与策略，避免多扣、漏扣、重复退款；测试配置恢复后再核对最终账本。
- [ ] **G5 — 数值安全。** 对图片数量、视频时长、分辨率/质量倍率、batch 和 token 上限验证边界，含透传、metadata、multipart 入口；超限在上游调用前拒绝。核对安全额度换算、饱和诊断及钱包列 64 位约束，预扣和结算都不得溢出为负值。
- [ ] **G6 — 证据来源。** 上游原始帧、本网关返回体和消费日志分别标明，处理时钟偏差、分页 ID 及关联窗口。真实提供方验证仅在本次有明确授权和预算时补充，使用独立令牌并核对消费/退款；不可用模型和未完成任务保留缺口，不以目录存在或提交成功作为能力通过证明。

## H. 后台任务、保留期与恢复（每次发布盘点并验证全部适用任务）

- [ ] **H1 — 有界扫描和并发。** 实时游标与历史补扫独立；验证每轮扫描、SQL 次数、批量、事务、超时和退避有界，迟到数据可补偿、重放幂等、积压可追赶。明确一页记录可能放大的 SQL 数，不能用页大小代替连接/锁预算。
- [ ] **H2 — 清理边界。** 验证保留期 0、截止时刻、时区、快照后迟到记录、子记录分批删除、重复执行和中断恢复；核对所有 writer 节点的去重能力。财务汇总与永久去重依据保留，列表计数/统计缓存同步失效，数据库 TTL 与应用清理不互相违背。
- [ ] **H3 — 故障恢复账本。** 对主/日志库只读、断连、部分提交、提交回包丢失、Redis/磁盘故障和坏恢复文件分别验证。区分明确未提交与结果未知，重放只补尚未完成的步骤；资金和关联日志完成前不删除恢复负载，再次回放不重复扣款、统计或记录。
- [ ] **H4 — 任务完整生命周期。** 验证提交、轮询、成功/失败/超时/取消、重复通知、升级前旧任务及计价快照。成功任务实际下载并检查产物、内容/Range 和跨用户拒绝；任务 HTTP 200、进度完成或文件 URL 存在不等于产物与结算正确。

## I. 容量与共享资源（每次发布混合负载基础回归；相关变更扩大覆盖）

- [ ] **I1 — 节点资源预算。** 按实际节点数核算主库/日志库/Redis 连接、worker、队列、内存、文件句柄和磁盘。审计读取、监控等独立池仍共享数据库 CPU/I/O；以当前配置核算，不能直接沿用历史每节点连接估计。
- [ ] **I2 — 校准后持续压测。** 先确认压测端和鉴权 mock 容量，预热后在代表性环境测 relay 30k RPM 基线及 100k RPM 目标，并发运行管理批量更新、扫描/清理/导出。负载包含 P 组适用的客户端行为、流式/非流式、长短请求、WS/任务、多用户/多令牌/共享出口和重连突发，记录实际占比；不能全部用单用户短 JSON 请求代替。记录实际成功 AI 请求吞吐、持续时间、P95/P99、首字节延迟、错误率、DB CPU/I/O、锁/连接等待及队列/GC，不能把配置速率、chunk、内部重试或双跳请求总数当成入口吞吐；客户端重发计入入口负载，另报去除重发后的业务操作完成率。
- [ ] **I3 — 正确性与降级。** 压测后等待异步工作收敛，再核对账本及资源回落；检查超载拒绝、慢客户端、日志/监控停用及恢复不会阻塞主链。组件压测、短时本地测试和低负载功能通过分别报告，不替代目标环境持续容量验收；未达到的门槛保留未通过。

## J. 部署、启停与收尾（每次发布；故障专项按变更触发）

- [ ] **J1 — 备份和回退准备。** 保存旧程序、配置及主/日志库备份，验证可读取并记录恢复演练结果；明确新旧 schema、设置和恢复文件的兼容性、回退步骤、监控指标及触发条件。备份文件存在不代表已演练恢复，不兼容迁移不能只回滚二进制。
- [ ] **J2 — 带负载启停。** 涉及异步结算、日志或关停路径时，验证停止接流量 → 排空请求 → 批量结算/日志刷盘的顺序；覆盖排空超时及强制退出的损失边界。保留原库/缓存/余额重启，检查旧请求终态和新请求账务，不能靠重置数据或新请求成功掩盖遗留预扣。
- [ ] **J3 — 部署后验证。** 核对运行二进制、前端资源、配置、数据库连接与候选清单一致，检查健康、迁移/启动日志、真实登录/刷新及受影响的管理操作、渠道请求和落库账单。经实际客户访问入口执行无浏览器会话的 API/SDK 冒烟，并对适用网页执行浏览器验收；观察代理/TLS、SSE/WS 和客户端可消费结果，保留 P4 证据。使用本次授权的隔离测试对象及上游，不能因部署冒烟默认取得真实付费模型调用权限。仅健康接口返回 200 不构成业务验收，灰度期间观察 I 组指标与回退条件。
- [ ] **J4 — 环境恢复与清理。** 恢复测试价格、策略开关和用户/渠道覆盖，撤销独立测试令牌/会话并实际验证失效；按明确归属清理本次账号、数据、容器、端口和临时凭据，保留脱敏证据。隔离验收不使用生产账号额度或污染共享开发库，历史外部测试授权不自动延续。
- [ ] **J5 — 发布结论。** 填写下表，核对 T1–T6 分层结果、M 组逐配置/组合覆盖、P 组客户端/接入覆盖和 E6/E7 页面业务集成证据，再逐项处理失败、未执行及不适用项。分别给出页面功能集成、独立 API 集成和混合链路结论；接口与界面各自通过但关联链路未测时，相关集成仍为未执行，纯 API 完整链路也不得仅因无浏览器操作被判未测。测试完成、缺陷复现成功、修复完成及部署完成分别记录；生产 schema 演练、目标环境、必要客户端入口或容量未验证时，不得签署无条件上线通过。
