## Goals and Scope

- 审计工具栏保留一个“导出”入口；导出面板内切换“新建导出 / 导出记录”。改善导出和详情的宽度、滚动及手机布局。

## 规则、配置与边界

新增规则不依赖 IP 外部服务；地理位置、VPN、代理、未知客户端和普通登录失败继续只告警。IP/UA 是关联线索，账户身份来自已认证操作和可信 UserID；这也符合 [OWASP 风险认证](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html#adaptive-or-risk-based-authentication) 对风险信号与认证依据的区分。

| 规则与内部标识 | 默认条件 | 自动处置对象 |
| --- | --- | --- |
| 多账号取钥 `multi_account_key_access` | 同公网 IP 和非空客户端摘要，在 60 秒内成功登录 ≥5 个不同账户；在 5 分钟内其中 ≥3 个账户登录后成功取钥 | 只为有本人成功登录和成功取钥证据的账户分别生成候选；不能封禁该 IP 下的其他账户。 |
| 多 IP 取钥 `multi_source_key_access` | 同一账号 5 分钟内从 ≥5 个不同公网 IP 成功登录，并从其中 ≥3 个 IP 在登录后成功取钥 | 该账号；空/无效 IP 不计数，单个 NAT/IPv6 规范化地址只算一次。 |
| 新来源批量改地址 `new_source_channel_rewrite` | 管理账户已有至少 1 天且最近 30 天活跃的管理来源基线；当前来源首次观察不超过 24 小时；5 分钟成功改动 ≥10 个不同渠道的 base_url | 实际操作者；管理员/员工范围需单独开启。未知变更、只提交未证实更改、模型列表维护不计入。 |
| 会话重放 `session_reuse` | 认证层已经验证的刷新凭据重放；不包含正常并发刷新或无效随机凭据 | 可信 UserID 对应账号，并再次核验当前角色。该规则不是从本次历史 CSV 推导出的样本命中。 |

多账号规则在达到组合阈值时，对**已满足条件的每个账号**建立候选，不能只处理最后一个发起请求的人。候选使用该账号自身的原始事件 ID/角色/时间作为证据，同时保留引发本轮关联的事件 ID。`store.go` 和 `persistFindingSnapshot` 需显式接收这一目标事件，不能把组内最后一人的 ActorID 套到其他账户。

计数以 event_id 去重，有 request_id 时进一步去重；批量只采用返回的正数去重 key ID，最多 100 个。失败、空返回、缺少身份、来源不完整、事实/关联历史被截断，均不能生成自动处置。历史补检和手工导入只告警。

自动处置只接受**规则启用后新生成、距本账号触发事件不超过 120 秒**的完整判定。规则版本、阈值和账户范围保存快照；延迟超限显示“已超过自动处理时限，请人工处理”。不会因打开总开关而处理历史告警。

配置继续放入 `audit_security_setting`：

| 字段 | 默认/限制 | 页面 |
| --- | --- | --- |
| `auto_ban_enabled` | false | 自动封禁 |
| `auto_ban_include_staff` | false；开启扩展到普通管理员/员工，Root 由独立开关控制 | 包含管理员和员工 |
| `auto_ban_exclude_root` | true；界面反向绑定，默认不包含 Root，仍遵守排除 ID | 包含超级管理员（默认关闭） |
| `auto_ban_excluded_user_ids_json` | `[]`；最多 100 个不同正数 ID | 排除账号 |
| `auto_ban_rules_json` | 上述 4 条固定规则定义，默认 selected=true；总开关关闭时只告警 | 每条规则可选择是否自动封禁；阈值默认收起 |

`auto_ban_rules_json` 只接受固定 rule ID、selected 和各规则允许的整数阈值，不支持表达式/脚本/任意动作。登录人数 3–100、取钥人数 2–100 且不超过登录人数；来源数 3–100、取钥来源数 2–100 且不超过来源数；渠道数 5–100；登录集中窗口 10–120 秒；取钥/操作窗口 60–600 秒且不小于集中窗口。关闭总开关时保留规则草稿，开启时至少选择一条规则。

移动阈值改为后端常量。旧字段保留读取兼容，在运行快照中归一化为 1000/200，现有自定义值不再生效；新页面不提交这两个字段，保存路径不允许绕过常量。既有历史告警继续显示当时保存的阈值，不能用新默认值改写历史证据。

排除账号、角色、总开关与规则开关在执行前重新校验。关闭/暂停监控取消未开始的动作，但不反向解封已经禁用的账户。用户管理手工解封后，同一处置事件不能再次封禁；新攻击事件仍可按规则处理。

## Data Flow 与处置生命周期

1. 已有审计落库 → 增量扫描。补入有限的 User-Agent 投影，后台计算有域隔离的 HMAC 摘要；不保存可用会话凭据。取钥 returned_ids 进入 Facts 白名单。
2. `commitSecurityBatch` 纳入成功普通 API Key 查看事件；新增组合规则读取有界的账户/来源窗口。保留现有简单规则，普通取钥不会自动变成“敏感管理操作”。
3. 判定、每账号告警、快照、待执行 SecurityAction、扫描回执在同一安全表事务提交。去重键绑定告警事件、目标账号和 `disable_account`，保证重叠页、重复请求、多规则重合不会重复处置同一事件。
4. 复用现有 worker，在 IP 外查/通知前处理已排队动作；本轮扫描产生的新动作在下一轮执行。每轮最多 5 项、总预算 5 秒，单项 1 秒，不创建每请求 goroutine，不占用 relay worker。
5. 模型入口 `DisableUserForSecurity` 使用监控独立主库池，在短事务内重新核验当前目标、角色、员工状态、排除条件和动作状态，只更新 `users.status/auth_version` 并写入 committed 回执。用主键/版本条件更新，绝不回写旧余额、权限、组别、设置或配额。
6. 事务提交后按现有版本协议发布认证缓存，保留缓存额度；后台 helper 传递 context 和独立 DB，不在持有 users 行锁时调用 Redis。新请求由既有账户状态校验拒绝；旧会话由 auth_version 校验失效，不逐条同步扫描全部会话或密钥。不会中断已在输出的流。
7. 状态为 pending → committed → succeeded；未提交失败为 failed，受保护/过期/已处理为 skipped，提交后缓存尚未同步为 sync_pending。DB 提交结果不明先按执行键读回，无法确定显示 unknown，不能盲目再封禁。
8. 缓存同步最多重试 3 次、每次仍受独立截止时间限制；仅重试已提交版本的收尾，不重复更新账号。超出次数保留 partial 并告警。复核发现账号已被人工解封或权限版本已前进时，以最新状态发布并记 superseded，不恢复旧禁用快照。
9. 处置结果写入现有动作历史并刷新 alert.version/updated_at，使页面能够发现结果变化。通知失败不回滚封禁，封禁成功不自动将调查结案。清理不能删去尚在执行/同步中的回执。

缓存发布前存在短暂传播窗口；Redis 故障时不承诺封禁即时全局生效。页面只有完成数据库和缓存收尾才显示“已封禁”；同步中显示“封禁状态正在同步”，重试失败显示“暂无法确认封禁已完全生效，请人工检查”。这一限制必须通过真实 Redis 故障/恢复验收，不能只证明 users.status 改了就宣称全链路阻止成功。

| 新 POST `/api/audit/security/alerts/:id/responses` | `{version,action:"disable_account",request_id}`；既有组再要求 AuditSecurityManage、AdminMenuUsersView、浏览器会话及现有 `admin.user.manage` 二次验证。操作者必须高于目标，Root 不能被封。目标从可信告警读取，客户端不能指定另一目标。返回 `{success,message,data:{action_id,outcome,target_user_id}}`。 |
| 既有用户管理接口 | 解封沿用 `action:"enable"` 和现有二次验证；不提供自动解封计时器。 |
| 员工客户风险接口 | 只显示该客户自身的封禁结果和简短原因，保留实时归属授权。员工没有自动策略修改和封禁接口权限，也不能看到跨账号证据。 |
| 既有审计导出 jobs 接口 | 创建/查询/下载/取消/删除合同不变。单一入口仍允许在筛选无效时查看已有导出记录，只有“创建导出”受时间范围与风险导出权限限制。 |

业务错误使用 common ApiErrorI18n 和既有 `{success:false,message}`；401/403 保留中间件语义，DB 故障按现有安全错误处理。不得直接返回 Go error 或账号是否存在的额外信息。新处置接口不加入 PAT 可调用路由白名单。

## Data Model、Index Design 与迁移

- `audit_security_actions` 增加 nullable `execution_key` 唯一索引，以及 `outcome`、`target_user_id`、`reason_code`、`next_attempt_at`、`attempts`、有界 `result` TEXT。result 只保存配置生效时间、规则快照、提交的 auth_version 和人工操作者认证版本，API 不返回 result。待执行查询索引 `(outcome,next_attempt_at,id)`，结果展示索引 `(alert_id,action,id)`；旧人工记录 execution_key 为 NULL，不回填历史自动任务。
- `audit_security_baselines` 增加来源用途字段，旧空值保持“登录”，新 `management` 用途与原来源摘要做域隔离。按 account/source 精确取值复用唯一索引；成熟度查询使用 `(account_id,kind,first_seen)` 并限制最近 30 天，历史基线清理仍走 last_seen。登录规则不会把新的管理来源当登录基线。
- SecurityEvent 的客户端摘要和去重返回 ID 放现有 Facts，不增加审计大表列。来源关联使用现有 `(ip,at)`，账户关联使用 `(actor_id,at)`；每次限制 1,001 条检测截断、时间窗口最多 600 秒，不做全历史 GROUP BY。
- 组合规则按 actor_id 分别合并告警并保存独立完整证据；更新客户可见规则版本和白名单投影，不能让一个共享来源告警携带其他用户证据给员工。
- 不向消费 logs、channels、tokens 增加列或索引。users 复用现有 status/auth_version 和主键；只执行极少量有界点更新。
- 新字段使用跨库 TEXT/varchar/nullable 唯一键，避免 MySQL TEXT 默认值、JSONB、部分索引及 MySQL 8 专属 SQL。

实施验收参照了 [生产环境](../production-environment.md) 和 [发布清单](../release-checklist.md)。生产是 MySQL 主库 + PostgreSQL 日志库，确切版本尚未记录。本次隔离实例测试及查询计划见文末；没有连接生产库，不能代替发布前针对生产 schema 的演练。

## Main Chain Impact

**同步：** AI 请求不新增检测、DB/Redis 调用、外部 IP 查询、队列投递或锁。只继续执行原有 TokenAuth 的账户启用检查；被封账号的后续请求按原合同拒绝。

**后台：** 审计读取、关联、自动决策、账户窄更新、认证缓存发布和通知全部在监控后台或明确的人工管理调用执行。自动处置的总开关可立即停止新动作，故障不向其他账户 relay 返回错误。

### Shared Resource Audit

| 资源 | relay 是否使用 | 隔离与影响 |
| --- | --- | --- |
| audit_security_* 表、规则窗口/基线/执行键 | 否 | 独立连接池、有界窗口和批次；新状态不放入 relay 缓存命名空间。 |
| audit_logs 与日志数据库 IO | 审计非 AI 热路径，但日志数据库可能同时写消费日志 | 复用 1 连接读池、500 条 keyset 页；不扫描消费大表，不加全表聚合或新回扫。 |
| users 目标行 | 是，额度及认证也使用 | 账户状态必须写权威用户行；仅主键短更新，不持锁做网络调用，不新增 relay 侧协调锁；超时退出。不能因用了独立池就声称无同机 IO/行锁影响。 |
| `user:<id>`、`auth:user:version:{user:<id>}`、相关版本字段 | 是 | 仅通过既有认证版本发布协议修改目标账号；不 DEL 整个用户 hash、不改 Quota、不扫描其他用户 key。监控计数不使用这些 key。 |

| DB/Redis 连接和 goroutine | 共享基础设施 | DB 继续监控主池最多 2、来源读/写各 1；Redis 使用有 deadline 的少量既有客户端调用，限制每轮动作数，不修改公共池配置。没有每请求 worker、无全局大 map。 |

### Concurrency Analysis

在现有 30k RPM 或目标 100k RPM 下，每个 AI 请求新增 **0 次 DB、0 次 Redis、0 次外部调用、0 个 goroutine**。成本取决于已记录审计事件和实际命中账号，不随每个模型 token/流片段增加。

每个新候选最多两类索引窗口读取（账户/来源，各最多 1001 条）；达到上限只告警，不放宽证据门槛。处置每轮最多 5 项，每项包括有界身份复核、一次短事务及认证版本发布；没有密钥数量相关扫描。使用独立池只限制连接竞争，不能免除共享 users 行锁、Redis 和同机 IO 的压力测试。验收需要对照开关关闭/开启下的正常账号延迟、错误率、缓存重建和正在输出的流。

## 界面与文案

### 标签切换的尺寸约束

- 同一容器的宽高只随视口和断点改变，不随选中标签、数据量、请求状态或按钮数量改变。不使用根据 `activeTab` 切换的宽度类、内容自然高度或宽高动画。
- 导出弹窗两个标签统一使用 `sm:max-w-3xl`。正文预留 `min(60dvh, 40rem)` 高度，整体限制在 `94dvh` 内；标题、标签栏和底栏保持位置。记录页也保留同高底栏并提供既有“关闭”按钮。
- 监控设置继续使用 `sm:max-w-2xl` 右侧抽屉和视口高度。四个标签只替换中间正文，头部、标签栏和底部操作区固定；校验错误在正文中呈现，不把外框撑高。
- 告警详情保留当前固定正文高度。审计主页面保留 `fixedContent` 框架；全部、仅自己、安全监控切换时不改变页面主容器尺寸。
- 正文使用 `min-h-0`、弹性剩余空间和单一纵向滚动区域；滚动区域预留稳定的滚动条空间，避免长短内容切换时左右位移。长表格横向滚动限制在表格内部。
- 标签按钮的宽高不由选中态决定，选中态只改变背景、边框或颜色。小屏换行/横向滚动采用固定结构，同一视口下不因切换标签改变行数。
- 首次加载、重新加载、失败、空态和长内容占用同一正文区域。展开更多选项在正文内滚动；切页保留表单草稿，隐藏页不得残留可聚焦控件。
- 验收固定视口下切换每一组标签，比较外框 `getBoundingClientRect()` 的宽高及标签栏/底栏位置，允许最多 1 CSS 像素舍入差。覆盖中文、长译文、手机、桌面、加载/错误/空态；滚动条出现与消失不得改变内容可用宽度。

## Error Handling 与恢复

- 无效配置在保存前及后端双重检查；保留输入并指向具体项。接口 200 + success:false 不能进入成功回调。
- 后台错误以 common.SysError 记录不含凭据的原因；请求错误用 logger 带 context。原始 DB/Redis 错误不透传页面。
- 规则证据不足、账户受保护、开关关闭、判定过期分别记录 skipped 原因，不能伪装为封禁成功。
- 自动模式关闭或回退版本前先停止新动作，等待已提交动作收尾；保留执行回执和新列。回退不自动解封。
- 账户封禁可能被攻击者反向利用，因此不根据匿名失败、单独 IP/UA 或共享出口封号；参考 [OWASP 账户锁定](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html#account-lockout)。处置必须留痕，原始会话凭据不入日志，参考 [OWASP 会话生命周期日志](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html#logging-sessions-life-cycle-creation-usage-and-destruction-of-session-ids)。实施对照当前 [ASVS 5.0.0](https://asvs.owasp.org/)。

### 复核修复方案（用户已要求全部修复）

- 自动动作沿用现有唯一执行键和告警事务。只有尚未执行、原因是过期/证据不足/开关关闭/范围排除的 skipped 回执，才允许被新的完整、有效触发事件接替；旧回执改用自身 ID 的历史键保留，新回执占用原执行键。相同或更早事件、已禁用、受保护、已提交、结果不明及同步中的动作都不能接替。原告警更新持有的行锁与执行键唯一约束串行化该交接，不新增表、列或索引。
- 人工接口对确认未创建动作的业务拒绝增加稳定错误码 `AUDIT_SECURITY_RESPONSE_REJECTED`，沿用已有翻译消息；数据库/网络等不明结果不标记为拒绝。前端保留服务端拒绝原因并恢复再次确认/验证的入口；未知结果仍不自动重试。
- 自动封禁选择 session_reuse 时必须启用安全事件采集：前后端均校验，规则卡直接展示依赖提示并提供已有名称的采集开关；关闭采集使待执行会话重放动作停止，采集配置变化推进策略生效时间。其他三条规则不强制采集认证失败事件。
- 移动规则说明改用“当时的阈值”，兼容固定默认值及历史自定义阈值。用户已确认 `audit-auto-ban-review-copy-translations.tsv` 的两条文案与全部译文。
- 先补测试：跳过后新事件、重复/更早事件、已封禁后人工解封、未确认/已提交状态不重放、采集依赖的正反组合、明确拒绝与传输不明的前端交互、历史阈值说明。数据库用独立 MySQL/PostgreSQL，缓存收尾沿用真实 Redis 夹具。
