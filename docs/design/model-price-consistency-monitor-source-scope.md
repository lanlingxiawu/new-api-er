# 模型价格巡检：来源适用范围补充设计

本补充设计记录价格矩阵的来源适用语义，主设计见 `model-price-consistency-monitor.md`。

## 目标与规则

- 官方价格为强制对比来源，适用于模型广场中的全部模型。后台不再提供关闭官方对比的操作；旧的 `include_official` 配置字段仅为兼容历史配置保留。
- 只加载状态正常的渠道。每个渠道只对其 `Channel.Models` 中已启用的模型参与价格对比，未启用模型不得误报为“渠道缺价”。
- 官方成功返回但缺少某个广场模型时，该模型计为价格不一致；官方抓取失败时保留官方列并显示“价格来源检查失败”，不得以平台值或旧值代替。

## 数据流与接口

巡检加载渠道时同时建立“来源 → 启用模型集合”。矩阵生成时，平台和官方对所有广场模型适用，渠道先检查模型是否属于自身启用集合，再读取其价格并比较。JSON 快照继续只保留最新一次，不新增数据表。

`GET /api/price_monitor/results` 与 `POST /api/price_monitor/public_query` 在模型筛选和分页之后，只返回当前页实际参与至少一个模型比较的渠道表头；平台和官方表头始终保留。外部兼容接口 `/api/price_monitor/inconsistencies` 的字段级响应不变。

## 排版布局

- 模型一行、来源一列，顺序为模型、平台基准、官方价格、当前页相关渠道。
- 表头明确标识“平台基准”和“必须对比”；渠道列副标题仅显示渠道名称。
- Token 价格统一单位仅在表格上方说明一次；单元格只展示输入、输出、缓存、图片、音频等具体美元价格。
- 仅高亮真正不同的价格行。渠道未启用某模型时显示“不参与对比”，但通过当前页列裁剪避免出现大量空列。
- 表格只允许横向滚动，不设置独立纵向滚动；模型列固定，适配来源较多的情况。

## 错误处理与主链路影响

来源抓取失败属于巡检的部分失败，写入最新快照并在矩阵中显示来源状态；全部来源失败时保留旧快照。此功能仍只运行在后台定时任务和管理/分享查询路径，不进入 AI 中继主链路；共享资源、并发上限与主设计保持不变。

## 测试

- 渠道只比较自身启用模型，未启用模型不产生缺价差异。
- 官方缺少广场模型时产生差异，官方抓取失败时保留表头与失败状态。
- 分页后删除当前页未参与任何模型的渠道列，平台和官方列始终存在。
- 后台类型检查、前端构建、Go 全量测试及测试服务器接口回归全部通过后部署。
