# 模型价格一致性自动巡检（Model Price Consistency Monitor）

状态：已实现并通过测试  
作者：AI 辅助设计
关联代码：`controller/ratio_sync.go`、`model/pricing.go`、`service/subscription_reset_task.go`

## 1. 目标与范围（Goals and Scope）

### 目标
1. **定时**自动比对三类价格，发现不一致的模型：
   - **平台模型价格**：本网关自身配置的价格（`getLocalPricingSyncData()` / `ratio_setting` 暴露的数据）。
   - **渠道模型价格**：各**启用**渠道上游 `/api/pricing`（或 `/api/ratio_config`、OpenRouter、models.dev）返回的价格。
   - **官方模型价格**：官方倍率预设（`basellm.github.io`）与 models.dev 预设。
2. 检测范围**只限模型广场展示的模型**（`model.GetPricing()` 返回集合），即"至少有一个启用渠道启用了该模型"的模型；渠道也**只检测启用渠道**（status 正常）。
3. 巡检**周期**由管理后台配置（开关 + 间隔）。
4. 持久化**最新一次巡检的不一致结果快照**，提供一个**对外查询接口**，供外部系统拉取"当前不一致的模型数据"。

### 非目标
- 不自动修改/同步价格（现有手动同步 UI 已覆盖写入；本功能只做**只读巡检 + 上报**）。
- 不改动 AI 中继主链路（见 §9）。
- 不做历史趋势分析，只保留最新一次快照（可后续扩展）。

## 2. 数据流（Data Flow）

```
定时器(master节点, 可配间隔)
  └─> RunPriceConsistencyCheck()
        1. 取模型白名单 = distinct(model.GetPricing().ModelName)          [读定价缓存；过期时可能刷新DB]
        2. 取启用渠道列表 = model.GetAllChannels(enabled only, 有BaseURL)
        3. 取官方/ models.dev 预设 upstream 定义
        4. 复用 ratio_sync 抓取逻辑并发拉取各上游 pricing (超时/重试/并发上限)
        5. localData = getLocalPricingSyncData()  (平台价格)
        6. differences = buildDifferences(localData, 各来源)             [复用现有函数]
        7. 按模型白名单过滤 differences（只保留广场模型）
        8. 原子覆盖写 price_monitor/snapshot.json，并发布进程内不可变快照
  └─> 对外查询接口读取最新快照返回
```

## 3. API 契约（API Contracts）

### 3.1 管理接口（`AdminAuth`，`router/api-router.go` 现有 admin 组）
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/price_monitor/status` | 返回配置 + 最近一次运行元数据（时间、成功/失败来源数、不一致模型数、动态密码与到期时间）；不返回明细数组 |
| POST | `/api/price_monitor/run` | 手动触发一次巡检（复用同一逻辑，异步执行，立即返回） |
| GET | `/api/price_monitor/results` | 按模型分页返回最新价格矩阵（供后台 UI 展示） |

配置读写复用现有**系统设置**保存通道（Rule 12，见 §5），不新增自定义保存端点。

### 3.2 对外查询接口（关键交付物）
```
GET /api/price_monitor/inconsistencies
```
- **鉴权**：`AdminAuth`（决策 1 按推荐）。
- **Query 参数**：`model`（可选，精确/前缀过滤）、`source`（`channel|official`）、`field`（可选）、`page`、`page_size`（默认 20，上限 200）。
- **返回精简**：只回必要信息，去掉冗余（不返回 confidence 明细结构、不返回 run 内部字段）。响应（`{"success":true,"data":{...}}`）：
```json
{
  "success": true,
  "data": {
    "checked_at": 1733650000,
    "password_expire_at": 1733671600,  // 仅用于页面提示本次报告有效期
    "status": "success",              // success/partial，页面据此提示数据完整性
    "total": 128,                       // 不一致条目总数(用于分页)
    "model_total": 42,                  // 当前筛选条件下涉及的模型数
    "page": 1,
    "page_size": 20,
    "items": [
      {
        "model": "gpt-4o",
        "field": "model_ratio",
        "platform": 2.5,                // 平台价格
        "sources": [                    // 仅与平台不一致的来源
          {"name": "渠道A", "value": 2.0},
          {"name": "官方倍率预设", "value": 2.6}
        ]
      }
    ]
  }
}
```
> 精简原则：`sources` 只列出与平台**不一致**的来源；数值一致的来源不返回；`confidence=false`（不可信）的来源直接剔除，不返回给外部。

### 3.3 动态密码 HTML 页（对外可分享视图）

面向"把不一致清单分享给外部人员查看"的场景，提供一个**独立自包含 HTML 页**，用**动态密码**保护，无需登录后台。

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/price_monitor/view` | 无（公开路由） | 返回自包含 HTML（内联 JS/CSS），页面首先要求输入访问密码 |
| POST | `/api/price_monitor/public_query` | 动态密码校验 | 请求体含 `password` + 分页/过滤参数，密码正确才返回 §3.2 精简数据 |

- HTML 由后端渲染的静态模板返回（不接入 React dashboard、不走 dashboard 的 Bearer 鉴权），确保外部人员开链接即可用。
- 页面交互：输入密码 → 校验通过 → 表格化展示不一致清单，支持搜索/分页（见 §6.2 大数据量展示）。
- 密码错误返回统一提示"访问密码错误或已过期"，不区分两者（防探测）。

## 3.4 动态密码机制

- **生成**：每次巡检成功运行结束时，生成一个新的随机密码（如 8 位数字，或 6 位字母数字），覆盖旧密码。
- **有效期 = 定时任务周期**：密码 TTL 设为 `IntervalMinutes`（下一次巡检会再次刷新）。即"密码有效期为定时任务周期"。存储 `password` + `expire_at = checked_at + IntervalMinutes*60`。
- **手动触发**同样刷新密码与有效期。
- **存储位置**：作为 `snapshot.json` 的 `access_password` / `password_expire_at` 字段（§4），随快照一并落文件 + 内存副本。
- **管理员如何拿到当前密码**：通过**已鉴权的查询接口** `GET /api/price_monitor/status`（AdminAuth）返回当前 `access_password` 与到期时间；管理员据此把"链接 + 当前密码"发给外部。不单独设发放/通知流程。
- **校验**：`public_query` 比对 `password` 且 `now < password_expire_at`；过期或不符一律拒绝。
- **安全**：公开路由 `public_query` 加基础限流（复用现有 IP 限流中间件即可），防暴力猜测；密码为一次性周期口令，泄露影响面限于当周期只读数据。

## 4. 存储（JSON 文件，不新增数据表）

**不新增任何数据库表**。最新一次巡检快照（含元数据、动态密码、不一致明细）持久化到**单个 JSON 文件**。

- **路径**：数据目录下 `price_monitor/snapshot.json`，数据目录优先取 `common.GetDiskCachePath()`；为空时使用进程工作目录下 `data/price_monitor/snapshot.json`。不使用 `os.TempDir()`，避免系统临时目录清理导致快照无提示丢失。
- **只保留最新一次**（决策 3）：每次运行**整体覆盖写**该文件。
- **写入安全**：先写临时文件 `snapshot.json.tmp` 再 `os.Rename` 原子替换，避免读到半截文件；写操作加进程内 `sync.RWMutex`。
- **内存缓存**：进程启动时加载一次到内存；每次巡检写文件的同时更新不可变内存副本。对外/后台查询**只读内存副本**，不每次读磁盘。
- **多节点约束**：JSON 快照是节点本地资源。只有 master 执行巡检；因此查询/分享路由必须命中 master，或所有实例必须挂载同一共享数据目录。未满足该条件的 slave 不保证返回最新快照。本限制会在状态接口中以 `storage_scope=local` 明示。
- **文件结构**：
```json
{
  "checked_at": 1733650000,
  "status": "success",                 // success/partial/failed
  "source_total": 5, "source_ok": 4, "source_err": 1,
  "model_count": 42, "item_count": 128,
  "access_password": "8391xz",         // 当前动态密码
  "password_expire_at": 1733671600,    // = checked_at + IntervalMinutes*60
  "message": "",
  "items": [
    {
      "model": "gpt-4o",
      "field": "model_ratio",
      "platform": 2.5,
      "sources": [ {"name":"渠道A","value":2.0}, {"name":"官方倍率预设","value":2.6} ]
    }
  ]
}
```

> **不与中继共享资源**：独立文件 + 独立内存结构，中继链路不读写（Rule 0 审计通过）。查询过滤/分页在内存 `items` 切片上做（量级百~千，成本可忽略）。

## 6. 关键业务逻辑与边界（Key Logic & Edge Cases）

- **模型白名单**：`model.GetPricing()`（反映启用渠道+启用模型；缓存过期时会刷新并读取能力、模型、供应商数据）。空则本次失败并保留旧快照。
- **启用渠道**：`model.GetAllChannels(0,0,true,false)` 过滤 `Status==ChannelStatusEnabled && BaseURL!=""`。
- **抓取逻辑复用**：已把 `FetchUpstreamRatios` 中的并发抓取 + 多格式解析（type1/type2/OpenRouter/models.dev）抽出为 `fetchUpstreamPricingData(ctx, upstreams, timeout)`；手动同步控制器与后台巡检任务共用，避免复制。为避免 controller/service 包循环依赖，调度入口与共享抓取函数同处 `controller` 包，设置、存储和纯查询逻辑仍保持独立文件。
- **差异计算复用** `buildDifferences`，随后按白名单过滤 `differences[model]`。
- **可信度**：沿用现有 `confidence`（model_ratio=37.5 且 completion_ratio=1 判为不可信）字段，透传到结果。
- 边界：
  - 全部上游失败或模型白名单为空 → **保留上一次成功/部分成功的数据和口令**，仅在进程内记录失败；不把失败状态覆盖到对外快照，避免快照元数据与其明细来自不同运行。
  - 部分失败 → `partial`，正常写入成功来源结果。
  - 单次运行加互斥（`atomic.Bool` CompareAndSwap），防止手动触发与定时重叠。
  - 仅 master 节点运行（`common.IsMasterNode`），与现有定时任务一致。

### 6.2 中文价格矩阵分享页

本轮按“只看中文、直接看实际输入输出价格、所有来源放在一个表里横向对比”重构公开分享页。现有倍率明细接口继续供后台诊断，分享页改用面向阅读的价格矩阵，不再展示 `model_ratio`、`completion_ratio` 等原始倍率。

#### 6.2.1 价格换算口径

- 统一显示美元价格，文本模型单位为 **`$/百万 tokens`**。
- 按现有模型价格编辑器相同公式换算，不能由页面自行猜测：
  - `输入价格 = model_ratio × 2`；
  - `输出价格 = model_ratio × 2 × completion_ratio`；
  - 每个平台/渠道/官方来源都使用**该来源自己的** `model_ratio` 与 `completion_ratio` 组合计算，禁止把平台输入倍率与渠道输出倍率交叉计算。
- `model_price` 固定价格模型显示为 **`$/次`**，输入/输出位置合并为“固定价格”；不伪造 token 单价。
- `billing_mode=tiered_expr` 不强行折算成单一价格：对系统可视化编辑器支持的标准阶梯表达式，解析并逐档显示具体输入/输出价格与输入长度条件；包含请求头、请求体、时间等动态规则或无法安全解析的自定义表达式时，明确显示“动态规则计费，无法给出唯一价格”，不猜测价格。
- 缺少基础倍率或来源不可信时显示“无可靠数据”，不以平台值代替来源值。
- 数字最多保留 6 位小数并去除末尾 0；极小价格仍必须可辨认，不能显示成 `$0`。

#### 6.2.2 单表矩阵布局

- 页面只保留中文，移除英文词典、语言切换按钮和所有中英双语文案。
- 一个模型占一行；第一列固定为“模型”，后续每个数据来源各占一列。
- 表头顺序固定：**模型 → 平台配置 → 官方价格 → 启用渠道（按名称排序）**。来源名称直接作为表头。
- 每个价格单元格按来源实际支持的字段显示：输入、输出、缓存读取、缓存写入、图片输入、音频输入、音频输出；固定价格与阶梯表达式沿用各自布局。
- 页面顶部已说明统一价格口径，单元格不再重复显示“每百万 tokens”，以减少视觉噪声。
- 平台配置列为对比基准；来源的输入或输出与平台不一致时，只高亮对应价格行，并在右侧显示相对差值百分比。
- 表头固定在顶部，模型列和平台配置列固定在左侧；来源较多时只允许表格容器横向滚动，页面本身不横向滚动。
- 页面只使用浏览器纵向滚动，表格容器不再设置固定高度或独立纵向滚动条，避免桌面端出现内外双滚动条；表格容器仍保留横向滚动。
- 公开表头使用可读名称：官方预设显示为“官方价格”，渠道隐藏内部 ID；同名渠道用快照内序号区分，内部唯一 key 仍用于 API 数据映射。
- 渠道表头第一行显示渠道名称，第二行显示清洗后的 API 地址；API 地址不得抢占主标题位置。
- 缺失价格区分为“该来源未提供此模型价格”和“来源返回占位价格，未参与对比”，不再统一显示含义模糊的“无可靠数据”。
- 阶梯价格在单元格内使用紧凑行展示“条件 / 输入 / 输出”，汇总信息改为紧凑状态栏，减少首屏无效高度。
- 默认仅返回“至少一个来源与平台不一致”的模型。分页按模型进行，每页 20/50/100 个模型，不再按差异字段分页。
- 筛选只保留：模型名称、来源类型（全部/官方/渠道）、每页数量、查询、重置。移除“字段”筛选。

#### 6.2.4 查询响应调整

`POST /api/price_monitor/public_query` 返回按模型聚合的必要数据：

```json
{
  "checked_at": 1733650000,
  "password_expire_at": 1733671600,
  "status": "partial",
  "total": 42,
  "page": 1,
  "page_size": 20,
  "source_headers": [
    {"key": "platform", "name": "平台配置", "type": "platform"},
    {"key": "official", "name": "官方价格", "type": "official"},
    {"key": "channel:12", "name": "渠道 A", "type": "channel"}
  ],
  "items": [
    {
      "model": "gpt-4o",
      "prices": {
        "platform": {"mode": "per_token", "input": 2.5, "output": 10},
        "official": {"mode": "per_token", "input": 2.5, "output": 10},
        "channel:12": {"mode": "per_token", "input": 2, "output": 8}
      }
    }
  ]
}
```

- `source_headers` 决定稳定列顺序并包含清洗后的渠道 `api_url`；`prices` 仅含展示所需的价格，不返回倍率、置信度或抓取错误。
- 来源 key 必须稳定且不泄露敏感信息；渠道使用内部 ID 或快照内稳定序号，显示名称单独放在表头。
- 后端在生成快照时就完成价格归一化和每个来源的输入/输出配对，页面只负责格式化，避免因分页结果缺少某个倍率而算错。
- 管理员 `/results` 与公开分享页共用价格矩阵响应，保证两处显示口径一致；`/inconsistencies` 按 §13 返回巡检统计和分享凭据。

#### 6.2.5 大数据、移动端与状态

- 服务端按模型筛选和分页；表头来源集合随筛选条件返回，但同一查询的翻页过程保持稳定。
- 桌面端使用单一横向价格矩阵。移动端仍是同一张表，不改为卡片；模型列固定，单元格宽度约 190px，通过表格内部横向滚动逐列对比。
- 空数据、网络失败、密码过期、部分来源失败沿用现有状态逻辑，全部改为纯中文。
- 密码仍仅保存在页面内存，不进入 URL、日志或浏览器持久化存储。
- 真实浏览器验收至少覆盖：3/10/30 个来源、20/100 个模型、极小价格、固定价格、表达式计费、缺失数据、移动端横向滚动。

#### 6.2.6 实现影响

- 需要新增“来源价格矩阵”快照数据，不能仅依赖当前只保存差异字段的 `items`，否则无法可靠组合某个来源自己的输入与输出价格。
- JSON 仍只保存最新快照，不新增数据表；预计体积为“模型数 × 来源数”的百 KB 至低 MB 级别，可接受。

#### 6.2.7 实现记录

- 巡检同时保留后台使用的字段级差异 `items`，并生成分享页使用的 `source_headers` 与 `matrix_items`；后台接口保持兼容，公开查询改为按模型分页返回矩阵。
- 每个来源分别使用自身的模型倍率和输出倍率换算输入、输出美元价格，避免交叉使用平台倍率；固定价格与表达式计费分别显示为“每次”和“表达式计费”。
- 公开页面为自包含纯中文 HTML，来源动态生成表头，平台列和模型列在桌面端固定，差异单元格高亮，缺失或不可信来源显示“无可靠数据”。
- 旧快照没有矩阵字段时，master 节点启动后会立即发起一次巡检，成功后原子替换 JSON 并刷新周期密码；巡检失败仍保留旧快照。
- 矩阵价格单元格保存输入、输出、固定价格各自的差异标记，以及可安全解析的表达式阶梯。页面仅高亮真正不同的价格行；显示值按价格大小自适应保留最多 6 位小数，悬停标题保留原始精度。
- 价格矩阵覆盖全部同步计价字段：`model_ratio`、`completion_ratio`、`cache_ratio`、`create_cache_ratio`、`image_ratio`、`audio_ratio`、`audio_completion_ratio`、`model_price`、`billing_mode`、`billing_expr`。倍率字段均换算为同一来源自身基准下的实际美元价格后展示和比较。
- 后台“价格巡检”结果表与分享页使用同一矩阵：模型一行、平台/官方/渠道为列、只高亮实际不同的价格项，不再显示原始字段名、倍率或表达式源码；后台文案继续使用全量前端 i18n。
- 巡检抓取、模型广场白名单、启用渠道过滤、动态密码、定时任务和主链路隔离策略不变。
- 实现前先补价格换算、来源独立配对、固定价格、表达式计费、缺失倍率、来源顺序和按模型分页测试。

新增单选参数 `comparison`。同一时间只启用一种快捷条件，避免多条件叠加后含义不清；它与模型、来源列筛选共同生效：

| 值 | 页面文案 | 判定范围 |
|---|---|---|
| `all` | 全部差异 | 当前所有不一致模型，默认值 |
| `channel_official` | 渠道与官方不一致 | 任一选中且适用于该模型的渠道，与官方价格结构不一致 |
| `channel_platform` | 渠道与平台不一致 | 任一选中且适用于该模型的渠道，与平台配置不一致 |
| `platform_official` | 平台与官方不一致 | 官方价格与平台配置不一致 |
| `input` | 输入价格不同 | 任一参与对比来源的输入价格与平台不同 |
| `output` | 输出价格不同 | 任一参与对比来源的输出价格与平台不同 |
| `cache` | 缓存价格不同 | 缓存读取、写入或一小时写入价格存在差异 |
| `billing` | 计费方式不同 | 固定价格、按 Token、阶梯或动态规则的模式/价格不同 |
| `official_missing` | 官方未收录 | 官方价格源未收录该模型 |
| `channel_missing` | 渠道未提供 | 已启用该模型的选中渠道未返回价格 |
| `source_failed` | 来源检查失败 | 任一选中来源本轮检查失败 |

- `channel_official` 通过统一价格单元比较函数判断输入、输出、缓存、图片、音频、固定价格及可解析阶梯价格；浮点值沿用现有容差。渠道未启用该模型时不参与判断。
- 占位价格和检查失败不混入“价格不一致”，分别由专用快捷条件筛选；一方明确缺少价格、另一方存在有效价格时视为不一致。
- 选择了具体渠道列后，所有“渠道与……”筛选只在所选渠道范围内判断；平台与官方筛选不受渠道列选择影响。
- 页面以紧凑快捷筛选条展示常用条件：全部差异、渠道与官方、渠道与平台、平台与官方；其余条件放入“更多筛选”菜单，避免首屏拥挤。

## 15. 按筛选条件裁剪无关列（已实现并部署验证）

筛选后，后端同时计算“符合条件的模型”和“实际参与该条件的来源列”。页面只渲染必要列，不再保留与当前条件无关的官方、平台或渠道列。模型列始终显示；列裁剪规则如下：

| 筛选条件 | 显示列 |
|---|---|
| 全部差异 | 模型、平台、官方、用户选中的渠道 |
| 渠道与官方不一致 | 模型、官方、至少有一条结果与官方不一致的渠道 |
| 渠道与平台不一致 | 模型、平台、至少有一条结果与平台不一致的渠道 |
| 平台与官方不一致 | 模型、平台、官方 |
| 输入价格不同 | 模型、平台、存在输入差异的官方/渠道来源 |
| 输出价格不同 | 模型、平台、存在输出差异的官方/渠道来源 |
| 缓存价格不同 | 模型、平台、存在缓存差异的官方/渠道来源 |
| 计费方式不同 | 模型、平台、存在计费方式或固定价格差异的官方/渠道来源 |
| 官方未收录 | 模型、官方 |
| 渠道未提供 | 模型、实际缺少价格的渠道 |
| 来源检查失败 | 模型、本轮检查失败的官方/渠道来源 |

- 渠道列范围仍受“显示来源”多选器约束；未选择的渠道不会因快捷筛选重新出现。
- 来源列相关性基于**过滤后的全部模型**计算，而不是只看当前分页，避免翻页时表头无规律变化。
- 每行只显示该行在当前条件下真正命中的来源：某渠道虽然因其他模型命中而出现在表头中，但当前行未命中时显示短横线，不再展示与当前筛选无关的价格。
- 固定列位置改为按实际可见基准列动态计算：仅显示官方时，官方紧贴模型列；同时显示平台和官方时，平台、官方依次固定。渠道列始终参与横向滚动。
- `source_headers` 改为裁剪后的表头，`items[].prices` 改为当前条件命中的显示数据；`available_source_headers`、`available_models` 保持完整，供快捷选择和切换筛选使用。
- 后端测试覆盖每种筛选的精确表头、逐行来源裁剪、指定渠道交集及分页前全量列相关性；后台与分享页契约测试覆盖动态固定偏移。

## 16. 页面稳定性与筛选布局优化（已实现并部署验证）

### 16.1 问题与目标

当前后台和分享页使用浏览器原生 `datalist` 提供模型快捷选择。不同浏览器会用系统级弹层渲染候选项，弹层宽度、位置和最大高度不可控；筛选条件变化时，查询结果还会短暂清空表格，再用新表格替换，造成明显的纵向跳动和横向宽度变化。

本轮只调整展示和交互，不改变巡检、快照、鉴权及查询接口契约：

- 筛选请求期间保留上一份表格，结果返回后一次替换，避免“空表 → 新表”抖动。
- 表格区域预留稳定的最小高度；加载状态在原区域内显示，不改变页面主体高度。
- 后台模型筛选改用项目已有的可搜索 `Combobox`，候选层锚定输入框、限制高度并在内部滚动。
- 分享页实现同样的锚定候选层，不再使用原生 `datalist`；候选层不参与文档流，不推挤筛选栏或表格。
- 整理筛选区为稳定的两层布局：第一层放模型、来源和操作；第二层放快捷筛选与价格单位。控件高度、间距和断点保持一致，窄屏再自然换行。
- 表格继续只在自身容器内横向滚动；筛选栏、摘要和分享信息不随表格横向移动。

### 16.2 后台交互

- TanStack Query 使用上一份成功数据作为占位数据；`isFetching` 仅控制表格区域的轻量加载遮罩或进度提示，不卸载表格。
- 模型组合框支持输入、模糊检索、键盘上下选择、回车确认和自定义模型前缀；选择候选项后仍由“应用筛选”统一提交，避免每次键入都请求接口。
- 来源选择器、快捷筛选和更多筛选保持现有能力；切换条件后页码归一，但筛选区自身高度不变化。
- 对来源列数量变化造成的表格宽度变化，只更新表格内部滚动内容，不改变外层页面宽度。

### 16.3 分享页口令入口

未验证状态只保留一个紧凑口令卡片：

- 唯一提示文案为“请输入访问口令”。
- 显示口令输入框和确认按钮。
- 删除图标、页面标题、用途说明、密码存储说明等额外提示。
- 口令错误或过期时仍显示必要的错误反馈，否则用户无法判断下一步操作。

验证后的分享页使用稳定的摘要、筛选工具栏和表格最小高度；请求新筛选结果时保留当前表格，成功后原位更新，失败时保留当前结果并在原区域反馈错误。

### 16.4 测试与验收

## 18. 手动巡检完成后静默刷新（已实现并部署验证）

- 点击“立即巡检”时记录当前巡检时间与最近尝试时间，启动成功后将状态轮询临时提升为每秒一次。
- 后台任务运行期间保留当前统计卡片、筛选条件和表格内容，仅禁用重复触发按钮并显示巡检中状态。
- 检测到本次巡检完成或失败后，停止高频轮询，并通过查询缓存失效静默更新状态与当前筛选结果；不重载页面、不清空筛选、不隐藏旧表格。
- 启动请求失败或后台拒绝重复任务时立即停止等待，继续使用常规定时刷新频率。

## 19. 分享页移动端滚动加载（已实现）

### 19.1 目标与范围

- 仅在 `/price_monitor/view` 的移动端断点（`max-width: 760px`）启用纵向滚动加载；桌面端继续使用“上一页 / 下一页”分页。
- 首次查询、修改模型/来源/差异筛选、重置筛选或修改每页模型数时，清空旧分页累积结果并从第 1 页重新加载。
- 移动端滚动接近结果列表底部时自动请求下一页，并把新模型卡片追加到当前列表末尾，避免用户反复点击翻页。
- 不修改后台管理页、巡检任务、价格计算、动态口令或 AI 中继链路。

### 19.2 数据流与接口契约

数据流为：浏览器首次查询第 1 页 → 渲染结果并观察列表底部哨兵元素 → 哨兵进入视口 → 使用相同密码和筛选条件请求 `page + 1` → 校验响应仍对应当前查询 → 追加 `items` → 更新已加载数量 → 无更多数据时停止观察。

- 继续调用 `POST /api/price_monitor/public_query`，请求和响应结构不变，仍使用 `page`、`page_size`、`total` 与 `items`。
- 鉴权保持动态口令校验；不新增公开路由或放宽权限。
- 不新增数据表、字段、迁移、配置参数、Redis 键或文件。
- 服务端仍按模型分页，移动端只在展示层合并相邻页；不请求一次性全量数据。

### 19.3 关键交互与边界

- 使用单个 `IntersectionObserver` 观察表格后的加载哨兵；不绑定持续执行的 `scroll` 事件。
- 设置请求中标记，任何时刻最多存在一个“下一页”请求；重复触发直接忽略。
- 为每轮筛选查询维护递增版本号。旧筛选的迟到响应不得追加到新结果，避免快速切换筛选时混入错误模型。
- 只有 `loadedCount < total` 时才继续加载；空结果和最后一页显示明确状态，不再发请求。
- 下一页按当前服务端顺序追加。以模型名去重，防止快照在翻页期间刷新导致页边界轻微移动时出现重复卡片。
- 移动端隐藏“上一页 / 下一页”按钮，页脚范围文字改为“已加载 X 个，共 Y 个模型”；桌面端保持当前分页范围文案和按钮。
- 从移动端切换到桌面端时，恢复普通分页语义并显示当前页；从桌面切换到移动端时从第 1 页重新构建连续列表，避免把单页结果误认为完整累积结果。

### 19.4 加载与错误处理

- 首次加载继续使用现有加载状态；追加页加载时保留已有卡片，只在列表末尾显示“正在加载更多…”。
- 追加请求失败时保留已有结果，在末尾显示用户可点击的“加载失败，点击重试”，不把内部错误或口令内容写入页面。
- 若响应表示口令错误或过期，沿用现有逻辑返回口令输入页并清理累积结果。
- `IntersectionObserver` 不可用时回退为“加载更多”按钮，保证旧浏览器仍可继续浏览。

### 19.5 现有子系统影响

- 查询仍只读取价格巡检的不可变内存快照，不访问数据库、Redis 或新共享资源。
- 每个移动端会话每加载一页增加一次公开查询请求；现有全局 Web 限流继续生效。观察器只在接近底部时触发，且请求串行化，不形成请求风暴。
- 该路径不进入 AI relay，不影响主链同步执行、连接池、缓存或 goroutine 资源。

### 19.6 测试与验收
