# 图片流完成校验与 Realtime 首轮请求错误修复

2026-09-14 补充：xAI 虽使用自有 DTO，但出站同样采用标准 n，因此纳入覆盖后数量同步；其他厂商自有字段仍保持本方案边界。图片数单独作为计费证据只适用于按张计价，token 计价按实际 token 字段判断，详见 [后续四项修复](stream-limits-evidence-and-json-probe.md)。

## 已确认目标和范围

按用户“全部修复”确认实施四项审计结论：图片 JSON 转 SSE 被新校验拦截、图片 DONE 绕过张数、图片期望张数未同步出站覆盖、Realtime 首轮请求级错误后的正常关闭误补异常。仅修改新流程，继续使用入口流式开关和真实 HTTP 200 / WS 101 门控。非流式、关闭开关、非 200 和失败握手沿用原流程。

## 数据流与关键规则

1. 图片请求初始化期望张数至少为 1；普通聊天会话保持 0。标准 ImageRequest JSON 转换及参数覆盖完成后，用实际出站 JSON 更新张数；缺失或 null 沿用接口默认 1。厂商自有 DTO 不因缺少标准 n 而重置入口值；透传及保留原表单的 multipart 路径沿用入口解析值，不新增文件读取或记录请求。
2. 完整 JSON 的图片分支仅在图片会话内生效：data 为非空数组，各项有非空字符串 b64_json 或 url，数量达到实际期望。保留正常 JSON 转 SSE；空结果、损坏项、缺图、非法 usage 和读取错误继续异常。合法完整结果登记确认图片数，不估造 token。转换后成功写出并刷新 URL 或 base64 图片都属于有效交付；转换帧不重复累计确认图片数。
3. 图片 DONE 必须满足期望完成数；仅预览、空流或少图时进入既有上游异常结算。已成功交付的图片/预览不回撤，原异常计费矩阵保持；正常末帧立即交付，不等待下一事件。
4. Realtime 记录“尚未开始回答时已透传可恢复请求错误”。仅在无活动轮次且上游正常关闭时允许首轮账本为空，不补 error、不建立虚假轮次预留。新的 response.create 或真正 response 事件清除此标记；空握手直接关闭、回答中截断、真实断链、超时及原生服务器 error 维持原错误策略。原始恢复错误不改写。

## API、存储、配置和子系统

不新增 API、配置、表、字段、索引、依赖或权限。沿用 Root 诊断、响应首尾窗口及异步日志；不采集请求。复用现有唯一结算及退款，保持六行异常计费合同，不改变价格表达式或已完成轮次账本。Realtime 首轮空账本最终使用零用量结算释放原预扣，跳过的只是轮次 Reserve。

## Main Chain Impact

同步：初始化一个请求局部整数；出站已有 JSON 查询 n；完整 JSON 读取后的图片结构检查；DONE 的常量条件；Realtime 的局部布尔状态。无额外网络读取、定时等待或下一帧等待。异步：仅既有日志/统计工作者。

## Shared Resource Audit

仅使用原请求 StreamSession 短锁、HTTP 响应缓冲、WS 所有者局部状态和既有 BillingSession。新增 DB/Redis 访问、共享缓存、连接池及工作池为 0；不持锁执行网络 I/O。图片 JSON 仍受既有帧预算约束，不解码图片或另复制大段 base64。

## Concurrency Analysis

30k/100k RPM 下新增网络、DB、Redis 和工作协程均为 0。参数查询每请求一次 O(已有 JSON 字节数)，图片校验 O(当前响应字节数/图片项数)，不保存额外图片副本；DONE 和 Realtime 判断为常量成本。原帧预算及首尾采集大小不变，生产慢客户端和 p95/p99 需部署环境压测。

## 实施步骤和验证

先编写回归并确认旧实现失败，再实现、补中文注释并审计：
- 真正安装 BeginStreamAttempt / HTTP 门控的 JSON 图片到 SSE 夹具；正常 base64/url、多图、空/损坏结果、少图、异常和非流式隔离。
- SSE 无完成图、只有预览、一张/多张完成加 DONE，检查有效交付、诊断、收费来源及无假成功尾帧。

- 本地 WS 覆盖首轮请求错误后正常关闭、继续生成、重新发起未完成请求、真正断链及原空握手行为；断言原帧、error 数量、轮次预留和诊断资格。

## 风险和取舍

完整 JSON 必须整体有效才交给转换器；不将任意 data 数组或普通聊天文本当成图片成功。multipart 保持原非文件字段，不新增参数覆盖功能。Realtime 例外仅针对已透传恢复错误后的正常空闲关闭，不放宽其他首轮失败。
