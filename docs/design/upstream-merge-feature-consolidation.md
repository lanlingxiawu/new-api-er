# 上游合并后的功能、代码与页面统一方案

状态：用户已确认并授权实施，代码整合、本机验证和测试服务器原程序覆盖已完成。具体结果见文末。

## 目标与边界

同一业务能力只保留一个管理位置、一套表单规则和一个业务写入流程。菜单、页面、弹窗、
接口、配置读写、缓存失效、权限和测试一起整理，避免只隐藏按钮而保留另一套可写实现。
根据能力和调用关系选择保留版本，不按“上游”或“本地”来源一刀切。

基线为合并提交 `9f87082ff` 及后续修复 `4f1a33daf`。审计同时核对当前工作区，
其中使用日志导出统一、计费等改动正在独立进行；本方案不覆盖、回退或代替这些改动。
报告中“待整合”不表示已经完成实现或部署。

## 页面和导航的最终行为

1. 旧“模型 → 路由可靠性”从菜单消失，原路径只跳转到请求策略。其独有配置全部迁入后再删除组件。
2. 模型列表只管理元数据、厂商及部署，不再嵌套第二个完整价格同步或价格编辑工作区。
   需要从模型定位价格时，进入唯一计费价格页并携带模型筛选；已有筛选、标签及返回行为必须复用。
3. 价格巡检保留报价比较与风险工作流，当前价格编辑复用唯一价格核心，不保留两套普通模型编辑器。
4. 旧会话亲和、敏感词、注册、控制台日志等已实现跳转的路径继续只作别名。
   别名不出现在菜单、不渲染独立表单、不独立抓取或保存配置。
5. 管理员只读、普通用户、员工、超级管理员分别检查。无权限项隐藏或只读，后端仍逐次鉴权。
6. 语言切换、桌面和移动页面、深链刷新、返回导航、未保存离开确认、失败后保留草稿一并回归。

## 数据流与写入生命周期

配置页面加载 → 服务端按用户实际权限筛选 → 唯一表单校验与差异草稿 → 保存确认 →
管理接口授权和业务校验 → 原子写入 → 发布原有配置快照／更新已有缓存 → 刷新共同查询键 →
页面显示实际保存结果。兼容 URL 只跳转，不参与这条写入流程。

模型价格：读取统一配置及版本 → 共用价格草稿 → 预览 → 普通保存或巡检风险审查 →
共用模型价格事务和版本检查 → 一次更新与缓存失效。巡检独有报价过期、成本下限、
未知来源确认不能被普通保存包装或旧请求格式绕过。

日志导出按已有统一任务生命周期执行，不另建文件、队列或浏览器导出流程。

## API 契约与授权

| 契约 | 处理 |
|---|---|
| `GET/PATCH /api/option/request_policy` | 保留现有控制台认证、分区白名单和请求策略快照；新页面沿用，不添加第二个策略端点 |
| `PUT /api/option/`、`PUT /api/option/group` | 保留通用与配置组兼容契约，价格／策略最终委托统一业务函数，不再重复实现校验和写入 |
| `/api/option/model_pricing` 及 preview／convert | 保留现有管理权限、完整草稿、显式零值及版本冲突检查，作为普通价格维护的后端契约 |
| `POST /api/price_monitor/apply_price` | 路径保留，管理权限不降低；保留当前 `changes`、报价上下文与风险确认流程，旧 `items` 请求明确拒绝并本地化提示需刷新客户端，禁止悄悄走另一套写入 |
| `GET /api/admin/channel/cost` 等成本兼容端点 | 先核验实际消费方；即使需要保留契约也只委托同一成本业务函数，不维持第二套规则 |
| `/api/log/export/jobs`、`/api/log/self/export/jobs` | 接受正在进行的日志导出统一结果；不在本方案新加端点或改变自助／管理员范围 |

本方案不新增公开端点。鉴权仍位于正确的 AdminAuth／UserAuth 路由组，敏感操作继续二次认证。
PAT 范围声明、菜单权限、配置白名单与页面能力一起核对。

### 旧权限的兼容边界

旧 `models.routing-reliability` 授权同时涉及健康与重试，新 `request-policies.routing` 又包含会话亲和。
不能简单把旧权限扩大为整个新路由页权限，否则原来只能改重试的管理员会获得亲和配置编辑能力。

保留旧权限资源作为兼容能力来源，在统一的管理端权限解析中按原 OptionKeys／GroupKeys
求允许字段；新页面只展示或允许编辑该账号原有权限与新分区授权的字段。
请求体中的任意 scope 不能扩大范围。旧页面消失不意味着旧权限记录立即删除。
每日限额的配置组保存必须明确保留 GroupKeys，不能只复制 OptionKeys 导致页面能看不能保存。

如实现发现现有分区权限只能整页授权而无法安全表达原有子集，先完成字段能力映射，
不以放宽新页面权限或默默丢失原管理员权限作为替代。

授权设计遵循 [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)
的最小权限、默认拒绝及每次请求检查原则；认证入口清理参考
[OWASP Authentication Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)。

## 数据模型、配置与兼容性

不计划新增、删除或重命名业务表、配置存储键及现有价格版本。用户、渠道、钱包、日志、
佣金与历史导出数据保留；清理重复代码不等同于清理业务数据。
不新增用户可配置参数；复用 setting 中现有配置与默认值。

旧权限资源暂不删除，不进行全表权限合并或批量授权。价格写入事务、锁顺序、版本递增和
缓存发布继续使用现有统一实现。若实施中发现确实需要数据库结构变化，应先更新本设计，
执行 SQLite、MySQL、PostgreSQL 新库／升级／二次启动及服务器结构预演。

## 错误处理与交互

保持现有成功／失败响应契约，管理错误使用 common 的标准辅助函数；记录内部错误，
向用户展示可执行的本地化提示。旧改价请求应清楚说明需刷新页面，不暴露 Go 校验器或数据库错误。
保存中禁用重复提交；失败保留编辑内容；只读账户不能通过隐藏入口直接请求写入。
需要补充文案时，按项目国际化脚本同时维护七种前端语言及实际后端语言文件。

## Main Chain Impact

本方案仅统一管理页面与配置写入入口，不修改主 AI 转发中间件、请求路由、上游调用、
流式处理、预扣费、结算或任务运行协议。中继请求协程上新增同步操作为零，新增异步操作也为零。
现有管理写入仍发布同一配置快照，不改变转发读取值、优先级与生效方式。

### Shared Resource Audit

| 资源 | 关系及限制 |
|---|---|
| `options` 与价格版本行 | 管理写入与中继配置缓存相关；统一现有事务与锁顺序，不引入第二把定价锁或逐模型新查询 |
| Casbin 规则和角色 | 仅管理端解释旧权限；不在中继路径增加权限查询，不做全表重写 |

| 用户／渠道／钱包 | 不新增读写，不改扣费缓存；渠道成本整合只复用现有管理服务 |
| Redis、数据库连接池、工作池及文件 | 本方案不增加资源；导出沿用既有独立方案的资源保护，不添加中继后台工作 |

### Concurrency Analysis

在 30,000／100,000 RPM 下，中继每请求新增数据库访问、Redis 调用、锁和协程均为零。
管理保存仍是现有受控、低频事务；页面统一应减少重复加载与过期草稿覆盖机会。
这是设计分析，不代表已完成本轮压测。若实施超出上述管理路径，重新审核主链影响后再推进。

## 实施顺序与先写测试的要求
