# 使用日志导出统一方案

状态：已按用户确认的方案实现；验证记录见文末。

## 目标与范围

每个使用日志视图只保留一个导出入口，后台只保留一套生成流程。移除上游新增的浏览器拼接 CSV 导出，以及旧的同步 XLSX 快捷导出，统一复用现有后台任务，生成 gzip 压缩的 CSV 文件（`.csv.gz`）。CSV 本身不压缩，相比 XLSX 的实际压缩率取决于数据内容。

保留已有管理员模板、筛选、汇总、进度、取消和文件下载能力。普通用户通过受限任务接口导出自己的日志。员工导出维持现有权限边界，其他账单、台账导出不在本次范围内。

相关设计：`usage-log-export.md`、`usage-log-export-anomaly-and-templates.md`、`usage-log-export-throttle-accounting.md`、`employee-customer-log-export.md`。文档与代码冲突时以代码为准。

## 现有实现

上游 `streamLogs` 在写入 HTTP 响应期间持有数据库结果集，浏览器累计 CSV 内容。旧 `ExportLogs` 每批读取 1000 行，但没有接入请求取消。

已有后台任务支持 CSV.GZ、并发限制、查询超时、时间窗口、CPU 节流、行速率限制、磁盘检查和文件过期清理。本次复用这套实现，不另建任务系统。

## 数据流与生命周期

登录用户提交 → 校验筛选条件和允许导出的列 → 固定服务端确定的数据范围 → 获取配额和并发名额 → 后台分批扫描 → CSV 转义及 gzip 压缩 → 标记完成 → 授权下载 → 到期清理。

每批查询完成并释放连接后，才进行格式转换、压缩、节流等待或下载。复用现有时间窗口、游标分页和单批查询超时机制，不让事务或结果集跨越文件生成和客户端下载过程。

任务超时、主动取消、执行失败或节点异常时必须释放并发名额，不得将未完成文件作为成功结果下载。现有清理机制负责废弃文件与过期元数据。

提交后任务在后台独立执行，关闭弹窗不隐式取消。页面展示进度并提供取消操作。浏览器直接下载完成的文件，不累计 CSV 行；界面明确提示文件经过压缩，解压后可使用 CSV。

## 接口契约与权限

管理员继续使用 `/api/log/export/jobs` 下的现有接口，保留 `AdminAuth` 及创建、列表、详情、取消或删除、获取下载地址的契约。新任务统一使用 `csv_gz`，不再生成 XLSX。

在 `/api/log/self/export/jobs` 下增加受 `UserAuth` 保护的接口：

| 方法与相对路径 | 请求及响应 |
|---|---|
| `POST /` | 接收 `{filters, options}`，仅允许普通用户可见的筛选条件和选项，通过标准成功响应返回现有任务公开数据结构 |
| `GET /` | 只列出当前用户的自助导出任务 |
| `GET /:job_id` | 返回进度、状态及已完成分片信息，不返回内部路径 |
| `DELETE /:job_id` | 只能取消或删除当前用户的自助任务 |
| `GET /:job_id/download-url` | 校验归属与数据范围后，复用现有签名下载响应和分片选择契约 |

自助筛选沿用现有请求字段名，仅开放时间、模型、令牌、分组和日志类型。不接受用户 ID、用户名、渠道筛选、任意列、共享模板或管理员汇总维度。服务端强制限定当前用户 ID 和安全列，详情也须过滤管理员及超级管理员诊断信息。

不能只校验创建者：曾经是管理员的用户降权后，不得通过自助接口访问历史特权导出。

继续使用现有签名下载接口，不新增匿名路由。保留下载令牌有效期、节点与文件定位、并发下载限制和清理机制。不放宽管理员路由组权限；新路由按现有控制台会话约定补入凭证路由声明表。

移除旧 `GET /api/log/export`、`GET /api/log/self/export` 生成接口及废弃前端调用，不把原 NDJSON 响应悄悄改为 CSV 下载。交付说明明确记录接口移除。

## 数据模型与兼容处理

计划不新增 SQL 表或结构迁移。在现有序列化任务元数据中增加自助导出范围标识；缺少标识的旧任务按历史特权任务处理。扫描器在每批查询中应用服务端指定的用户限制，客户端元数据不能扩大范围。

新任务统一使用 `csv_gz`。已有 XLSX 模板在使用时转换为 CSV，不批量改写数据库记录。已完成的历史 XLSX 文件保留原格式信息，到期前仍可下载。

仅保留历史文件所需兼容逻辑；确认其他调用方后，移除无用的 XLSX 生成代码和格式选择界面，不删除其他导出仍在使用的共享依赖。

## 配置参数

复用 `log_export_setting` 中的批大小、查询和任务超时、并发名额、CPU 与行速率节流、压缩、磁盘空间和保留时长配置。

普通使用日志导出开关统一使用 `log_setting.user_export_enabled`，其他台账开关不变。新增 `log_export_setting.user_max_range_sec`，默认 30 天，使自助时间范围限制独立于管理员配置。通过现有设置接口和分区白名单读写。

实现前核实关闭 Redis 和多节点部署时的行为。如果后台任务依赖 Redis，明确提示该运行条件，不可用时返回清晰错误，不降级为无资源限制的同步导出。获取并发名额失败不得绕过限制。

## Main Chain Impact（主链路影响）

不新增中继钩子、中间件、计费改动或每个 AI 请求上的额外工作。导出只在已有受并发限制的后台任务中运行。

在中继每分钟 3 万或 10 万请求的场景下，本次改动增加的同步中继操作为零，但后台任务仍会争用磁盘、CPU 和数据库容量。这属于架构分析，不代表完成了压测。

## 共享资源审计与索引设计

| 资源 | 共享关系与保护措施 |
|---|---|
| `LOG_DB`、`logs` | 与日志写入和控制台查询共享，可能还与主库共用连接池。复用批次超时、时间窗口、索引支持的游标查询及并发上限，不新增连接池或长事务 |
| Redis `logexport:*` | 复用导出专属命名空间及分布式并发名额，检查与中继键无冲突。旧 `log_export:*` 锁仅在最后一个调用方移除后删除 |
| 文件、gzip 缓冲和任务名额 | 由现有分片、磁盘、并发和保留时长限制约束，生成和下载不持有跨批 SQL 游标 |
| 渠道和用户缓存 | 自助导出不读取特权渠道信息，管理员导出保留现有有界查询方式 |

核对自助范围下的实际查询与索引，重点检查用户 ID、时间及游标排序组合。在接近真实数据规模的 SQLite、MySQL、PostgreSQL 环境执行 `EXPLAIN`，再确认索引覆盖情况。若执行计划表明确有需要，再增加索引并单独记录迁移验证。

## 业务规则与错误处理

导出关闭、范围无效、配额或并发名额不足、磁盘空间不足时拒绝创建。超时、取消、扫描失败、压缩或写入失败、达到资源上限时，任务进入失败或取消状态，不将部分结果展示为完整导出。

保留 CSV 公式注入防护，正确转义逗号、换行和引号；可选 UTF-8 BOM 写入 gzip 内部的 CSV 内容。保留时区处理及普通用户日志脱敏。无匹配记录时生成合法的仅含表头的压缩 CSV。

使用标准接口错误辅助函数和可操作的本地化提示，内部错误写日志且不包含凭证。前端补齐七种语言，后端按实际语言文件补齐文案。复用现有弹窗和任务列表样式，不修改受保护的认证基础模块。

## 实现前的测试设计

1. **权限**：跨用户访问、伪造筛选或列、历史特权任务、角色降权、导出关闭。
2. **分页边界**：空结果、单行、批大小减一、等于批大小、批大小加一、相同时间戳、窗口边界、并发插入，验证初始查询范围记录不重复、不遗漏。
3. **连接释放**：使用受限连接池及刻意阻塞的文件写入，验证压缩和下载前已释放查询连接；覆盖查询超时、任务超时和取消后的资源释放。
4. **资源治理**：同用户与多用户名额耗尽、Redis 故障、磁盘写满、压缩失败、节点中断及清理；保留原节流计费测试。
5. **文件**：CSV 转义、公式安全、中文及 BOM、gzip 压缩解压、仅表头文件、分片限制和历史 XLSX 文件及模板兼容。
6. **前端**：每个视图只有一个导出操作，进度、取消、重试、下载可用，不累计 CSV 行，普通用户与管理员视图隔离。
7. **验证环境**：运行相关 Go 测试、前端类型检查、代码检查、测试和构建，以及真实 SQLite、MySQL、PostgreSQL 查询验证。记录实际环境与未覆盖项，不宣称未执行的数据库验证或压测已通过。

## 完成标准

管理员与普通用户通过统一使用日志导出流程，由既有受资源限制的后台任务生成 CSV.GZ。慢下载不持有数据库结果集，重复生成实现被移除，原有高级功能及历史下载保留。

## 实现记录

- 删除两条同步生成接口及对应的浏览器 CSV 拼接、后端 XLSX 写入代码。新任务统一生成 CSV.GZ；历史完成文件沿用原格式下载，不批量改写模板。
- 自助任务使用 `self_export` 标记，并要求创建者、筛选用户一致。创建接口拒绝越权字段；列表、详情、取消和下载均检查任务范围；签名下载还检查账户当前是否启用。
- 自助导出按普通用户列权限渲染，读取脱敏所需的类型和原始错误字段后再过滤管理员诊断。管理员模板、汇总和员工导出的原有权限检查保留。
- `timeout_sec` 现限制任务的总经过时间，包含 CPU、速率和低峰等待；扫描器仍保留原工作预算检查。每个受并发上限约束的任务增加一个取消监视协程，每秒最多检查一次导出取消标记，不在中继请求中运行。
- 普通用户默认最大时间范围为 30 天，通过 `log_export_setting.user_max_range_sec` 配置。后台导出依赖 Redis，关闭或不可用时提示不可用，不回退同步生成。
- 保留现有查询连接池，每批读取完成后释放连接，再渲染和压缩。下载读取已完成文件，不执行日志扫描。使用原有 `logs` 索引，没有新增 SQL 表、列、索引或迁移。

## 验证记录（2026-10-16）

使用独立测试资源：SQLite 3.50.4 临时数据库、MySQL 8.0.46、PostgreSQL 15.19、Redis 7。容器数据库仅供本次验证，不连接共享开发库。执行 `go test ./model -run Export -count=1 -timeout 180s` 与对应 `./controller` 检查；SQLite 无主库配置时，部分既有数据库集成用例会跳过，自助扫描、脱敏、连接释放和总超时用例使用真实临时 SQLite 执行。

单连接池用例在扫描回调中断言占用连接数为零，并成功再次取连接；覆盖自助越权字段、跨用户及历史特权任务访问、账户停用后的下载、敏感详情、公式防护和资源等待期间总超时。文件测试通过实际 gzip 解压及 CSV 解析校验。

SQLite 与 MySQL 查询计划使用已有 `idx_log_export_user_time`；PostgreSQL 在临时填充 5 万行后选择 `idx_logs_user_id` 位图索引扫描再排序，空表选择顺序扫描。未添加索引。此次无结构迁移，未执行旧版本升级迁移演练；没有验证 ClickHouse，也没有进行 3 万或 10 万 RPM 压测。

最终结果：SQLite、MySQL、PostgreSQL 三组导出测试均通过（SQLite 的跳过范围见上文）。`go build ./...`、路由与访问令牌规则回归通过；`bun run typecheck`、`bun run lint`、28 个前端测试文件共 461 项测试及 `bun run build` 通过。lint 保留项目已有警告，无错误。取消后的未完成文件清理、旧 XLSX 请求转换 CSV.GZ 已另行通过真实 MySQL 回归。

复验曾因无主库但配置 Redis 的旧控制器测试触发空数据库异常，留下并发名额，导致后续共享 Redis 库的名额测试失败。最终按数据库使用独立 Redis 库复验，SQLite 未配置 Redis 的控制器集成用例按约定跳过；没有修改生产并发限制来绕过测试。

本次保留原有后台任务的限制与资源保护，不声称导出完全不消耗共享数据库、CPU 或磁盘资源。隔离测试容器在验证完成后清理。
