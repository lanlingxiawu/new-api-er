# 旧版 function_call 有效交付修复

## 目标、问题与已确认范围

用户确认修复旧版 `choices[].delta.function_call` 被漏判有效内容的问题；“受管流式异常跳过渠道自动禁用”暂缓，本轮不调整 controller 或渠道健康状态。

当前原数据转发可成功写出旧版函数调用，但统一流式交付观察只累计新版 `delta.tool_calls`。多候选中一个函数调用已经结束、另一个候选上游异常时，结算会误选无有效交付的零用量路径。

## 数据流与推荐实现

1. 在现有 `StreamSession.CommitDelivery` 识别实际写出且刷新成功的旧版函数调用对象；请求是否透传不参与判断。
2. 以 `chat:<候选索引>:legacy` 隔离旧版调用，与新版工具索引命名空间分开。复用已有 128 项、名称和参数合计 8 MiB 的工具缓存，不另建无界映射。
3. 函数名和参数支持跨帧拼接；共享工具方法增加显式的名称追加参数，旧版开启，其他协议仍按原规则更新非空名称。名称使用独立拥有字节的 Builder，避免保留整帧或反复拼接完整前缀。
4. 候选真实 `finish_reason` 已成功交付后，非空名称和完整合法 JSON 对象参数才确认有效；空参数按现有工具规则视作 `{}`。残缺参数、无名称、缺结束、写入/刷新失败不确认交付；重复空结束不重复计量。
5. 复用既有异常结算选择：上游异常有交付且有确认用量采用确认值（含显式零）；有交付而无确认用量采用交付估算；无交付仍为零。用户断开的确认用量规则不变。
6. 原 SSE 不过滤、不改写、不等下一帧；只把完整交付的名称和参数交给现有增量估算器。正常流原渠道计量、强制 DTO 转换的旧版字段支持程度不在本轮扩展范围。

## API、配置、数据模型与错误处理

无新增端点、配置、依赖、表、列或迁移。沿用 `stream_error_setting`、真实成功响应门控、现有补发错误、异常用量选择与单次资金结算。原响应/下游正文诊断、Root 查询权限与原错误透传保持原状，不额外读取或记录请求数据。

## 涉及文件与实施步骤

- `relay/common/stream_session.go`：旧版交付观察、工具名称累计与中文参数注释。
- `relay/common/stream_tool_delivery.go`：现有共享方法调用保持非追加名称语义。
- `relay/common/stream_legacy_function_test.go`、`stream_retention_test.go`：协议、资源边界、成功写出/刷新和名称内存所有权回归。
- `relay/channel/openai/stream_legacy_function_test.go`：真实 OpenAI 适配器内存 SSE 及异常结算选择夹具，不执行实际资金操作。
- 本文及统一流式设计文档：记录实现及测试结果。

先写回归并确认 RED，再实施修复，最后运行相关 Go 测试、构建、差异检查及中文注释核对。

## Main Chain Impact

同步仅在现有交付观察中多一次字段查找；旧版调用复用候选缓存，名称和参数增量累计、完成时校验和估算。没有额外聚合等待、网络调用或同步持久化。异步日志、统计、资金资源调度全部沿用现有流程。

## Shared Resource Audit

复用单请求会话短锁、128 项工具缓存和共享 8 MiB 预算；锁不跨网络 I/O。无新增 Redis 命名空间、DB 访问、文件句柄、连接池、工作池或跨请求可变状态。不修改 users/tokens/channels/订阅资源的访问次数或方式。

## Concurrency Analysis

30k/100k RPM 下每请求新增 DB/Redis 调用、goroutine、连接数均为零。普通文本只有常数次字段查询；旧版工具增量累计为摊销 O(名称与参数总字节数)，结束校验为 O(参数字节数)，预算不随流时长增长。Builder 的容量增长存在常数倍开销，8 MiB 是已保存有效字节预算而非进程 RSS 上限。不会新增下游等待，但解析和计量仍有微小 CPU 成本；容量判断以压测为准。

## 风险、可选项及验证

- 覆盖单帧、分片名称/参数、空参数、残缺 JSON、无名称、无结束、候选隔离、现代与旧版工具共存、重复结束、128/129 项及字节预算、响应重置。
- 写入器夹具验证实际正文不变、刷新前不记有效、短写及刷新错误不确认。
- 真实适配器覆盖 n=2 下已完成旧版调用后 EOF/原错误/非法 JSON；确认正数/零/缺失用量；不完整调用仍为零。请求 DTO 保留旧版 functions/function_call，响应流程不依赖请求转换。
- 原有现代工具、Claude、Responses/Realtime 及门控回归同时运行，确保共享方法语义保持。
- 不扩展正常流旧版函数 token 估算或强制格式转换兼容；不处理本轮明确暂缓的渠道自动禁用问题。

## 实施结果与验证（2026-09-14）

- RED 阶段成功复现：单帧/分片旧版调用交付内容为空；真实 OpenAI 适配器在候选 0 已结束、候选 1 异常时仍标记 `EffectiveContent=false`。补齐观察分支后上述回归通过。
- 复用原工具缓存，仅旧版调用开启名称追加；现代工具非空名称覆盖、Claude 参数累计、Responses/Realtime 完成去重语义保持。名称独立内存所有权测试随 Builder 调整，断言原意不变。
- 夹具通过名称/参数分片、缺字段、参数非对象/不完整、重复空结束、不同候选、新旧工具同候选、共享字节预算与 128/129 项边界、SDK 新响应清理、短写/刷新失败。原始 SSE 逐字节保持，刷新前无有效交付。
- 真实适配器 15 个组合覆盖 EOF、原 error、非法 JSON，以及确认正数/显式零/无报告/未完成调用；完成调用分别选择 upstream 或 estimated，未完成且无其他正文保持 none。重复 Finalize 返回同一结果，不重复补错误或累计估算。
- 透传复核：`CompatibleHelper` 的透传分支只选择请求 Reader，后续与转换分支共用 DoResponse；BeginStreamAttempt 已安装相同写入器。新回归直接使用入口 DTO 和真实响应适配器，不依赖请求转换；没有实际访问外部供应商或执行资金扣款。
- 核心旧版交付、新版工具、候选尾帧回归连续 20 次通过；`go test ./relay/... ./logger ./common ./router ./setting/operation_setting ./i18n -count=1` 和根模块 `go build ./...` 通过。
- service/model/controller/middleware 的 Stream/Diagnostic/RejectReason/Private 相关回归通过；使用既有仓库外 overlay 跳过数据库 TestMain，只验证 DB 无关夹具，不代表真实数据库联调。
- 已核对新增/修改业务字段、函数及参数中文注释，执行 gofmt 与差异检查。没有修改 controller、资金接口、relaykit、前端、配置或数据库。未运行生产负载；本机 CGO 关闭，未运行 race 检测。未提交 Git，未部署。
