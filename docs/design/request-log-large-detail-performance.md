# 请求日志大详情性能优化

状态：用户已确认“不截断，尽量优化，其余按方案来”，按此约束实施。

## 目标与范围

完整保留已采集并获准返回的日志内容，不新增预览截断。详情页的大正文采用虚拟滚动，滚动可访问全部内容；复制与 JSON 下载仍覆盖完整字段。小正文保持自动 JSON 格式化，大正文保持原始文本。此处不改变服务端原有采集上限及其截断标记。

## 当前问题与数据流

当前 Block 在每次渲染中调用 JSON.parse/stringify，并把全文放入自动换行的 pre。下载状态改变也会重复渲染四个 Block。JSON 下载序列化在主线程执行。

新数据流：现有详情接口返回 → memo 化 Block → 小文本缓存格式化结果；大文本交给 Worker 建立显示行索引 → 仅渲染视口附近的文本行。复制使用小文本已缓存的格式化内容或大文本原文；下载由 Worker 序列化当前详情并返回 Blob，浏览器主线程仅触发文件保存。

## 展示规则与边界

以 64 Ki UTF-16 code units 为小文本阈值，避免为判定大小再次编码整段正文。超过阈值的内容不执行 JSON 美化。

显示行按换行符划分，超长单行再拆为最多约 256 UTF-16 code units 的显示段，避免 base64 或压缩 JSON 单行仍导致全文排版。分段不得拆开代理对或 CRLF。分段只是显示换行，不修改原始字符串；保留空行、结尾换行和所有字符。索引仅存偏移，避免 split 构造大量子串。使用现有 @tanstack/react-virtual 固定行高虚拟列表，允许横向滚动查看宽字符内容；只渲染可见行和少量预渲染行。

虚拟列表原生选择和浏览器查找只覆盖挂载区域，完整内容通过“复制”或“下载 JSON”获取，界面说明此行为。处理期间显示加载状态；Worker 失败提示用户复制或下载查看，不回退到主线程全文渲染。切换日志/关闭弹窗终止未完成的索引 Worker，过期结果不得出现在新日志中。

## API、数据模型与配置

不新增或修改接口，仍为 `GET /api/request-log/:id`，沿用 AdminAuth、view/view_detail 和服务端脱敏规则。没有表、列、索引、迁移、服务端缓存或设置开关变化。阈值与显示段长度为前端内部实现常量。

## 下载生命周期与错误处理

下载启动后创建独立 Worker，将已授权的详情对象发送给它。Worker JSON.stringify 后构造 application/json Blob 并返回，主线程创建 object URL 和下载链接。成功、错误、超时、取消均终止 Worker；链接和 object URL 按原有延迟释放策略清理。关闭/切换详情取消仍在准备的下载，避免后台处理结果归属错误。

Worker 加载失败、序列化失败或超时使用可重试的国际化提示，不在 UI 暴露异常堆栈。不使用会重新阻塞主线程的全文序列化兜底。无需新增外部网络服务。

## Main Chain Impact 与 Shared Resource Audit

全部变更发生在浏览器详情查看路径；relay goroutine 无新增操作。DB、Redis、服务器 worker 池、日志目录和文件句柄均无新增使用。每个大文本块最多一个短生命周期索引 Worker（最多四个），一次下载最多一个 Worker；显示行索引为 O(n) 偏移数组，传回时转移 ArrayBuffer。主线程仍承担 API JSON 解码及 Worker 消息复制的开销，不能承诺所有尺寸零卡顿。

使用 React.memo 和 useMemo 避免父组件下载状态变化导致反复格式化。不得改变列表缓存或权限语义。对大日志设置局部较短的 inactive query 回收时间，并通过 AbortSignal 取消已关闭详情的在途读取，避免连续打开多条大日志时长期保留无用正文；不修改全局 HTTP/认证模块。

## 实施前确定的验证用例

- 空文本、64 Ki 临界值及越界、普通 JSON/非法 JSON、SSE、纯文本、小/大中文内容。
- 超长单行、全部换行、CRLF、孤立 CR、尾部换行、代理对恰逢显示段边界；按索引拼回必须与原文逐字一致。
- 对 10 MB 合成日志建立索引，检查渲染候选行数量受视口约束，比较旧全文格式化耗时及新索引耗时，注明 CPU 时间与主线程时间区别。
- Worker 中下载序列化后 Blob 解析结果与原始详情一致，包括空字段、正文、headers_withheld、截断标记和日志 ID。
- 模拟 Worker 错误、启动失败、超时、取消和成功均清理资源；切换日志不得使用旧结果。
- typecheck、lint、前端生产构建验证 Worker 可打包。不新增测试框架；使用临时脚本验证纯数据处理与 Worker 生命周期。真实浏览器滚动、布局和下载仍需可用浏览器验收。

## 实施结果与验证

- 大正文采用原文偏移索引、256 code units 左右的显示段、20 px 固定行高和 8 行 overscan。每页最多 10,000 个显示段，页内虚拟滚动，全部页面均可访问。分页防止极端大量空行超过浏览器最大滚动高度；不是内容截断。
- 小正文只在内容变化时格式化，Block 使用 memo。大正文不再进行全文 JSON 美化；复制覆盖完整显示文本，下载保留接口返回的原始字段。
- 索引和下载使用独立短生命周期 Worker，30 秒超时；成功、错误、消息错误、启动异常、发送异常和取消均有清理。关闭/切换详情取消旧任务，不展示过期结果。
- 详情 query 关闭后切换为空 ID，传递 AbortSignal，gcTime 为 0，及时释放不再查看的正文；未修改全局 HTTP、认证、列表缓存或后端采集逻辑。
- 回归用例在实施前写入临时脚本，首次运行因待实现模块不存在而失败，实施后通过。覆盖空文本、普通/非法 JSON、SSE、阈值边界、10 MiB 单行、10 万个换行、中文、代理对、CRLF、独立 CR、尾部换行；按索引重组与原文逐字一致。
- Worker 模拟覆盖成功、无效返回、error、messageerror、构造失败、postMessage 失败、已取消、进行中取消及超时，验证创建/终止数量一致。
- Bun 实际 Worker 验证：10 MiB 文本索引生成 40,960 个显示段，约 31 ms（含启动和传输），主事件循环期间继续运行；请求/响应合计 20 MiB 的下载 Blob 解析后与原对象完整一致。该数据是本机运行时验证，不代表浏览器帧率。
- `bun run typecheck`、`bun run lint`、`bun run build` 通过，生产构建包含独立 Worker 资源。lint 仅剩已有 footer 的 dangerouslySetInnerHTML 警告。七种语言新文案、已有分页按钮文案和 UTF-8 无 BOM 验证通过。
- 当前环境无可用浏览器，因此尚未验证真实浏览器的滚动、分页交互和下载手势；需在浏览器验收。
