# 修复 2FA 会话连续性

## 目标与范围

修复用户启用、禁用 2FA 或重新生成备用码后，后台登录状态立即失效的问题；同时修复“密码登录 + 2FA 验证”过程中，前端没有把后端签发的一次性登录流程令牌从密码验证步骤传递到验证码验证步骤的问题。

本次修改仅涉及后台登录界面、2FA 设置界面及其前端状态管理，不修改 TOTP 算法、备用码验证规则、会话有效期、后端接口契约或 AI 中转鉴权逻辑。

## 数据流

### 修改 2FA 安全设置

1. 已登录用户向现有 2FA 管理接口提交 TOTP 验证码或备用码。
2. 后端提交 2FA 设置变更，提升 `users.auth_version`，推进当前 `user_sessions` 会话版本，撤销其他登录会话，轮换刷新 Cookie，并在响应的 `data` 中返回新的认证凭证包。
3. 现有请求层通过接口配置的 `acceptAuthRotation` 验证 `data` 并在响应返回功能组件之前应用新凭证。
4. 对话框显示操作成功，并重新获取当前 2FA 状态。

如果接口返回成功但响应中意外缺少认证凭证包，前端不能继续假定当前会话有效。界面应提示用户当前登录状态无法继续使用，并引导用户重新登录。

### 密码与 2FA 登录

1. 用户向 `POST /api/user/login` 提交用户名和密码。
2. 当账户启用了 2FA 时，后端返回 `require_2fa`、`flow_token` 和 `expires_at`。
3. 前端把不透明的流程令牌保存到当前标签页的会话存储中，然后跳转到 `/otp`。
4. OTP 表单读取该令牌，并把令牌与 TOTP 验证码或备用码一起提交到 `POST /api/user/login/2fa`。
5. 验证成功后，前端清除流程令牌、应用后端返回的认证凭证包，然后进入后台。
6. 用户取消验证、流程过期、流程状态异常或收到不可重试的验证结果时，前端清除流程令牌并返回登录页面。

用户名和密码验证完成后，前端不会保存用户密码。

## API 契约

本次修改不需要调整后端接口契约。

### `POST /api/user/login`

- 鉴权方式：公开接口，继续使用现有的关键接口限流中间件。
- 请求：`{ "username": string, "password": string }`
- 需要 2FA 时的响应数据：
  `{ "require_2fa": true, "flow_token": string, "expires_at": number }`

### `POST /api/user/login/2fa`

- 鉴权方式：同时持有有效的一次性 2FA 登录流程令牌，以及正确的 TOTP 验证码或备用码。
- 请求：`{ "code": string, "flow_token": string }`
- 成功响应数据：现有认证凭证包。

### 现有的 2FA 管理接口

- `POST /api/user/2fa/enable`
- `POST /api/user/2fa/disable`
- `POST /api/user/2fa/backup_codes`

这些接口继续使用 `UserAuth()` 鉴权。接口成功后已经在响应的 `data` 字段中返回替换后的认证凭证包。

## 数据模型变更

无后端数据模型变更。现有 `auth_flows`、`two_fas`、`two_fa_backup_codes`、`users` 和 `user_sessions` 的行为保持不变。

浏览器只保存不透明且短期有效的 2FA 登录流程令牌及其过期时间。数据保存在 `sessionStorage` 中，仅对当前标签页有效，并在验证成功、用户取消、流程状态无效或流程过期时清除。

## 配置参数

无新增配置参数。

## 核心业务逻辑与边界情况

- 登录响应中必须包含非空的流程令牌和未来的过期时间，前端才允许跳转到 `/otp`。
- 流程令牌不能放入 URL 查询参数，避免其出现在浏览器历史记录、日志、引用来源或截图中。
- 同一标签页刷新页面后，待验证流程仍然有效；关闭标签页后，待验证流程自动清除。
- 用户重新发起登录时，新的待验证流程会替换旧流程。
- OTP 登录成功或用户选择“返回登录”时，都必须清除待验证流程。
- 流程状态缺失、无效或已过期时，前端不再发送 OTP 请求，而是提示用户重新登录。
- 启用 2FA、禁用 2FA、重新生成备用码继续使用现有请求层的 `acceptAuthRotation` 机制，在刷新状态或关闭对话框之前应用接口返回的新认证凭证包；功能组件不重复应用凭证。
- 保持上游维护的 `web/src/lib/api.ts`、`auth-session.ts`、`auth-session-sync.ts`、`http-client.ts` 和 `server-error-message.ts` 与 `main` 分支字节一致。项目定制的状态处理和响应处理放入独立的功能模块。

## 错误处理策略

传输错误和 HTTP 错误继续由现有 HTTP 拦截器处理。接口返回 HTTP 200 但 `success` 为 `false` 时，由对应功能模块处理。2FA 登录请求设置 `skipBusinessError`，避免全局响应拦截器和 OTP 表单对同一个业务错误各显示一次提示。

所有面向用户的提示都通过现有前端 i18n 系统翻译。提示内容应明确说明临时验证会话已经过期，并指导用户重新登录；不能向用户显示内部响应细节或原始异常信息。

## 与现有子系统的交互

- **会话服务：** 使用后端已经返回的认证凭证包，不修改后端会话行为。
- **认证状态与跨标签页同步：** 使用现有 `applyAuthBundle` 入口，使 access token 和会话状态按照现有流程更新。
- **2FA 数据模型：** 不变。
- **计费、额度、缓存和 AI 中转：** 无交互。

## 主链路影响

本次修改没有任何逻辑运行在 AI 中转请求协程中。所有改动都发生在浏览器的后台登录或个人设置操作中，不修改中转中间件、渠道适配器、流式响应、计费钩子或额度处理逻辑。

## 共享资源审计

- 浏览器 `sessionStorage`：新增 2FA 专用键命名空间；AI 中转链路不访问浏览器存储。
- 前端认证状态：复用现有后台 access token 和会话状态；后端 AI 中转链路不共享此前端内存结构。
- `users`、`user_sessions`、`auth_flows`、`two_fas` 和 `two_fa_backup_codes`：不新增任何后端读写操作，前端仅开始正确使用现有响应字段。
- Redis、数据库连接池、协程池和后端内存缓存：无新增使用。

## 并发分析

在 AI 中转链路达到 100,000 RPM 时，本次修改不会增加任何数据库调用、Redis 调用、锁、协程或中转路径内存分配。后台登录和个人设置请求保持现有的同步后端开销，不进入 AI 中转热路径。

## 测试设计与验证

前端目前没有测试框架，因此本次修复不会擅自引入新的测试框架。验证范围如下：

- TypeScript 类型检查确保登录响应和 OTP 请求中包含必需的 `flow_token`。
- ESLint 检查所有改动的功能模块。
- 生产构建验证路由和模块组合。
- 人工契约检查覆盖待验证流程缺失、空值、过期、被新流程替换、验证成功、用户取消以及页面刷新等情况。
- 代码审查确认启用 2FA、禁用 2FA 和重新生成备用码接口已经设置 `acceptAuthRotation`，请求层会在功能组件继续执行前应用接口返回的新认证凭证包。

bun run build

## 评审修订：流程有效期与用户文案（2026-07-31，已实现）

### 客户端时钟

`expires_at` 是服务端绝对时间，浏览器不能用 `Date.now()` 判断该流程是否仍有效。客户端
时钟可能偏快或偏慢；偏快会让密码已经验证成功的用户无法进入 OTP 页面。

修订后的规则：

- `savePendingTwoFAFlow` 只校验 `flow_token` 非空以及 `expires_at` 是有限数字，不再与
  客户端当前时间比较。
- `getPendingTwoFAFlow` 不再根据客户端时间删除流程。
- 服务端 `GetAuthFlow` / `ConsumeAuthFlow` 是流程有效期的唯一权威判断。
- OTP 接口返回流程已过期时，前端清除 `sessionStorage` 中的令牌，显示可操作的本地化
  提示并返回登录页。
- `expires_at` 可继续存储用于展示或诊断，但不能作为授权判断依据。

这比保存“接收响应时刻 + 剩余秒数”更稳健：后端当前只返回绝对过期时间，客户端无法在
时钟不可信时准确计算剩余秒数；增加服务端 `expires_in` 会扩大 API 契约，而取消客户端
授权判断即可彻底避免该问题。

### 后端用户文案

`Verify2FALogin` 的所有用户可见错误改用 `ApiErrorI18n`，至少覆盖：

- 参数无效；
- 流程已过期，需要重新登录；
- 用户不存在或已禁用；
- 用户未启用 2FA；
- TOTP 或备用码无效；
- 备用码校验的内部错误（记录底层错误，客户端只收到脱敏文案）。

对应消息键同时写入后端 `i18n/locales/en-US.yaml` 与 `zh-CN.yaml`，不再透传
`err.Error()` 或硬编码中文。前端 `skipBusinessError: true` 保持不变，由 OTP 表单对
服务端已本地化的业务错误只展示一次。

### `sessionStorage` 风险

流程令牌继续保存在 `sessionStorage`。它是五分钟、一次性、限定用途的凭证，放在 URL
会带来浏览器历史、Referrer 和日志泄露，内存存储又无法支持刷新恢复。XSS 确实可以读取
它，但同源 XSS 也能读取现有 access token 并代替用户发起请求；本次不单独引入一套无法
隔离同源脚本的存储机制。降低 XSS 风险属于 CSP、依赖治理和令牌架构的独立安全工作。

### 测试增补

- 前端无测试框架：用类型检查和人工契约检查覆盖客户端时钟快/慢、刷新、过期响应清理。
- 后端先增加 `Verify2FALogin` 控制器测试，覆盖每个错误分支的 i18n 键/本地化响应，
  并确认原始备用码错误不会返回客户端。
- 完成后运行相关 Go 测试、`bun run typecheck`、`bun run lint` 和 `bun run build`。

实际实现取消了 `storage.ts` 中保存和读取流程时的客户端绝对时间比较；后端
`Verify2FALogin` 的错误分支统一使用 i18n helper，并记录脱敏前的底层错误。新增的流程
过期消息已同步到后端英文、简体中文和繁体中文语言包。
