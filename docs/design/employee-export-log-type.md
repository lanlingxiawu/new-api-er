## 目标与范围

员工导出当前被服务端强制设为消费日志，且候选值查询也被同样限制。改为显式选择日志类型，默认全部；从客户日志列表打开时继承当前类型。复用现有日志类型选项（全部、消费、错误等），避免列表可见而导出不能选择。全部指所属客户的日志记录，不读取充值订单等业务表。

## 数据流与 API

员工表单 → 预估/创建任务 → 校验类型及客户/模板 → 保存任务类型快照 → 既有后台扫描及文件生成 → 既有授权下载及过期清理。

- `POST /api/user/employee/export/estimate` 和 `/jobs` 新增顶层可选 `type` 整数，与日志列表语义一致：缺省/0 为全部，1–7 对应既有日志类型。拒绝负数、未知编号、非整数及错误类型。类型属于基础范围选择，不依赖自定义模板的 `allowed_filters`；原模板限定的其他筛选和字段不变。
- `GET /api/user/employee/export/options` 新增可选 `type`，模型/令牌/分组选项按同一类型查询，切换类型重新查询并重置分页；客户候选仍只按归属查询。
- 以上沿用既有员工认证与导出授权，无新增端点。
- 前端类型初始为全部，列表入口传入当前类型；换模板、客户和时间不重置用户所选类型。预估和创建使用相同请求对象。
- 已生成任务保留原类型快照，不修改已有文件；需要包含错误记录时重新导出。

## 数据模型、配置与索引

无新表、列、迁移、索引或配置；复用 `LogExportFilter.LogType` 和已有带时间范围、客户范围的索引查询。所有查询保持超时、行数上限、游标及后台限速，不引入无界扫描。

## 边界与错误处理

缺省类型改为全部，显式消费仍只导出消费，显式错误只导出错误。创建、预估及候选值类型必须一致。非法类型使用现有 `ErrEmployeeExportInvalid` 本地化错误；不向前端返回底层错误。客户转移、停用、模板权限及下载时复核沿用已有逻辑。

## 子系统和共享资源审计

只修改管理接口参数，不修改 relay、账务计算或日志写入。沿用日志库 `logs` 限时只读查询、主库用户归属/员工/模板读取、导出专用 Redis 命名空间及既有后台文件工作流；不新增连接池、缓存、锁或工作线程。日志库与 relay 写入共享，仍依靠既有客户/时间范围索引、批量上限、CPU/扫描限速保护资源。

## 测试方案（实现前）

- 后端回归：缺省/0/消费/错误及其余有效类型；非法负数、越界、字符串、小数；内置与自定义模板；预估、任务快照、实际下载 CSV 内容一致，其他客户和时间范围外日志不混入。
- 候选值回归：仅错误中出现的模型可见；消费与错误互不混入；非法类型拒绝。
- 前端交互集成：真实导出抽屉默认全部，从列表继承错误；切换类型后预估与创建请求一致，候选查询携带类型，换模板保留类型。
- SQLite/MySQL/PostgreSQL 实例验证现有查询，前端 Vitest、typecheck、lint、构建。记录未能执行的项。
