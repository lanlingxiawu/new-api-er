## 目标与范围

## 数据流与接口

模型有效表达式 → 既有表达式解析器 → 共享计费类型分类 → 筛选与侧栏计数。任务模型优先保留独立分类；无法解析时沿用旧分类。

消费日志已存储的 `other` → 现有 JSON 解析及命中档位价格解析 → 12 小时用量/单价指标 → 本站低于上游的行提示。普通倍率价和表达式价都支持，缺失与显式零值保持区别。

导出列接口 `GET /api/log/export/columns` 按原有权限返回新增 `cache_creation_tokens_12h` 与 `cache_creation_ratio_12h`。列选择器自动消费目录；后台导出复用原有 `other` 提取器。对账和客户模板补上两列，旧默认/legacy 列顺序保持不变；已保存的自定义模板不会自动改写。

## 数据模型、配置、错误与兼容

无表、索引、迁移、查询、鉴权或配置变更。仅从已经查询的日志 JSON 读取两个现有字段，缺失输出空单元格，显式零输出 0。继续使用现有表达式无法解析回退、日志无效值忽略及导出错误处理。列名采用已有英文原文/i18next 约定并补齐七语言。
