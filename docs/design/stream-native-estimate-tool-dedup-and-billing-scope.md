# 原生 Claude 估算、工具完成去重与缓存计费范围修复

## 已确认需求、当前问题及范围

本轮按用户“按推荐修复”实施三项：原生 Claude 仍按 8 KiB 独立取整；Realtime/Responses 同一工具的两类完成事件重复估算；仅缓存用量的收费资格扩展误影响非受管请求。只修复新流式流程引入的问题，不改非流式价格、音频算法、异常结算矩阵及诊断权限。

## 数据流、推荐方案及边界

1. 原生 Claude 成功 Write/Flush 后，将有效内容候选交给已有 StreamTokenEstimator，保留词类及未取整权重，不再缓存 8 KiB 或单独估算尾部。异常无确认用量和正常缺最终输出报告的 mixed 分支共用累计值；异常已有确认用量及正常最终输出报告（含显式零）仍优先。仅起始报告不视为正常结束的最终输出用量。
2. response.function_call_arguments.done 和 response.output_item.done 按 item_id/item.id、call_id 识别同一工具。会话内只对已交付的完整合法工具计量一次，不过滤或延迟原始帧。保留最近 128 个工具的两类别名，缺失别名可后续补齐；标识以定长 SHA-256 摘要保存，避免长期保存任意长 ID。首次有效工具交付时才分配去重表；无共同标识的事件不按名称/参数猜测合并。非法或无名事件不占已计量记录。SDK 新成功响应、渠道新尝试及 Realtime 新轮次重置记录。
3. textQuotaSummary 在生成时记录是否已有 StreamResult，只有该受管终态可使用缓存专属计费资格。原生 Claude 虽停用通用会话，仍有 StreamResult；非流式、关闭开关、HTTP 非 200、没有响应则沿用 bb6317462 的普通 token/工具附加费资格。非零普通用量的缓存折扣与价格公式不变。

## API、数据模型、配置及错误处理

没有新端点、表、字段迁移、配置、依赖或对外协议变更。继续使用 stream_error_setting 和实际成功响应门控；诊断接口及 RootAuth 不变。无新增错误事件或额外结算；资金由既有结算流程执行一次。去重只影响无确认用量的估算候选，不修改原始 body 或确认用量证据。

## Main Chain Impact

同步仅包含成功交付后的增量字符扫描、工具标识哈希/有界表查询及结算摘要布尔判断。没有等满缓冲或等待下一帧；哈希仅发生在工具完成事件，不在普通文本 delta 上运行。异步日志/统计仍用现有队列，不增加任务。

## Shared Resource Audit

只新增请求会话局部去重表与局部估算器，复用现有会话短锁。模型权重共享只读配置在首次非空估算读取一次；不更改配置。新增 DB/Redis、连接池、工作池、文件句柄、跨请求锁为零；现有资金接口调用次数不变。

## Concurrency Analysis

30k/100k RPM 下每请求新增 DB/Redis 调用和 goroutine 均为零。估算为 O(交付字符数) 时间、O(1) 状态，且移除 8 KiB 文本缓冲。去重至多 128 项/256 个固定长别名；仅有工具的请求分配，有界内存不随会话时长增长。哈希耗时为 O(ID 字节数)，受既有帧大小限制；会话锁不跨 I/O。

## 风险、可选项及验证

- 估算仍为近似值，仅保证完整字符边界分片不改变结果；不引入官方 tokenizer。
- 最近 128 个工具之外的旧完成事件不保证去重，避免无界连接状态；缺少共同 ID 不推测相同调用。
- 测试 8191/8192/8193/16385 边界、中英文分片、异常 estimated/正常 mixed/确认零；工具两类事件正反序、重复、别名补齐、无名/非法后有效、不同 ID 相同内容、容量淘汰/重试/轮次清零；缓存只读/创建/分时字段及旧路径隔离。
- 使用本地 SSE/WS 与内存费用夹具，不调用供应商或修改实际资金。相关 Go 测试、根构建、gofmt 与差异检查；生产负载和竞态验证单独注明实际执行情况。
