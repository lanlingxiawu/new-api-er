# 价格巡检与真伪检测页面排版统一设计

## 目标和范围

本次统一“价格巡检”和“真伪检测”两个管理员功能页的页面骨架、标题操作区、内容间距、设置弹窗和结果工具栏密度，解决价格巡检设置弹窗留白过多、字段左右失衡，以及“立即巡检”被藏在设置弹窗内的问题。

本次不修改价格巡检算法、真伪判定规则、批量检测范围、手动检测能力、定时任务、权限资源、接口路径、查询参数或存储结构。

## 统一排版规范

两个页面继续复用 `SectionPageLayout`，并采用以下共同规范：

- 标题栏只承载页面级操作；次要操作使用描边按钮，当前页面的全局主要操作使用主按钮并放在最右侧。
- 主内容区统一使用紧凑的三级结构：摘要或页签、筛选与操作工具栏、结果表格；区块间距统一为 12 像素级别，不再混用大段 24 像素留白。
- 筛选区使用相同的圆角、边框、字段标签密度和响应式断点；窄屏按单列排列，宽屏按业务字段宽度展开。
- 结果数量、自动刷新、重置、清理、刷新、下载等辅助操作统一靠工具栏右侧排列，换行时保持原有相对顺序。
- 多选下拉统一使用“清晰勾选标识 + 轻量背景 + 细边界”的选中态，不再使用大面积连续高亮色块；悬停、键盘聚焦和已选中状态必须能够独立辨认。
- 表格继续保留各自业务需要的列宽、粘性列和横向滚动，不为了外观一致牺牲数据可读性。
- 加载、错误、空结果和禁用原因继续使用现有组件与文案，不改变用户反馈语义。

## 价格巡检页面调整

### 标题操作区

标题栏操作按“分享页面 → 巡检设置 → 立即巡检”排列：

- “分享页面”和“巡检设置”为描边按钮。
- “立即巡检”为页面级主按钮，从设置弹窗移出并放在最右侧。
- “立即巡检”继续遵守 `edit` 权限、主节点限制、已有任务运行状态和提交中状态；运行时显示现有“正在巡检”文案。
- 点击“立即巡检”仍直接沿用现有异步启动与轮询流程，不依赖设置弹窗是否打开，也不自动保存未提交设置。

### 设置弹窗

设置弹窗底部只保留“取消”和“保存设置”，并重新排列字段：

1. 第一行放置“启用价格巡检”和“包含 models.dev 价格”两个同尺寸开关卡片。
2. 第二行放置“巡检间隔”和“来源超时”两个数字输入框。
3. 官方价格始终作为必选对比来源，不在设置弹窗中重复展示只读说明，避免占用空间。
4. “免检模型白名单”及说明占满整行。
5. 弹窗内容高度改为随内容自适应，仅保留视口最大高度与内部滚动，消除截图中的大面积空白。

仅有查看权限时，设置弹窗仍可打开查看，所有设置控件和保存按钮保持禁用；关闭弹窗继续丢弃未保存修改。

### 结果区域

- 保留四项摘要统计，但压缩其与筛选区之间的垂直间距。
- 筛选工具栏、差异类型切换、计价单位说明和结果表格使用与真伪检测结果页一致的边框与紧凑间距。
- 分页条继续位于表格下方，不修改分页接口和每页数量。

### 渠道多选样式

“显示来源”弹层按以下方式优化：

- 每个渠道使用独立的规则圆角行，相邻选项保留 6 像素纵向间距，不再让选中行连成大面积蓝色块。
- 已选中行使用低强度主题背景和细边界，勾选框作为主要状态标识；渠道名称与地址保持正常文本层级，不整体变成强调色。
- 未选中行保持透明背景，悬停时只出现轻量底色；键盘聚焦显示明确焦点环。
- “全选渠道”“清空渠道”、已选数量和“应用”按钮维持固定的头部与底部区域，列表滚动不影响操作入口。
- 选中状态只在点击“应用”后写入实际筛选；关闭弹层继续放弃草稿，保持当前交互语义。

## 真伪检测页面调整

- 标题、标题操作按钮、页签与内容之间的间距与价格巡检统一。
- “检测设置”保持标题栏描边按钮；批量检测和手动检测的执行按钮继续留在对应页签内，因为它们依赖当前选择或临时表单，不提升为全局动作。
- 检测结果页继续按“筛选 → 统计 → 辅助操作 → 表格”排列，统一与价格巡检相同的工具栏圆角、边框和纵向密度。
- “结果”多选筛选使用与价格巡检渠道选择相同的轻量选中语义：勾选标识承担主要反馈，背景仅作辅助，不以整块高饱和填充区分状态。
- 批量检测页继续按“任务状态工具栏 → 渠道目标表格 → 选择操作”排列；手动检测页继续在表单顶部显示执行按钮。
- 检测设置弹窗沿用与价格巡检相同的两列字段网格、开关卡片和页脚按钮规范；由于字段较多，保留受视口限制的滚动内容区。

## 数据流

### 价格巡检立即执行

1. 用户在标题栏点击“立即巡检”。
2. 前端按现有条件判断权限、主节点、运行状态和提交状态。
3. 前端调用现有 `POST /api/price_monitor/run`。
4. 成功后展示现有提示并轮询状态，完成后刷新摘要与结果；失败时展示现有可重试提示。

### 设置保存与结果查询

两个页面继续使用现有 React Query 查询和 Mutation。弹窗重排只改变组件组合，不增加请求，不改变保存载荷，也不把用户交互建模为新的副作用监听。

## API 契约

本次不新增或修改 API。继续使用：

- 价格巡检：`GET /api/price_monitor/status`、`GET /api/price_monitor/results`、`PUT /api/price_monitor/settings`、`POST /api/price_monitor/run`。
- 真伪检测：现有 `/api/channel/veridrop/*` 查询、设置、检测和清理接口。
- 权限仍分别使用 `admin_menu.price_monitor:view/edit` 与 `admin_menu.veridrop_detection` 及既有渠道操作权限。

## 数据模型、配置与迁移

不新增表、字段、索引、配置项或迁移。价格巡检继续使用 `price_monitor_setting`，真伪检测继续使用 `veridrop_monitor_setting`。

## 关键边界和错误处理

- 非主节点、无编辑权限、任务已运行或请求提交中时，“立即巡检”不可点击。
- 设置弹窗内存在未保存修改时，关闭或取消应恢复服务端最近一次配置；点击标题栏“立即巡检”不会使用或保存这些草稿。
- 设置保存仍执行现有二次确认；保存失败时弹窗保持打开，方便用户修正或重试。
- 查询失败、检测启动失败、清理失败和下载失败继续使用现有用户可理解提示，不暴露内部错误。
- 移动端标题按钮允许换行，设置弹窗字段退化为单列，页脚按钮保持可触达。

## 与现有子系统的关系

- 授权：资源和策略不变，只移动前端按钮位置。
- 后台任务：调度、冷却、批次和轮询不变。
- 分享页面：地址、密码和公开查询契约不变。
- 国际化：优先复用现有文案；如实现中产生新文案，按七语言脚本流程补齐。
- AI 转发链路：不接入、不修改。

AI 转发请求协程不执行任何新增代码。本次只有管理端 React 组件布局变化，每个 relay 请求新增的数据库查询、Redis 操作、锁和 goroutine 数量均为 0。

## Shared Resource Audit

不新增或修改 Redis 键、数据库表、内存缓存、连接池、goroutine 池或文件句柄。两个管理页面继续读取原有管理接口；AI 转发链路不会访问新增资源，因为本次没有新增资源。
