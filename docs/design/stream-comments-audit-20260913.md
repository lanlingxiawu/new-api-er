## 首次审计复现的问题（后续状态见各项说明）

### A1：多候选流的单个候选结束帧被整帧过滤

- 位置：`relay/common/stream_writer.go` 的 `Write`，以及 `IsStreamSuccessEvent`。
- 触发：OpenAI 兼容 `n > 1`，两个候选均已出现，其中一个先带 `finish_reason` 结束，其他候选仍在生成。
- 实际：全局 Complete 尚为 false，过滤器把该候选的结束帧整体丢弃；同帧的最后一段正文/工具内容也一起丢失，后面不重发。
- 本地复现：先发送候选 0/1 起始内容，再发送候选 0 的 `LOST_LAST_TEXT + finish_reason`，最后结束候选 1；下游缺少 `LOST_LAST_TEXT` 和候选 0 结束帧。
- 建议：区分逐候选合法结束与整条响应终止；不要因其他候选未完成而丢弃该候选内容。增加多候选交错及尾段正文夹具。优先级 P1。
- 后续状态：用户于 2026-09-13 确认单独修复 A1，已区分候选/响应结束粒度；实现及验证见 [多候选尾帧修复](stream-candidate-end-forwarding.md)。本节以上保留首次审计时的复现记录，A2 的后续状态见下一项。

### A2：Realtime 轮次之间的异常断链未补发 error

- 位置：`relay/channel/openai/managed_realtime.go` 的 `managedRealtimeHandler`，`if active || a.last == nil` 终止分支。
- 触发：至少一轮正常 `response.done` 后，还没有下一轮活动，上游异常断开。
- 实际：`active=false` 且已有 `a.last`，跳过 `finishRound/FinalizeStreamUsage`；最终日志记 Failed 与 DiagnosticAvailable，但下游只被关闭，没有补发 error。
- 本地真实 WS 复现：上游先发正常 `response.done`，随后不发关闭帧直接关闭；结果 `failed=true diagnostic=true error_event=false`。
- 建议：轮间异常也执行只补发终止错误的处理，不重复计量或退款已完成轮次。优先级 P2。
- 后续状态：用户于 2026-09-13 确认修复 A2，已增加轮间只补错误分支，保持完成轮次账本和原计费入口；验证覆盖异常断链、正常关闭、取消、受管超时与错误去重，见 [Realtime 轮间终止修复](realtime-interround-terminal-error.md)。
