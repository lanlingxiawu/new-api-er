# 导出历史筛选组件修正

2026-10-27。依据用户对重复创建者字段和下拉组件的明确修正要求，调整现有筛选交互。

## 范围、数据流与契约

- 管理员的创建者账号与创建者 ID 合并为一个可搜索的“创建者”选择器，候选展示账号、名称和 ID，只提交 `creator_id`；更换或清除时移除旧 `creator_keyword`，避免同一用户两个条件互相冲突。
- 复用 ExportFilterSelect / ComboboxInput 以及现有 `/api/log/export/options?field=customer` 用户候选接口。增加数字关键词按用户 ID 匹配，保持账号/名称搜索和游标分页。员工接口继续按所属客户约束，普通用户不请求管理用户候选。
- 状态、范围、来源、模式改用项目 Base UI Select，保留字段值与现有接口契约。
- 任务 ID 复用 ComboboxInput，提供当前筛选结果已加载的任务候选及继续加载入口，支持粘贴完整 ID；复用原列表数据，不额外枚举任务，不扩大权限。
- 管理员、员工、普通用户角色可见字段保持既有边界。所有操作经搜索按钮应用，重置清空全部条件。

## 生命周期、错误和资源

无新接口、表、迁移、配置或任务存储变更。用户候选仅在原认证/授权路由上查询 `users`，使用现有上下文、连接池、最多 51 行和主键游标。数字关键词新增主键等值匹配，保留已有名称搜索；不写用户表、不加锁、不改 relay 路径或 Redis。任务候选直接使用原列表缓存及分页，无额外连接或后台工作。候选加载、空结果、失败与重试复用现有组件。

已选创建者不在首批候选时，按其 ID 补查一次显示名称，使用带用户身份的 TanStack Query 缓存与 30 秒 staleTime；失败显示现有内联重试入口。这样应用筛选并重新挂载表单后仍显示账号，而非只显示数字。

- 真实组件点击下拉选择、搜索、清除、重置、继续加载；断言无原生 select，无重复创建者字段。
- 创建者候选展示账号和 ID，提交只有 ID；任务选择和粘贴均提交正确 job_id。
- 三种角色只显示授权字段；员工用户候选的数字查询不能跨越所属客户范围。
- SQLite、MySQL、PostgreSQL 验证用户候选新增数字查询；前端模块回归、typecheck、lint、构建。
