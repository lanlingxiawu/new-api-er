# 模型价格巡检：价格可用状态优化设计

状态：已实现并部署至测试服务器验证。

## 1. 目标与范围

修正当前把多种情况统一显示为“该价格来源未提供此模型”的问题，区分以下状态：

1. 官方预设没有收录该模型。
2. 来源只提供输入价格，例如嵌入模型没有输出倍率。
3. 价格来源本次抓取失败。
4. 渠道没有启用该模型，因此不参与比较。
5. 来源返回占位价格，数据不可信且不参与比较。

不在本次范围内：根据相似名称自动匹配模型别名、从厂商官网抓取新的价格体系、自动修改平台价格。

## 2. 价格单元数据结构

保留现有 `unavailable_reason`，扩充为明确的机器状态：

```text
missing          来源响应中没有该模型的任何可用价格
source_failed    本次来源抓取失败
placeholder      来源返回占位价格，不参与比较
```

渠道未启用模型仍不生成价格单元，由表头类型为 `channel` 且当前行没有该来源单元共同表达 `not_applicable`，不写入差异，也不增加快照体积。

对于只提供输入价格的来源，价格单元仍为 `mode=per_token`：

```json
{
  "mode": "per_token",
  "input": 0.13,
  "output": null,
  "output_available": false
}
```

实现中可直接使用 `output` 缺省表达不可用，不新增冗余布尔字段；前端根据 `output == null` 显示“仅提供输入价格”。

## 3. 解析和比较规则

- 有 `billing_mode=tiered_expr` 且存在表达式：按现有阶梯/动态表达式逻辑处理。
- 有 `model_price`：按固定每次价格处理。
- 有 `model_ratio`：至少可以计算输入价格，生成 Token 价格单元。
  - 同时有 `completion_ratio`：计算输出价格。
  - 没有 `completion_ratio`：保留输入价格，输出缺省；不再把整个模型判为未提供。
- 没有表达式、固定价格和 `model_ratio`：判为 `missing`。

字段差异采用空值安全比较：

- 两侧都没有输出价格：输出一致，不高亮。
- 一侧有输出、另一侧没有：输出不一致，缺失一侧显示“未提供输出价格”。
- 两侧都有输出：按现有浮点容差比较。
- 输入价格采用同一规则，不把两个空值误判为差异。

官方来源的 `missing` 文案为“官方价格预设未收录此模型”，明确只代表当前 BaseLLM 预设缺失，不代表厂商官网一定没有价格。渠道来源的 `missing` 文案为“该渠道价格接口未提供此模型”。

## 4. 页面展示

后台矩阵和公开分享页使用一致状态文案：

| 场景 | 展示文案 | 是否计入价格差异 |
|---|---|---|
| 官方预设缺失 | 官方价格预设未收录此模型 | 是 |
| 渠道接口缺失 | 该渠道价格接口未提供此模型 | 是，仅该渠道启用了该模型时 |
| 仅输入价格 | 展示输入价格；输出位置显示“仅提供输入价格” | 按双方输出是否同时缺失决定 |
| 来源抓取失败 | 价格来源检查失败，请等待下次巡检 | 否，属于运行状态异常 |
| 渠道未启用 | 该渠道未启用此模型，不参与对比 | 否 |
| 占位价格 | 来源返回占位价格，未参与对比 | 否 |

Token 单位继续只在表格顶部说明一次。缺失说明使用次要文字，只有真正构成差异的缺失项使用错误色。

## 5. API 与存储

不新增接口、表或文件。`/results`、`public_query` 使用现有价格矩阵结构，字段级兼容接口 `/inconsistencies` 不变。

矩阵快照版本递增，部署后主节点自动重新巡检，避免旧快照继续使用原来的模糊状态。

## 6. 错误处理与主链路影响

来源失败继续保留在表头并显示失败状态；全部来源失败时继续保留旧快照。所有逻辑只在后台巡检、管理查询和公开分享页面执行，不进入 AI 中继主链路，不新增数据库、Redis或连接池资源。

## 7. 测试计划

- `model_ratio` 存在、`completion_ratio` 缺失时生成仅输入价格单元。
- 双方输出都缺失时不产生输出差异。
- 只有一方缺失输出时产生输出差异。
- 完全不存在模型时仍为 `missing` 并计入差异。
- 官方、渠道、来源失败、未启用、占位价格在后台与分享页显示不同文案。
- 现有固定价格、阶梯表达式、缓存/图片/音频价格测试保持通过。
- 前端类型检查、目标文件 lint、生产构建及 `go test ./...` 全部通过后重新部署测试服务器。

## 8. 实现记录

- `priceMonitorCell` 在只有 `model_ratio` 时生成仅输入价格单元；`completion_ratio` 缺失不再导致整个来源被标记为缺价。
- 输入、输出差异改为空值安全比较：两侧都缺失视为一致，仅一侧缺失才视为差异。
- 后台矩阵根据来源类型分别显示官方预设缺失、渠道接口缺失、来源失败、渠道未启用和占位价格。
- 公开分享页已同步重写为清晰中文状态，并保留模型一行、来源一列、横向滚动与动态密码访问。
- 后台管理页仅允许价格对比表格横向滚动；巡检设置、统计摘要和分享信息固定在内容区宽度内，不随表格横向移动。
- 设置页外层 `fieldset` 和内容滚动容器显式使用 `min-width: 0`，避免浏览器对 `fieldset` 的最小内容宽度规则把整页撑宽；回归检查需确认页面级 `scrollWidth == clientWidth`，而价格表容器在来源较多时保持 `scrollWidth > clientWidth`。
- 后台矩阵与公开分享页只显示具体价格和差异高亮，不再显示相对平台价格的百分比。

## 9. API 地址表头与分享表格优化（已实现并部署验证）

### 9.1 表头数据

`PriceMonitorSourceHeader` 新增 `api_url` 字段。渠道来源保留内部 `name` 用于识别和筛选，但后台与分享页的渠道列表头改为：

- 主标题：渠道 API 基础地址；
- 副标题：仅显示渠道名称，不重复展示渠道模型范围说明；
- 平台列仍显示“平台配置”，官方列仍显示“官方价格”，避免把官方预设文件误称为渠道 API。

API 地址写入快照前进行安全清洗：保留协议、主机、端口和路径，移除 URL 用户信息、查询参数和锚点，防止意外展示凭据。相同 API 地址的多个渠道依靠副标题中的渠道名称区分。矩阵版本递增，部署后重新生成快照。

### 9.2 查询与筛选

现有 `source` 参数同时匹配来源类型、渠道名称和清洗后的 API 地址。后台来源筛选增加按具体 API 地址选择；公开分享页增加“来源筛选”，便于只查看一个渠道，官方价格列始终保留。

### 9.3 分享页表格布局

- 保留“一行一个模型、一列一个来源”的矩阵结构；
- 模型列与平台配置列保持左侧固定；
- 表格上方增加左右移动按钮，用户无需滚动到页面底部即可横向浏览来源；
- 渠道列宽收紧并允许 API 地址换行，避免长地址撑宽列；
- 无数据状态改为紧凑标签：“未启用”“未收录”“检查失败”“占位价格”，完整解释通过单元格辅助说明和 `title` 提示保留；
- 公开页仍使用页面纵向滚动，不增加表格内部纵向滚动条；
- 服务端继续按当前页裁剪完全无关的渠道列，官方列无条件保留。

### 9.4 API 兼容与测试

`source_headers` 仅新增可选字段 `api_url`，现有调用方保持兼容。测试覆盖：URL 凭据清洗、重复 API 地址、来源按地址筛选、官方列强制保留、当前页无关渠道裁剪、公开页紧凑状态和横向移动控件、后台类型检查与生产构建。该变更仍只作用于后台巡检和查询，不进入 AI 中继主链路。
- 矩阵快照版本升级为 7，部署后会触发新快照。
