# 渠道禁止探针：流式范围选择

日期：2026-10-12
状态：用户已确认并授权实施；实现及专项验证完成，完整测试受现有数据库环境限制（见末节）。

## 目标与范围

在渠道编辑 → 高级设置 → 路由策略的“禁止探针请求”开关下增加范围选择：全部、非流、流。保留关闭功能的能力，默认全部，兼容原有配置。范围只决定哪些疑似探针需要跳过该渠道，不禁止普通请求，不改变既有探针识别长度和结构规则。

沿用 [渠道探针分流设计](channel-probe-routing.md)。现有实现以 `disable_probe_requests` 布尔值生成禁止渠道集合，本设计在该逻辑上增加请求方式维度。

## 交互和生命周期

- 关闭开关：不禁止任何探针，隐藏范围选择；保留已选范围供再次开启使用。
- 开启开关：显示选择器，选项依次为“全部”“非流”“流”。
- 全部：禁止流式和非流式探针；非流：只禁止非流式探针；流：只禁止流式探针。
- 新建默认关闭、范围全部；旧配置已开启但没有范围时按全部处理。
- 编辑回显、保存、复制均保留范围；沿用敏感设置权限及路由策略已配置标记。
- 复用同区域表单和选择器样式，支持七语言及暗色主题；保存失败保留输入并沿用现有反馈。
- 管理保存刷新本节点策略，其他节点沿用原 60 秒后台刷新；请求持有入场快照，修改只影响新请求。

## API contracts、数据模型与配置

沿用 `GET /api/channel/:id`、`PUT /api/channel/` 及既有新增/复制接口。管理接口保持 AdminAuth、渠道读写及敏感设置权限，无新增端点或权限放宽。

在已有 `channels.settings` JSON 文本中增加 `probe_request_mode`，允许 `all`、`non_stream`、`stream`。`disable_probe_requests` 继续作为功能开关。`relaykit/dto.ChannelOtherSettings` 同步增加纯配置字段，保持模块独立。

更新请求片段（实际客户端合并其他 settings）：

```json
{"id":442,"settings":"{\"disable_probe_requests\":true,\"probe_request_mode\":\"non_stream\"}"}
```

响应沿用渠道对象，其 `settings` 字符串包含上述字段。管理保存成功/失败沿用既有响应结构。

缺失或空范围兼容为全部。更新未提供范围时保留原值，未提供开关时保留原开关；显式 false 可关闭。新提交的非法类型或未知范围拒绝保存。创建和更新一致校验，复制保留字段。后台刷新遇到无法解码的历史配置，或已开启渠道的未知范围，记录内部错误并保留上一有效快照；关闭渠道不使用其范围。沿用 180 秒过期后的普通选路降级。

无新增表、列、迁移、索引或全局配置；渠道级配置继续使用现有渠道 settings，不引入环境变量。没有新增需经 setting/ 注册的系统参数。文本 JSON 与 GORM 查询兼容 SQLite、MySQL 和 PostgreSQL。

## 数据流与业务逻辑

管理表单 → 渠道 API 校验并保留未提交字段 → channels.settings → 管理/后台发布不可变策略快照 → 请求分类时确定客户端流式方式 → 选择对应禁止渠道集合 → 原候选过滤/绑定检查 → 真实上游调用及计费。

后台快照生成流式、非流式两组禁止渠道：all 进入两组，其他范围只进入对应组。请求只选择一次集合，后续过滤可保留现有 `Blocks(id)` 语义，避免在每个候选上重复解析配置。

客户端 JSON 顶层 `stream: true` 为流式，false 或省略为非流式；沿用现有受限正文分类扫描读取该值，不增加网络、磁盘或重复 DTO 序列化。非法 stream 类型不得被探针逻辑改写为另一种有效请求，交由既有校验处理。采用客户端原始请求方式，上游协议转换或强制流式不改变范围判定。

对应方式没有任何禁止渠道时，直接沿用普通路由，不创建探针路由上下文，不改变亲和性与 auto 分组行为。存在禁止渠道且满足原探针规则时，沿用原同组过滤、优先级/权重和重试固定分组行为。指定渠道仅在其范围匹配时返回既有 403；同组全部候选被匹配规则排除时返回既有 503。

不改变三种已支持入口、平台测试豁免、正文 16 KiB 上限、长度阈值、真实调用计费、日志可见性或自动封禁规则。匹配判断在首次选路及重试中一致。

## 错误处理与子系统交互

管理端校验错误复用适用的已有 i18n 错误；如需新文案，按仓库实际后端语言文件补齐翻译，并通过 ApiErrorI18n 返回。底层故障记录内部日志，不向客户端暴露 Go 错误。Relay 继续使用原探针错误路径，不使用管理 API 错误格式。

策略后台刷新失败保留旧快照，超时、过期和 panic 沿用已有隔离；不增加同步写日志或新的每请求事件。仅最终实际调用渠道参与既有预扣、结算和日志，被跳过的渠道不调用、不计费、不记失败。

## Main Chain Impact

同步执行：读取原子快照，在原有受限分类中取得 stream 标记，选择流式/非流式集合，按原候选遍历查询集合。不开启功能时跳过识别；渠道开关仍是可立即关闭该策略的配置入口。

异步/后台执行：配置加载、JSON 解析、集合构造及原子发布，沿用已有单刷新任务、60 秒周期和 3 秒 DB 超时。主链新增 DB、Redis、网络、磁盘调用和 goroutine 均为 0；不新增等待、锁或后台任务。

## Concurrency Analysis

30k RPM 为 500 RPS，100k RPM 约 1667 RPS。相较原实现，每请求新增 DB/Redis 调用、goroutine、锁均为 0；增加一次方式选择及原受限扫描中的标量读取，候选过滤仍为 O(C)。后台快照内存保持 O(渠道数)，不随 RPM 增长；不得逐请求创建集合或重读 settings。

复跑既有分类和选路 benchmark，比较分配和延迟，目标保持 happy path 亚毫秒开销；本地微基准不等同线上 100k RPM 压测。无增长表或新增大表查询，无新增索引与 EXPLAIN 要求。

## 实际实现与验证

- 后端保留原 Classify API，新增 ClassifyWithStream 在同次顶层遍历中返回客户端 stream；重复或非布尔 stream 不进入探针策略，留给既有请求处理。
- ChannelProbePolicy 根对象保存非流式集合，streaming 子对象保存流式集合；ForStream 返回现有对象或 nil，不分配、不复制集合。后台构造两组集合，原子发布；请求先固定快照再选择范围。

## 真实 MySQL 压测（2026-10-12）

用户要求压测禁止 SQLite，随后指定使用当前仓库 `.env.example` 中的基本配置。本轮直接读取该文件的 SQL_DSN，连接本机 MySQL；没有复制、输出或保存凭据。

初次连接返回 MySQL 1049：配置中的 `newapi` 数据库不存在。确认不存在后创建该数据库，仅初始化当前版本的 channels/abilities 表供压测使用，没有修改其他数据库。新建的数据库及两张空表保留，压测渠道和能力行按 ID 清理。压测工具自身不迁移 schema，也没有 SQLite 回退。

工具：[bench/proberouting](../../bench/proberouting/README.md)。运行真实分发中间件、HTTP 请求解析、探针分类、缓存选路以及本地 TCP 模拟上游，覆盖三个受支持入口；不包含鉴权、计费、真实供应商适配器或 Redis，不能据此宣称完整生产网关容量。

每档每种设置 30 秒，64 个有界 worker；流式/非流式各 50%，短探针 75%，长普通输入 25%，同组两个不同优先级渠道。测试中每 10 秒从 MySQL 刷新一次不可变策略，比正式默认 60 秒更频繁；连接池上限 4。策略关闭、全部、非流、流依次比较。Windows 延迟采用 QueryPerformanceCounter；预检发现原 time.Since 在本机亚毫秒请求上会量化为零，已更换计时方式后才运行正式压力轮次。

执行命令：

```powershell
go build -o tmp/probe-routing-load.exe ./bench/proberouting
./tmp/probe-routing-load.exe -env-file .env.example -duration 30s -report tmp/probe-load-mysql-20261012.json
```
