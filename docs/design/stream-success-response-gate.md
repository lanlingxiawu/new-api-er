# 成功响应后启用新流式流程

2026-09-13 用户确认实施。本文覆盖之前文档把连接失败和非成功 HTTP 响应纳入新诊断/异常结算的规则。

## 目标与范围

入口是流式且既有开关开启时，只预备请求局部观察状态；真正收到上游 HTTP 200 后才启用协议观察、异常补发、异常计费及诊断。已知非 200（包括 201/204），以及 DNS/TLS/连接失败、响应头之前超时等未收到 HTTP 响应的情况均回到原流程。WebSocket 仅实际成功握手 101 才启用，失败握手走原流程。

非流式、HTTP 200 后的协议错误/读取失败/超时/客户端断开计费合同不变。普通旧错误日志、状态码映射、渠道重试及旧退款规则保留；不恢复请求头/body 或下游请求头采集。独立 `reject_reason` 保持已确认逻辑。

## 数据流与关键逻辑

请求 → BeginStreamAttempt 创建待激活门控 → HTTP/SDK/WS 实际交换返回原状态（状态码映射前）→ 成功时打开门控并接入响应采集/协议观察 → 原渠道解析转发 → 原有新流程终止与结算。

未成功时门控保持关闭：采集器不包装错误响应/保存错误正文，下游观察器透明转交、不保留正文；通用会话不接管终止，Claude 无响应分支不调用严格流式终止器；控制器继续旧错误响应、重试与退款。禁止在最后一次失败的 defer 中重新接入新结算。

门控只属于一次渠道尝试，使用原子状态在 SDK/流式工作者间读取，禁止修改请求级冻结配置。SDK 内部后续 200 可以重新激活，之前非 200 的 body/header 不进入 previous_responses；最终失败关闭门控，不保存前次成功交换的私有证据。新渠道尝试重新创建门控。Realtime 同一连接的后续轮次继承已成功的握手资格。

实现中 `StreamResponseGate` 由 RelayInfo / StreamSession / StreamResponseCapture 共用，指针在发布前固定。成功的后续 SDK 交换清空旧协议终态、用量和交付状态，保留原始成功响应的有界历史；最终失败时日志出口再次检查门控。nil 门控仅兼容既有非流式采集和独立协议组件，正式新流式入口总是绑定待激活门控。

只有真实 HTTP 客户端或 WS 拨号结果能开门；适配器构造的占位 HTTP 200 不作为成功证据。

## API contracts、模型与配置

无新接口、表、列、索引或配置。Root 诊断接口、历史日志读取和前端按钮合同不变。

门控未开放时不写 `stream_diagnostic`、`stream_diagnostic_attempt`、`stream_diagnostic_available`、`stream_result`；因此无新诊断按钮。实际入库依旧使用原异步日志队列。开启后沿用响应头 16 KiB、body 首尾各 1 KiB、下游单字段 base64 合同。

## 错误处理与既有子系统

错误响应和状态码映射交回旧处理器；只过滤新诊断，不隐藏旧普通错误日志。SDK 解码错误仅在已确认 HTTP 200 后属于新流程；SDK 请求编码、拨号和非 200 失败不因包装成通用错误而进入新结算。门控不会读取/关闭/消费错误 body，不干扰旧错误处理器或 SDK 的读取和重试。

## Main Chain Impact

同步仅增加请求局部门控的一次原子写和常数次原子读，复用已有字节上限与观察器。无新 DB/Redis/网络调用、goroutine、定时器或跨网络锁。持久化沿用异步队列，门控失败路径减少诊断采集和序列化。

## Shared Resource Audit

门控只在本次尝试的 info/session/capture 共享，不进入全局 map，不修改共享 HTTP 客户端、SDK 池、Redis 命名空间或数据库结构。logs 表、日志工作队列与原资金结算入口保持原有使用方式，无新增连接/队列/资金锁。

## Concurrency Analysis

30k/100k RPM（约 500/1667 请求每秒）新增 DB/Redis 调用及后台工作者均为 0；每个活跃尝试增加常数大小门控，无 body 时不分配下游正文缓冲。SDK 状态切换不访问 Gin、不修改正在读写的共享配置；流水线异步读取门控不跨 I/O 持锁。失败请求不新增日志诊断负载。

## 实施顺序与测试

先写门控/HTTP 保真/日志隔离/原退款分支回归，再实现入口与 SDK/WS 接入。覆盖 HTTP 200/201/204/3xx/401/429/5xx，无响应连接错误、请求头阶段超时、200 后读取超时，SDK 与渠道重试的失败→成功及成功→失败，真实 WS 101 与握手失败、占位 200、Claude 原生连接失败、透传请求、采集关闭、非流式隔离、原始 error body 未被提前读取/替换、无新补发/异常计费/诊断。

只使用本地 HTTP/WS 夹具，不请求真实 AI。运行相关 Go 包测试及根构建，保留既有 200 后的异常计费和诊断回归。标准 DB 初始化依赖未就绪时用仓库外 overlay 与已有 SQLite 回退夹具区分验证范围。未新增前端文案或依赖。
