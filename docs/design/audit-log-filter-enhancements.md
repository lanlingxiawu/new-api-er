## 启动路径局部优化（2026-11-17）

用户在确认初始化超时、迁移职责分离的优化方向后要求“先进行代码优化”。本轮只处理这两项，不改表定义、索引、员工快照语义或列表分页合同。

### Existing Logic and Related-Path Findings

`main.go` 在 HTTP 监听前依次初始化审计查询池、导出池。查询池初始化隐含调用 `MigrateAuditSecurity`，而 `service/auditsecurity/worker.go:initialize` 又在每个 worker 首次连接时执行同一迁移；查询池与 worker 都没有沿用主库启动的 master-only 迁移边界。关闭检测时历史告警查询和删除仍使用 `model.AuditReadDB(false)`，因此不能通过停用查询池来跳过迁移。

`openAuditSecurityDB` 的 MySQL 初始化包含驱动版本查询；导出池的读取超时为零，且该查询使用驱动自己的 Background context。本地无响应握手已复现无限等待风险。`OpenDataCleanupDB` 已有临时为初始化查询绑定 context、随后恢复原始连接池的模式；本轮按此模式保留审计驱动的版本识别，不跳过 MySQL 版本能力判断。导出任务本身继续使用任务 context，不把初始化的短截止时间留在正常查询上。

### 实现范围与生命周期

- 审计连接构造和两类池初始化显式接收 context；每组池初始化总预算 3 秒，涵盖版本探测、连接验证和重试。预先取消不建连；失败关闭本次已打开的连接，完整成功后才发布池。失败由原启动调用方记录，不中止整个服务。
- `MigrateAuditSecurity` 只由已有 master 主库迁移流程调用，预算 15 秒；安全监控 schema 初始化失败记录错误，不把辅助功能变成主服务启动失败条件。查询池与 worker 不再执行 DDL，worker 正常读写失败仍沿用既有错误报告。副节点依赖 master 完成 schema 部署，与主库其他表一致。
- HTTP API、权限、设置和表结构均不变；不新增重试线程、迁移状态表、缓存或配置项。正常独立池容量、关闭流程及导出查询时限保留。

### Main Chain Impact / Shared Resource Audit

变更只发生于启动和监控 worker 连接初始化。主库迁移池在 HTTP 监听前使用，审计查询、导出及 worker 继续使用各自连接池；不新增连接池，不改 DB/LOG_DB 方言标记、Redis namespace、员工缓存或 AI relay 的同步路径。30k/100k RPM 下，每个 relay 请求新增 SQL、Redis、锁和 goroutine 均为零；这是调用链核对，不是负载实测。

### 实施与验证结果

已完成显式 context、初始化版本探测绑定、连接验证、失败释放和迁移入口集中；`MigrateAuditSecurity` 的生产调用只保留在 `model/main.go:migrateDB`。表定义与原有索引兼容修复未改动。

正文恢复均为 `incomplete=false`，各次均无 DDL且登录/审计读取成功。第二次启动已有恢复检查点；大档首次恢复还按默认最大 5,000、清理后保留 1,000 的规则收敛，因此 **1.801 秒不表示再次完整解析了 19.7 GB 正文**。无检查点时仍需扫描原始正文，数据库使用日志量与这段文件恢复成本是两个不同因素。

测试准备纠偏：渠道数量收敛后，修正夹具的能力唯一键与单用户唯一档案基数；MySQL dump 恢复后仅把相同 utf8mb4/排序规则的显式字符集标记归一化再比较 schema。第一组 MySQL DDL 采集遗漏 prepared Execute，PostgreSQL 的语句与耗时分行也最初漏配对，均已修正记录器；原始启动时间有效，但第一组 MySQL DDL 数量不可用。大档位旧日志索引准备切换为并行，主动取消的顺序及中间分组构建是夹具准备行为，不是应用启动失败。造数阶段临时调整的 CPU、内存、WAL、检查点、autovacuum、索引 worker 与 `full_page_writes` 均在正式计时前恢复并断言原值。

### 角色及员工身份

保留不可变的 `actor_role`，新增可空的 `actor_is_employee`，仅对普通角色用于区分员工与普通用户：

| 条件 | 显示 / 筛选值 |
| --- | --- |
| actor_role=100 | 超级管理员 / `root` |
| actor_role=10 | 管理员 / `admin` |
| actor_role=1 且 actor_is_employee=true | 员工 / `employee` |
| actor_role=1 且 actor_is_employee=false | 普通用户 / `user` |

| 其他 actor_role | 未知身份 / `unknown`，仅 Root 可见 |

普通角色的新日志在管理/认证审计采集时，按已验证操作者 ID 查询当时启用的员工档案，保存布尔快照；之后员工离职、禁用、用户升降权不修改历史记录。管理员即使有员工档案仍显示管理员。

后台安全采集已有可信快照时沿用；没有快照的队列事件保留 NULL，不在稍后消费时根据新身份补写成事发时事实。禁止为此给 AI 转发路由增加查询。

**历史数据限制：** 已有 Root/管理员记录可直接按 `actor_role` 筛选；已有普通角色记录无法可靠区分当时是否员工，因此进入“普通账号（员工身份未记录）”。不按当前员工名单回填历史，也不通过日志正文猜测。员工/普通用户的精确区分从新快照记录开始生效；页面应有简短说明。

### 操作来源

- `session` → “网页登录”，指网页登录身份；不保证请求一定来自真实浏览器，脚本也可能使用同一类登录凭据。
- `access_token` → “访问令牌”，包括现有个人访问令牌及兼容的旧版访问令牌。
- 空或无法识别的值 → “未知来源”，不默认归为网页。
- 浏览器使用个人访问令牌时，客户端显示浏览器，操作来源仍为访问令牌。
- “令牌生成/撤销”等是事件动作；通过网页登录生成令牌仍属于网页登录操作，不能根据事件标题判断来源。
- 不改变认证判定、授权、会话刷新或令牌权限；只消费既有服务端审计字段。新增选择器继续区分空参数（全部）与显式 unknown。

优先复用已有解析能力；当前未发现专用 UA 解析依赖，本次采用小型、确定性的展示规则，不为此加载大型浏览器依赖：

- 明确标识的客户端优先：Electron、Postman、curl、Python requests/httpx、Node.js、Go HTTP Client。
- 浏览器按 Edge/Opera/Firefox/Chrome/Safari 的特征优先级识别，覆盖移动端常见标识；再识别 Windows、macOS、Android、iOS、Linux。
- 明确包含产品标识时才显示对应名称；不能从单独的 `node` 推断 Claude Code、某种 SDK 或业务软件。
- UA 是客户端自报值；详情注明“根据客户端标识识别”，不作为认证、安全告警或权限判断依据。
- 非空但未识别时显示“其他客户端”，可查看原文；空值显示“未知客户端”。不猜测被浏览器隐藏的操作系统版本。

## 异常 IP 标注与筛选（2026-11-15 补充）

用户补充要求在审计列表标注异常 IP、筛选时能直接筛选异常 IP，并明确“地址”指 IP 归属地位置信息（国家/地区、省市）。本项已纳入确认后的实现，使用既有安全监控告警作为异常证据，不在页面加载时重新运行检测规则。

### 显示与判定

| 状态 | 显示依据 |
| --- | --- |
| 需关注（警示色） | 关联 `new_login_source` 新来源登录，或达到既有规则阈值的 `login_failures` 连续登录失败 |
| 高风险（危险色） | 关联 `password_spray` 密码喷洒、`login_after_failures` 多次失败后登录成功、`session_reuse` 会话重放等已有高风险认证告警 |
| 已处理（中性色） | 关联告警已 resolved，历史原因仍可查看，不继续作为活动风险显示 |
| 无活动标记 | 没有可见关联告警，或告警已 false_positive；不显示“安全 IP”结论 |
| 检测不可用/待检测 | 监控未启用、扫描尚未覆盖、历史证据已清理、查询失败或覆盖不完整时给出对应状态，不伪装成已确认无异常 |

复用 `StatusBadge`、Tooltip、`CopyButton` 和既有安全监控详情入口。IP 单元格展示原始 IP 与异常等级，悬停 IP 时查询归属地并在提示框显示；不在列表加载时查询。详情采用相同交互；“按此 IP 筛选”填入原始 IP 并保留其他条件。

标注语义是“这条记录的来源关联了异常事件”，不是宣判该 IP 的所有使用者恶意。仅按事件关联匹配，不因同 IP、同一 NAT 出口而把其他账号或其他时间的记录全部标红。普通敏感操作告警 `sensitive_operation` 本身不能证明 IP 异常；单次 401/403、使用 Node/Go、UA 不明也不直接触发风险标记。

增加地理归属展示，不新增第三方 IP 信誉判断，也不根据国外/机房/VPN 地址推定异常。此功能仅展示和筛选，不自动封禁账号、IP 或令牌。

### IP 归属地（按用户要求简化，2026-11-15）

移除本地 City MMDB、相关依赖、设置页面和后端批量归属地接口。列表只展示原始 IP 与异常标记；鼠标悬停 IP 后才在 Tooltip 中查询并显示“国家/地区 · 省/州 · 城市”。键盘聚焦和点击 IP 也可打开提示。复用现有 Tooltip、CopyButton 和 TanStack Query，不新增后台服务或配置项。

浏览器直接请求 `https://free.freeipapi.com/api/v1/json/{IP}`，读取 `countryName/regionName/cityName`。公网 IP 会发送给该服务；不使用带本站认证头的 api 实例，不发送 Cookie、令牌、来源页面 URL 或审计元数据。地址先校验，内网、回环、链路本地和保留地址在本地显示，不向外发送。服务支持 HTTPS、IPv4/IPv6、CORS，免密钥且允许商业使用；免费额度为每个访问者 IP 每 10 秒 10 次、每分钟 60 次，详见 [供应方文档](https://freeipapi.com/docs/api-reference/api-introduction) 和 [使用说明](https://freeipapi.com/)。城市和省州沿用数据源名称，国家名通过浏览器 Intl 按界面语言显示。

仅提示框打开时启用查询；相同 IP 复用 TanStack Query 缓存，成功结果缓存 24 小时，闲置 10 分钟回收。请求最多 5 秒，不自动重试或轮询，不在窗口重新聚焦时刷新；失败只在提示框显示不可用，再次打开可重试。结果缺失时显示未知，不猜测城市；位置仅为当前近似归属地，不是事发时的位置快照。异常 IP 标记和筛选继续独立运行。

验证先覆盖：页面初载零归属请求；悬停/聚焦后查询、缓存复用；IPv4/IPv6、内网及无效地址；查询失败和超时不影响列表；请求不携带本站凭据。此次调整不改数据库模型、审计授权或 AI 转发链路。

本次新增的是归属地展示与异常 IP 筛选；原 IP 输入框仍按数值精确匹配，未把城市名当作 IP 参数。地域本身不参与风险等级计算。

### 异常 IP 筛选语义

新增独立的“异常 IP”下拉，默认“全部 IP”：

| 选项 / 参数 | 匹配规则 |
| --- | --- |
| 全部 IP / 省略 `ip_risk` | 不按风险缩小范围，包含未检测记录 |

| 需关注 / `attention` | 当前事件最高活动风险为需关注，且没有更高风险 |
| 高风险 / `high` | 当前事件至少关联一项活动高风险规则告警 |

等级映射与列表徽标共用同一规则。已处理、误报、未检测、历史证据缺失不作为活动异常命中；监控覆盖不足时显示范围说明，不能宣称没有命中等于该范围所有 IP 都正常。监控暂停后已保留的活动告警仍可查询，同时注明检测未持续更新。

异常条件与时间、具体 IP、权限身份、用户名、路由、操作来源、结果、分类等条件均为 AND。例如“仅异常 IP + 203.0.113.24 + 管理员 + 访问令牌”只返回同时符合这些条件的事件。选择异常条件、切换等级或重置均从结果首页开始，纳入已选条件计数和移动端筛选。

**筛选必须在服务端、分页之前生效，覆盖所选时间范围内全部有权限且有证据的记录。** 不允许先取普通日志第一页，再根据本页徽标在前端删除正常行；不允许只使用已加载的异常 IP 列表作为整个查询范围。同一 IP 下没有关联异常证据的正常事件，不因地址相同被算作异常事件；用户可切回“全部 IP”并保留地址，查看该 IP 的完整操作记录。

### 证据关联、接口与权限

当前 `audit_security_alerts.evidence` 是最多 20 条事件的 JSON 快照，没有可按审计事件 ID 反查告警的关系表。**需补齐后端关联查询能力，不能前端扫描当前告警页或按 UA/HTTP 状态伪造风险。**

新增主库表 `audit_security_alert_events`：`event_id`、`alert_id`、`event_at`、`ip`。复合主键 `(event_id,alert_id)` 用于当前页事件批量反查，另有 `(alert_id,event_id)` 用于随告警清理、`(event_at,event_id,alert_id)` 用于异常结果时间游标、`(ip,event_at,event_id,alert_id)` 用于具体 IP 与异常条件组合。只保存安全的证据标识，不复制凭据、UA 或完整请求。

既有监控 worker 提交相关规则告警时，在同一事务批量幂等写入证据事件关联；每个 finding 仅处理已有的最多 20 条证据。告警 severity/status/visibility 从原告警表读取，不另存可能失效的风险状态。误报处理后立即停止显示活动标记；重新打开告警按当前状态显示。

新增 `GET /api/audit/security/ip-markers?event_ids=...`，放入现有安全监控路由组，要求 AdminAuth + `audit:read` + `audit_security:read`。event_ids 最多 100 个、每个不超过 64 字符，超限拒绝；服务端先检查原审计记录可见性，再按事件 ID 批量关联告警，匹配事件时间和 IP。返回 `{success:true,data:{items:[{event_id,ip,state,level,reasons:[{rule,alert_id,status,at}]}],coverage}}`；ip 取自已验证的原审计记录。单条最多 3 个原因，注明是否还有更多。无权限的关联不返回原因、数量或告警 ID。

新增 `GET /api/audit/security/ip-records` 用于异常筛选结果，复用相同安全监控路由组及权限。接受现有审计筛选参数（分页除外）、必填 `ip_risk=abnormal|attention|high`、可选 `cursor`、`limit=1..100`（默认 20）；返回 `{success:true,data:{items:[审计记录及ip_marker],next_cursor,coverage}}`。全部 IP 模式继续调用原 `/api/audit`；异常模式使用本接口，防止不同数据库间关联破坏分页正确性。两个模式共用参数校验、日志投影和可见性规则。

异常结果从主库按 `(event_at,event_id)` 倒序读取可见活动告警对应的候选事件、合并重复事件，再按批次向日志库查询原记录并应用全部审计条件；每批最多 100 个候选、每次请求最多处理 1,000 个候选，总预算 3 秒。日志库用时间范围和 event_id 批量查找，严禁拉取整个异常 ID 集合构造无界 IN。游标指向最后实际处理的候选，不能越过已预取但尚未处理的事件；跨页继续服务端过滤，确保没有漏页或重复事件。

异常模式显示“上一页 / 继续加载”，不显示未经完整计算的 total 或任意跳页；前端保存游标栈以返回上一页。筛选较稀疏而处理预算耗尽时，返回已找到的结果及 next_cursor（即使本批为空），明确提示继续加载；只有游标耗尽才显示“无符合条件的记录”。超时是可重试错误，不返回伪造的空结果或总数。选中条件时即清除旧分页游标；告警处理状态变化后重新查询，旧游标不能跳过权限校验。

只有具备安全监控读取权限的管理视图加载标注；普通用户及“仅自己”视图本次不开放跨账户安全信号。Root/未知身份和认证关联的 Root-only 限制沿用既有 `SecurityVisibleQuery`，不能借 IP 徽标扩大可见性。

全部 IP 模式先正常展示审计列表，再一次请求当前页标注；不逐行请求、不阻塞日志展示。异常模式直接返回符合条件的记录和标注，不做本页二次筛选。切换页码、筛选、账号或权限时隔离/取消旧请求，处理告警后同时失效标注和异常结果缓存。普通列表标注失败仅显示标注暂不可用，原日志仍可查看；异常查询失败必须显示查询错误，不能回退为未筛选列表。

### 生命周期、资源与验证

新表仅在主库迁移，兼容 SQLite/MySQL/PostgreSQL；日志库即使为 ClickHouse，也只按 event_id 和时间范围批量核对，应用层合并，不跨库 JOIN。当前页标注批量读取复用本设计的专用审计读取池，最多 2 秒，最多 100 个事件；异常筛选遵循上述 3 秒/1,000 候选的预算。主库查询使用事件关联时间/IP 索引及告警 ID 主键，不对 evidence 做 LIKE 或全表 JSON 解析。真实 EXPLAIN 需覆盖等级、具体 IP、时间、告警可见性和稀疏结果组合；候选上限不替代数据库扫描成本验证。

历史告警的关联只能从仍保留的 evidence 分批补建，每批最多 20 条告警，按不可变 ID 递增扫描，并固定首批取得的最大 ID；同时限制保留期和 IP 规则。`audit_security_risk_states` 保存回填位置、结束 ID、完成标记及风险修订号。新增告警由正常事务维护关联，避免 `last_seen` 变化导致回填跳项。现有证据已被截断/清理的记录仍为覆盖未知，不承诺完整恢复历史。清理先按 alert_id 每事务删除最多 500 条关联，再删除对应告警，不扩大原审计保留期。

新增表与 worker 事务只用于安全监控，不接触 relay。列表标注读取与检测池分离；数据库 CPU/I/O 仍共享，需验证关联批量写入和回填负载。不给每次 AI 请求增加查询、网络请求、锁或 goroutine。

测试补充：完整 IPv4/IPv6 地址和复制值、国家/省市层级缺失、内网/回环/未知归属、悬停前零请求、缓存复用、查询失败与再次打开重试；同 IP 不同事件/账号不串标；新来源与高风险等级；正常敏感操作、单次失败排除；告警已处理/误报/重开；Root-only/无权限隔离；监控关闭/积压/失败/历史缺失；100/101 个事件边界；同一事件多告警合并；跨页旧响应不污染新页；关联幂等、回填续跑、清理与三库迁移重复启动无 DDL。异常筛选必须覆盖“普通第一页没有异常、后续记录存在异常”、多条件 AND、同一事件多个等级取最高、候选重复/分页去重、稀疏结果空批后续仍有命中、1,000 候选预算后的继续加载、查询失败不降级为未筛选列表，以及主库/日志库分离的真实查询。新增文案按既定前后端语言集同步。

## 数据流

新审计事件：既有管理/认证请求 → 已验证操作者身份 → 有界员工快照读取（仅适用普通角色）→ 既有审计写入，新增快照列 → 既有日志保留/清理流程。

列表：筛选表单提交 → 对应 all/self 接口 → 参数校验与服务端可见性约束 → 日志库按时间及索引过滤 → 统一统计/分页 → 既有元数据权限投影 → 前端身份、来源和客户端展示。

异常 IP 结果：管理视图提交异常条件 → security/ip-records 校验安全监控权限 → 主库按时间/IP 和活动告警获取候选 → 日志库批量执行完整筛选及可见性约束 → 按事件去重和游标返回记录与具体 IP 标注；整个流程在服务器执行，不局限于普通列表的当前页。

归属地：已有权限范围内的日志展示 IP → 悬停/聚焦/点击 IP → 浏览器按需请求在线接口 → Tooltip 显示国家/省市，复用查询缓存；不回写审计日志。

路由选项：打开下拉/搜索/加载更多 → 对应 all/self 路由接口 → 同一可见性和时间约束 → 仅查询去重的路由模板 → 游标分页返回。选项不从当前页的二十条日志拼凑。

## API 合同与授权

| 接口 | 授权 |
| --- | --- |
| GET `/api/audit` | 沿用 AdminAuth + `authz.AuditRead` |
| GET `/api/audit/self` | 沿用 UserAuth；服务器绑定当前 user_id |
| GET `/api/audit/routes` | 新增于同一管理权限路由组，AdminAuth + `authz.AuditRead` |
| GET `/api/audit/self/routes` | 新增于 UserAuth 组；服务器绑定当前 user_id |
| GET `/api/audit/security/ip-markers` | AdminAuth + `authz.AuditRead` + `authz.AuditSecurityRead`；当前页批量标注 |
| GET `/api/audit/security/ip-records` | 同上；异常 IP 组合筛选与游标分页 |

不新增公开接口。新接口登记到既有访问令牌路由/权限注册机制，沿用当前允许的调用身份，不额外扩大令牌能力。

列表保留原 `p/page_size/category/success/username/request_id/token_ref/exclude_token_ref/start_timestamp/end_timestamp` 参数，新增：

| 参数 | 规则 |
| --- | --- |
| `ip` | 去除外围空白后最多 64 字符，校验 IPv4/IPv6，按存储文本精确匹配；不接受 CIDR 或任意 LIKE 模式 |
| `actor_type` | `root/admin/employee/user/unclassified_user/unknown`；空为全部 |
| `auth_method` | `session/access_token/unknown`；空为全部 |
| `route` | 最大 255 字符的路由模板，精确匹配；不接收完整 URL 或查询串 |
| `route_missing` | 可选 `true`，筛选未记录路由；不能与非空 route 同时使用 |

普通列表响应仍为 `{success:true,data:{items:[...],total,p,page_size}}`，每项增加 `actor_is_employee: boolean|null`；原始字段保留，客户端展示不改变原始 UA。异常结果使用上文定义的独立游标接口及 `ip_risk` 参数；非法等级必须报错，普通/self 列表收到不适用的异常参数时明确拒绝，不能忽略后返回全部记录。

路由接口接受 `start_timestamp/end_timestamp`、`q`（最长 255 字符的字面前缀）、`after_route`（上一页最后一个模板）、`limit`（默认 50，1–100）。响应为 `{success:true,data:{items:["/api/status",...],next_cursor:null|"/api/..."}}`。查询读取 limit+1 行判断下一页；仅返回非空模板。“未记录路由”为固定筛选选项，不泄漏记录是否存在。

旧列表时间合同保持不变，不自动补齐或截断旧客户端查询；新增路由/异常接口要求完整有效时间窗且跨度不超过 31 天。前端提交最近 24 小时作为默认值。负时间、逆序、无效枚举返回可读错误。

非 Root 不能通过指定角色、路由、统计 total 或选项接口获取 Root/未知操作者记录。列表、统计、选项共用可见性规则；self 不接受客户端传入的 user_id/username 扩大范围。既有 `root_info/admin_info/audit_info` 投影保持一致。

## 数据模型、索引与迁移

基础筛选在 `audit_logs` 增加可空布尔列 `actor_is_employee`；Go 使用 `*bool`，JSON 明确返回 NULL，不用 `omitempty` 隐藏显式 false。异常 IP 标注另增加上文规定的主库证据关联表。不修改用户角色或员工档案结构，不回写已有审计记录。

SQLite/MySQL/PostgreSQL 使用 GORM 可空布尔映射，不声明布尔 default。ClickHouse 使用 `Nullable(Bool)`，新建及旧表增列均覆盖；真实驱动测试发现 `Nullable(UInt8)` 不支持 `*bool` 写入，因此没有采用该类型。

### Index Design

关系库提出以下索引，以实际 EXPLAIN 验证为实施门槛；索引覆盖筛选/排序键，不试图覆盖 Content/Other/UA 等大字段：

| 查询 | 索引键 |
| --- | --- |
| IP + 时间排序 | `(ip, created_at, event_id)` |
| 角色 + 时间排序 | `(actor_role, created_at, event_id)` |
| 员工/普通用户/历史未分类 + 时间排序 | `(actor_role, actor_is_employee, created_at, event_id)` |
| 来源 + 时间排序 | `(auth_method, created_at, event_id)` |
| 路由精确筛选 / 路由前缀选项 | `(route, created_at, event_id, actor_role)` |
| 本人路由选项 | `(user_id, route, created_at, actor_role)` |

复用已有 `(created_at,event_id)`、`(user_id,created_at)`、令牌/请求 ID 等索引。组合条件不为每个排列新增索引；验证主选择条件的访问计划及剩余过滤成本。使用显式列清单，禁止路由选项 SELECT *。

路由选项按 route 游标分页，不用 OFFSET。现有日志列表本次保留页码合同；时间窗、查询超时和索引限制其成本，不以“有 LIMIT”声称深页查询代价恒定。超时提示缩小时间范围或增加筛选。

ClickHouse 保留原有按月分区及 `(created_at,event_id)` 排序，依赖时间裁剪；分别评估 IP/route 的 bloom_filter 与低基数身份/来源的 set 跳数索引，只有 EXPLAIN 和读取行数证明有效才加入。不得把关系库索引方案直接套用或承诺 ClickHouse 精确等值索引效果。历史索引物化不得在服务启动无界执行。

新增关系库索引会增加审计写放大和磁盘占用；在生产 schema 副本和接近实际分布的数据上验证后再部署。MySQL 5.7 索引字节长度、SQLite 建索引锁、PostgreSQL 建索引影响及 ClickHouse 增列均必须实测。第二次启动不应再发 DDL。

## 查询资源与配置

- 列表和路由选项使用审计查询专用日志库连接池，最多 2 个连接；请求总预算 3 秒，路由选项最多 2 秒，包含等待连接的时间。池在进程初始化/关闭时统一管理，不按请求创建。
- 员工快照使用独立主库只读池，最多 2 个连接，单次最多 100ms；不占用转发与员工佣金读取使用的连接池或内存缓存。只做索引点查，无行锁。
- 不与安全监控 worker 的池混用；可复用项目现有独立池的底层连接构造方式，不能把查询功能依赖于监控是否启用。
- 连接数、查询预算等为实现边界，不新增对应用户配置。归属地无配置项，现有审计保留配置继续生效。
- 时间范围及 LIMIT 不是物理扫描行数保证；真实执行计划、超时与连接数上界共同验收。独立池只隔离连接容量，仍须评估数据库服务器的 CPU/I/O。

## 错误处理与国际化

参数失败用 `common.ApiErrorI18n` 返回现有 success=false/message 结构；认证/授权由既有中间件处理。数据库故障先记录带请求上下文的内部错误，再返回可读提示，不向浏览器暴露 SQL、驱动错误或 DSN。新增控制器路径不沿用当前接口直接返回原始 err 的做法。

员工识别异常只影响身份细分，显示未记录，不丢弃审计、不改变业务结果。路由加载失败可独立重试；列表失败显示错误并禁止把旧数据当作新筛选结果。

前端七种语言同步新增筛选项、历史身份说明、来源和客户端文案。后台按实际仓库的 `i18n/locales/en.yaml`、`zh-CN.yaml`、`zh-TW.yaml` 补齐新错误；现有 AGENTS 路径示例与当前文件格式不同，以实际代码加载位置为准。所有写入为 UTF-8 无 BOM。

## Main Chain Impact

AI relay goroutine 新增同步操作、DB/Redis 调用、锁、goroutine 数量均为 **0**。不改 `relay/`、TokenAuth、分发、计费或流式处理，也不在 relay router 注册新的审计逻辑。

身份快照查询只发生在已有管理/认证审计采集路径；来源和客户端展示不修改鉴权机制。安全采集原有异步队列保持非阻塞，没有快照就保留未知。

### Concurrency Analysis

30k/100k RPM 的 AI 转发新增每请求成本均为零；新增负载由审计事件与审计页面查询量决定。

普通角色审计请求最多增加一次主库索引点查，同请求复用结果；Root/管理员为零。并发最多占两个专用连接，超过预算按身份未知降级。普通列表沿用一条统计和一条分页查询；路由选项为一条有界结果查询，不为每个选项读取日志详情。异常结果不做全范围统计，最多处理 10 个候选批次，主库候选及日志库查询均使用专用池和统一截止时间，不按候选逐条查询。不新增 Redis 调用或逐日志 goroutine。

关系库审计写入增加一列及索引维护；实际吞吐与部署库配置有关，需要管理流量叠加转发的负载验证。当前设计阶段没有完成 30k/100k RPM 或生产规模性能验收。

## 实施文件范围与交付状态

实现涉及审计模型、采集、独立读取池、controller/router、前端 audit feature 与测试。异常 IP 另涉及安全监控模型、证据关联/回填/清理及权限测试；归属地仅使用前端按需查询及提示框，不增加后端服务。员工查询与日志库迁移按本设计限定范围处理，不修改员工佣金算法。

实现覆盖基础筛选、员工身份快照、路由分页、来源/客户端识别、悬停 IP 查询归属地、事件级异常筛选、证据关联、回填与清理。旧列表接受未传时间和单侧时间；新增路由、标注和异常结果接口要求完整且不超过 31 天的时间窗。批量标注最多 100 个事件 ID；分页末尾省略 next_cursor。

审计读取创建三个独立连接池（日志、主库风险读取、员工快照），各最多 2 个连接。监控表在读取池初始化时迁移，即使检测关闭也能查询保留告警；迁移失败不撤销普通日志读取池，后台监控启用后仍有自身初始化重试。员工快照只允许 `/api/` 请求，按操作者 ID 在请求内缓存，后台队列不回填身份。

风险游标在 SQL 按事件聚合后分页，因此无需把 `alert_id` 放进游标；同一事件的所有可见活动告警在分组前参与最高等级判断。游标绑定完整筛选、用户、角色和持久化风险修订号；告警、关联或清理变化后要求重新搜索。列表覆盖信息只返回启用、采集、暂停、就绪和截断状态，不返回 Root 专属扫描错误、计数或进度。

归属地不再依赖 MMDB 或 Go 解析库，也不增加设置保存逻辑；前端直接调用支持 CORS 的固定 HTTPS 地址，不复用本站带认证的 HTTP 客户端。

路由选择沿用基础 Combobox 的组合组件。现有业务 Combobox 未暴露远程查询需要的展开与输入事件，因此本功能组合 `ui/combobox` 的 Input/Content/List/Item，保留项目键盘和无障碍行为；没有引入第二套选择器库。其余工具栏、复制、状态徽标、详情弹窗和设置弹窗复用已有组件。
