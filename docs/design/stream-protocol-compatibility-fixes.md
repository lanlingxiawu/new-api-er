# 流式协议兼容性三项修复

## 已确认目标与范围

用户确认修复本轮审计的三项问题：OpenAI 转 Claude 首帧前置空事件导致缺少 message_start；候选数量取自入口而非实际出站参数；Gemini promptFeedback 策略拦截被误记为流截断。仅修复新流式流程，保留原非流式、开关关闭、非 200 和未收到 HTTP 响应的处理。

## 数据流与实现方案

1. 受管 OpenAI 转 Claude 在决定执行转换后才推进转换计数；message_start 尚未发送时按首帧初始化。ping/空 choices 在协议完成前只保存可能存在的 usage，不消耗首帧，也不补正常结束。
2. 请求转换、字段移除和参数覆盖完成后，从已有出站 JSON 提取候选约束，覆盖本次会话入口默认值。覆盖 Chat、Claude、Gemini、Responses 和 Chat 经 Responses 转换。移除字段或转换到没有候选数的协议时清除旧值。透传不执行参数覆盖，沿用入口 DTO 对原文中受支持参数的解析结果，不重读请求体。每次重试重新创建会话再采用本次最终参数。
3. Gemini 有明确、非空且非 UNSPECIFIED 的 promptFeedback.blockReason，且没有候选和先前未完成候选时，识别为策略终态；普通空对象、仅 usage、空/无效反馈仍是未完成。SSE 和完整 JSON 共用判定。保留已有 reject_reason 及原响应转换和正常计量，不补上游异常 error，不设置异常诊断资格。原生 error、非法 usage、后续非法 JSON 仍按异常处理。

## API、数据模型与配置

无新增接口、权限、日志字段、表、迁移、索引或配置。仅增加请求局部辅助逻辑；沿用 stream_error_setting.enabled。原始响应、底层错误和用量证据仍仅由超级管理员诊断接口查询，仅上游异常持久化原始响应；不采集请求头或请求 body。

## 计费及错误边界

不改异常计费矩阵：用户断开采用确认用量；上游异常有有效交付采用确认用量或交付估算；无有效交付不计费。修复的是进入该矩阵的错误分类。Gemini 策略终态沿用渠道现有计量，不把它归入网络/协议损坏。真正缺尾帧继续报错；候选数量下降不误报，上升后确实缺失候选仍报错。

## Main Chain Impact

同步执行：请求发送前只对已有 JSON 查询少量计数字段；每帧进行已有协议观察中的反馈字段检查和转换计数更新。不增加网络读取、请求体复制/落盘、定时等待或等待下一帧；响应日志仍走既有异步路径。关闭开关和非流式仅执行 nil 会话判断。

## Shared Resource Audit

新增访问仅为请求局部候选整数、转换状态及会话现有短锁。无新增 Redis namespace、数据库表/行访问、共享缓存、文件句柄或连接池；不占用额外后台工作者。已有请求 BodyStorage 的创建/释放方式保持不变。

## Concurrency Analysis

30k/100k RPM（约 500/1667 请求每秒）新增 DB/Redis 调用 0、协程 0。出站参数查询每请求一次，最坏 O(JSON 字节数)，不持有 JSON 引用；响应新增查询 O(当前事件大小)，无跨请求锁。使用本地基准关注大请求查询成本与首帧交付测试，不将本地测试视为生产压测。

## 验证方案与步骤

先编写回归测试并确认修复前失败，再实施：
- ping、空 choices、首帧 usage、多条前置事件后正文：message_start 恰好一次且先于内容，正文不重复，异常不伪造成功尾帧。
- 本地 HTTP 夹具捕获真实出站 JSON：n/candidateCount 覆盖增减、删除、跨协议转换、透传原字节不变、渠道重试；测试期间上游返回 503，避免进入资金数据库，再单独测试响应完成状态。
- Gemini 原生/转换 SSE、完整 JSON、合法拦截、空反馈、仅用量、普通截断、原生 error：检查 reject_reason、诊断资格、错误事件与用量选择。
- 运行相关 relay、service、model、controller、middleware 测试和构建，补中文注释并核对含义；环境相关数据库/race 验证另行注明。

## 风险和取舍

不修改 relaykit 的通用转换器或扩展非流式协议。候选约束只解释实际协议支持的字段；缺失不推断未声明的额外候选。Gemini 合法反馈终态有严格结构约束，不将任意空结果放宽成正常完成。

## 实施结果

三项均已实施。先前代码运行新增夹具时分别出现：message_start 数量为 0；出站 n=1 而会话期望 2；Gemini 策略反馈的原用量被替换为异常零用量。修复后这些夹具通过。

- Claude：跳过事件不推进转换计数，实际首次转换以 MessageStartSent 初始化；覆盖首帧 ping、空 choices、带 usage 及多条前置事件，正常/截断路径均验证。
- 候选数：五个最终出站位置调用 UpdateStreamExpectedChoices，只保存整数，不保留请求原文。覆盖 n 增减、删除、不覆盖但转换移除/保留字段、Gemini candidate_count 别名、跨协议、透传原字节以及重试改变覆盖。参数更新不提前开放 HTTP 响应门控；非 200 仍走原流程。
- Gemini：协议观察和完整 JSON 校验共用明确策略反馈判断。无候选允许省略、null 或空数组；普通空结构、无效反馈、非法 usage、原生 error、先前候选未完成均保留异常。原生 Gemini、OpenAI、Claude、Responses 四种输出验证原 reject_reason、正常用量对象、无补发 error 和无异常诊断标记；日志无原始响应 body/头。
- 无 relaykit、前端、依赖、数据库结构修改。新增和变更方法及测试说明已补中文注释并核对实际分支。
