# 流式缓存字节边界与 SDK/Realtime 原错误保留修复

## 已确认需求与范围

按本轮“按推荐修复”实施两类问题：Realtime response ID、未完成工具名称通过 JSON 子串间接保留大帧；SDK/Realtime 原 error 携带非法 usage 时被通用错误替换。仅修改新流式流程，非流式、未收到 HTTP 响应、HTTP 非 200、功能关闭、原生 Claude 专用状态机保持原流程。

## 数据流、方案及边界

1. Realtime 完成轮次的 response ID 立即计算 SHA-256，最近 128 个身份的表与环都只保存定长摘要。空 ID 不参与去重；重复 ID 不前移淘汰位置；新连接重新初始化，轮次之间保留窗口。
2. 未完成工具名称存入会话前使用 strings.Clone，参数继续由 Builder 复制。现有工具数和总字节预算不变，不再通过小名称持有完整 JSON 分配。
3. ObserveEvent 识别终止 error 后，先独立保存原始载荷，再校验用量。非法 usage 仍产生 upstream_json_error，不采纳该事件任何用量，先前确认的证据保持。可恢复 Realtime 请求错误仍提前返回，不占终止槽。
4. 增加仅会话内部使用的 ErrorPayload 字节槽承载 SDK/WS 无 SSE 外壳的原载荷，保留空白与原始排版；快照深复制。HTTP ObserveFrame 保存完整原 SSE 帧时释放该载荷副本，最终只保留一种表示。每种输入仍受现有单帧上限约束。
5. 同协议、错误形状匹配时优先透传：HTTP 原 SSE 帧不变；SDK 载荷只添加 SSE 字段外壳，多行按 SSE 行规则编码（CR/CRLF 规范化为 LF），不重新序列化 JSON；Realtime 直接发送原 WS 消息字节。SDK 终止写入采用固定 4 KiB 编码缓冲，不在内存中构造换行放大后的全帧，写出失败立即结束。跨协议或形状不兼容仍用既有公开错误。
6. Realtime DTO 解码失败分支也将原终止错误交给观察器，覆盖 response.usage 类型错误先被 DTO 拦下的情形。原错误仅在最终输出处补发一次；原本已成功透传的错误保留既有去重逻辑。

## API、存储、配置与错误处理

无新端点、日志字段、数据表、迁移、配置或依赖。ErrorPayload 是请求局部工作状态，不直接序列化到日志或接口。诊断仍使用原采集器、现有截断规则与超级管理员接口；capture_response 关闭不影响错误透传。已确认用量和有效交付的计费矩阵、预留及退款规则不变。

## Main Chain Impact

同步新增成本仅为完成轮次 ID 哈希、保留工具名时的短字符串复制、终止错误时的有界载荷复制及必要 SSE 包装。没有等待下一帧、聚合正文、数据库/网络查询或新增异步任务。原错误写出仍发生在既有终止写入点，正常 delta 即时转发。

## Shared Resource Audit

使用请求/连接局部会话、身份环和现有会话短锁；锁不跨网络 I/O。不新增或修改 Redis 命名空间、DB 表、连接池、工作池、文件句柄及跨请求缓存。资金会话接口与异步日志队列调用次数不变。

## Concurrency Analysis

30k/100k RPM 下新增 DB/Redis 调用、goroutine 均为零。身份环固定 128×32 字节，集合最多 128 个 32 字节键；哈希 O(ID 长度)，受 8 MiB 单帧上限约束。工具名称 O(名称长度) 复制，仍使用原工具总字节预算。错误载荷只在终止异常保留，上限为现有单帧大小；HTTP 保存原帧后清空冗余载荷。SDK SSE 编码额外缓冲固定 4 KiB，极端换行可增大线上字节数但不分配放大后的全帧。所有状态在请求/连接结束时释放。

## 风险、可选项与验证

- 固定摘要有理论碰撞风险，采用 SHA-256；超过 128 个不同完成响应的旧 ID 不保证去重，保持既有窗口语义。
- 不使用 GC 堆大小的易波动断言；工具缓存验证字符串存储地址独立，身份缓存直接断言固定摘要、128 边界与淘汰。
- SDK/WS 验证非法 usage 容器、计数类型与负数，先前确认用量保留、无交付零计量、有交付按原矩阵计量，错误字节和次数、排版、多行及采集关闭；保留 HTTP 原 error、跨协议、不完整 JSON、自定义错误和可恢复事件现有测试。
- 全部供应商交互使用本地夹具，无真实上游或资金操作。测试、构建、gofmt 和差异检查；真实数据库联调、竞态与生产负载只按实际执行情况报告。

## 实施结果与复核（2026-09-14）

- RED 阶段先复现：工具名仍与原 JSON 子串同地址；Realtime 缓存身份仍为 string；SDK 和 WS 的非法 usage 错误被通用错误替换。修复后上述回归通过。
- Realtime 身份验证空值、重复不推进、128 项容量、第 129 项淘汰、长 ID、连接隔离。工具名验证独立存储、完成内容和总字节预算释放。
- 载荷验证原输入修改与快照修改均不污染会话，首错之后不覆盖原错误/证据；新成功响应清空旧载荷；HTTP 原 SSE 帧替代临时载荷；8 MiB 前一字节、恰好上限及超过一字节；未激活、取消、可恢复错误和非法 JSON 的排除分支。
- AWS SDK 本地夹具覆盖非法 usage 容器、负数、排版 JSON，已交付内容和既有确认用量保持，重复 Finalize 不重复输出错误。

- SDK 多行包装使用固定 4 KiB 编码缓冲。先以大量空行复现整帧聚合的 14,436 字节单次写出，再验证固定缓冲交付且载荷完整；另覆盖短写、底层错误及小/长行/多行错误，失败后停止写出和刷新。
- 协议回归覆盖 OpenAI、Claude、Gemini、Responses，同协议保留、跨协议和错误形状不匹配使用既有错误；未收到响应和 201/401/429/500 不进入终止写入。现有 HTTP 原错误、可恢复事件、结束顺序、透传、非流式及诊断权限回归全部通过。
