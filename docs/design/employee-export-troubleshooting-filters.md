# 员工客户日志导出：补齐排查筛选

状态：已获用户确认并实现。分支：`zhuzhan-f0b-latest`。

## 目标与范围

补齐用户截图中管理员新建导出的“排查筛选”，用于员工客户管理和客户日志页的客户导出：

- 异常：任意异常，以及服务器提供的异常类别。
- 是否计费：不限、已计费、未计费。
- 快捷筛选：输出为 0 却计费。
- 最低额度、最少输出 tokens、最多输出 tokens、最短耗时（秒）、最少重试次数。

复用管理员导出的筛选语义、样式和文案。不扩展日志类型、渠道筛选或输出列权限。

## 现状

`model/employee_export.go` 的员工筛选白名单仅含 `model_name/token_name/group`。`controller/employee_export.go` 将 `filters` 解码为字符串映射，创建任务时也只映射这三项。前端 `employee-customer-export.tsx` 仅按模板白名单渲染值下拉。现有日志扫描器已经实现异常和数值筛选，因此本次复用扫描器而不另建扫描流程。

## 数据流与 API 合约

沿用 `/api/user/employee/export/capabilities`、`/estimate`、`/jobs`，认证和客户归属检查沿用现有员工导出规则。

capabilities 增加 `anomaly_kinds`、`quota_per_unit` 和筛选列表数量上限，供异常按钮、额度单位说明和校验使用。

请求仍使用 `filters`，原三项仍为字符串；新增 `anomaly_only`（布尔）、`anomaly_kinds`（字符串数组）、`charged`（布尔或 null）、`quota_min/completion_tokens_min/completion_tokens_max/use_time_min/min_retry_count`（非负整数或 null）。省略或 null 表示不限；明确的 `false` 和 `0` 必须保留。

估算与创建使用同一解析、校验和任务筛选映射。数值条件复用现有 SQL 筛选；异常和重试条件复用逐行过滤。估算包含逐行条件时展示过滤前的扫描行数，不能暗示为最终结果数量。

实现中 `filters` 使用 `json.RawMessage` 保存各值的类型，通过 `common.*` 解码为既有导出请求 DTO。`buildEmployeeExportFilter` 先校验模板白名单、字符串长度及非负安全整数，再复用 `buildLogExportFilter` 校验异常类别、列表长度和上下界。前端省略 null 条件，保留 false 和 0。值上限为 JavaScript 安全整数上限 9007199254740991。

## 模板兼容与界面

内置客户对账单开放上述排查筛选。自定义模板编辑器增加相同选项，员工只看到管理员开放的筛选项；旧自定义模板保持原白名单，由管理员编辑后开放。输出列、格式和汇总维度继续由模板决定。

员工导出加入默认折叠的“排查筛选”，控件复用管理员界面的行为；任意异常与指定异常类别互斥。快捷条件设置 `charged=true` 和 `completion_tokens_max=0`，同步显示到相关控件。额度明确标注单位及美元换算。切换模板时清除不再允许的条件，提交中禁用控件。

## 数据模型、配置与生命周期

无新增表、列、索引或配置；模板筛选白名单沿用 `definition`，任务继续保存现有 `LogExportFilter`。旧请求和旧任务保持兼容。创建、估算、后台扫描、取消、清理、下载以及权限撤销沿用原导出生命周期。

## 校验与错误处理

后端拒绝未开放或未知筛选、错误类型、未知异常类别、过多列表项、负数、小数、超出安全范围的数值及最少输出大于最多输出。复用已有导出参数校验逻辑和本地化提示；不向界面泄露底层错误。前端同步阻止无效提交并显示可操作提示。

## Main Chain Impact 与共享资源

AI relay goroutine 上新增同步操作为 0。仅修改员工导出管理请求、表单和任务筛选构造；沿用现有日志读取、时间窗、批次限速、查询超时及并发预算。无新增连接池、缓存、Redis key 或后台 worker。异常过滤在既有导出 worker 进行，不新增日志写入或 relay hook。

## 测试与验收

实施前先补回归用例：原字符串请求兼容；新条件正确进入任务；false/0 不丢失；非法类型、负数、未知类别、超限列表及模板禁止条件被拒绝；估算和实际导出的筛选一致；客户范围不能被筛选覆盖。

验证员工客户导出使用“输出为 0 却计费”时仅写出额度大于 0 且输出 tokens 为 0 的记录，并验证异常、最低额度、耗时和重试条件。运行相关 Go 测试、前端类型检查及 lint；核对空条件下的导出行为和旧模板兼容性。实现后同步更新原员工导出设计文档。

验证结果：新增参数回归、模板白名单和范围校验通过；使用 SQLite 回退验证完整员工请求解析、客户范围和零输出已计费／未计费的实际 SQL 估算结果。相关模型异常判定与模板校验测试、前端类型检查、lint、格式检查和生产构建通过；通过 Happy DOM 验证快捷按钮、0、false、异常互斥和模板控件可见性。未配置 SQL_DSN；完整 controller/model 套件的既有 veridrop 测试访问空 DB 时发生空指针，真实 MySQL/PostgreSQL 集成测试尚未验证。lint 留有无关 footer 文件的既有警告。
