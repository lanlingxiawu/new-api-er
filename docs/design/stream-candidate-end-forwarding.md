# 多候选流结束帧转发修复

> 本文主体记录此前单独修复候选帧过滤的一轮实施。后续已修复候选完成判定、预读时序、AWS Claude delta 和完整 JSON 校验，当前规则见 [四项修复与延迟验证](stream-four-regression-fixes.md)。以下原范围/结果是历史记录，不代表后续代码仍保持不变。

## 授权、目标与范围

用户确认“按推荐修复”，本轮只修复审计 A1：正常多候选流中先结束的候选被整帧丢弃。A2 Realtime 轮间错误补发不在本轮范围。

保留异常后过滤假成功尾帧的机制，将候选级结束与整条响应级结束区分。覆盖公共写入器识别的 OpenAI `choices.finish_reason` 和 Gemini `candidates.finishReason`，不改变渠道转换、上游完成状态机或计费策略。

## 数据流与业务规则

实际成功响应门控 → 既有上游协议观察 → 渠道转换 → 下游 SSE 帧分类 → 原字节写出/刷新 → 既有有效交付统计 → 既有终止结算与日志。

帧分类为：非成功结束、候选级结束、响应级结束。显式错误事件优先于所有成功标记；`[DONE]`、`message_stop`、带 stop_reason 的 `message_delta`、Responses 终态等既有响应级标记优先于附带的候选字段。

- 候选级结束：只要尚未记录终止原因，即原样转发整帧，不要求全部候选完成；保留正文、工具参数、同帧其他候选和未知字段。
- 响应级结束：仍要求上游全流 Complete 且没有终止原因。
- 已记录上游/本地异常：两类成功结束帧仍过滤，既有错误补发接管；原错误帧不因候选字段被过滤。
- 不因下游候选结束帧提前设置上游 Complete，也不清除已记录异常。原始字节、事件顺序和写入/刷新成功后的有效交付统计保持原机制。
- 候选级标记仅结束该候选，不承诺全流完成；若其后发生 EOF/读错误，仍按现有异常规则终止结算。

## API、数据模型与配置

无新接口、鉴权级别、公开字段、数据库表/列/索引、迁移或配置项。保留 `IsStreamSuccessEvent` 的布尔含义，内部增加帧粒度分类。修复受已有 `stream_error_setting.enabled` 及成功响应门控控制；非流式、未成功握手和专用 Claude 处理器不改变。

## Main Chain Impact

同步：在既有写出点执行有界帧分类、读取当前会话状态；不做 JSON 重编码，不增加正文副本或响应缓存。不额外等待其他候选完成。异步日志与资金结算保持现有机制，无新后台任务或外部调用。

## Shared Resource Audit

只读请求局部的 StreamSession 状态，沿用现有会话短锁；解析在会话锁外，锁不跨网络写入/刷新。StreamWriter 自有锁仍按原逻辑串行写入。无新增或变更 Redis、DB、连接池、工作池、跨请求缓存或文件句柄。

## Concurrency Analysis

30k/100k RPM 下新增 DB/Redis 调用、协程及跨请求锁均为 0；帧扫描维持原有有界复杂度，不新增全流缓存。非结束帧无需为成功过滤读取会话锁，结束帧沿用一次短锁。容量压测仍由部署环境执行，不以单元测试替代。

## 测试与实施步骤

先添加失败回归测试，再修改分类与过滤，最后重跑公共流式、渠道回归和根构建。

测试覆盖：候选先后结束、不同候选编号、同帧混合候选、最后正文与工具参数、空 delta 的结束帧、候选结束后上游失败、全流结束提前输出仍被拦截、错误帧原样透传、HTTP 分批读取及下游分片写入、非活动会话原样转交。断言尾帧原字节和刷新后有效交付，而非仅检查 Write 返回成功。

## 实施结果

已完成并复核，仅两个业务文件调整：`relay/common/stream_session.go` 增加结束粒度分类，`relay/common/stream_writer.go` 按粒度决定是否过滤。既有布尔接口保持原含义，上游协议完成状态、异常分类、预扣/结算和诊断保存条件均未修改。

- 测试先行：原实现下，正文尾段、混合候选、空 delta、工具参数、Gemini 混合候选等新增夹具均复现整帧丢失；修复后全部通过。
- 新增 6 组回归：公共分类、HTTP 观察/分片写入、成功终止保护、候选完成后异常、非活动门控、OpenAI 实际格式处理器。OpenAI 夹具同时覆盖原数据转发/强制格式化、正常完成/后续读错误及原用量选择规则。
- `go test ./relay/common ./relay/channel/openai -count=1` 通过；本轮新增回归连续重复 20 次通过。
- `go test ./relay/... ./logger ./common ./router ./setting/operation_setting ./i18n` 通过；根模块 `go build ./...` 通过。
- 重跑原审计复现，结果变为 `lost_tail=false`、`choice0_finish_missing=false`；该候选的尾段和 finish_reason 均已原样出现于下游。
- 复核原错误事件仍放行、全流成功终止提前输出仍过滤、已记录异常后的候选/响应成功终止仍过滤。没有新增 I/O、共享资源、JSON 重编码或等待其他候选的缓存。
- 中文注释与本轮实际行为一致；修改文件通过 UTF-8 无 BOM、gofmt 及差异空白检查。未更改前端、relaykit、依赖、数据库或部署，未提交 Git。

本轮未运行真实数据库集成、真实上游调用和负载压测；当前 CGO 关闭，未运行 race 检测。本次不调整上游观察器既有的候选完成判定/预读时序，也不修复 A2 Realtime 轮间异常缺少 error 事件；重跑其本地复现仍得到诊断为 true、未补 error，与本轮范围一致。
