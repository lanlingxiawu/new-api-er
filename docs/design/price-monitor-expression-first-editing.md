# 价格巡检：表达式计费的简易图形改价

日期：2026-10-20（同日按代码审计修正）；2026-10-22 按用户验收意见重构改价窗口并更新本文。
状态：已完成三轮交互修正、浏览器验收与香港测试服部署；当前功能以第 3—6 节为准，历史调整与验证记录见第 10—12 节。

用户补充：改价时允许将原有价格转换为动态计价，转换行为参考系统设置中的模型定价功能。2026-10-22 用户验收意见：现在只有表达式计费，改价窗口不得再出现计费方式切换；打开时自动转换为表达式；编辑面只需模型定价中的可视化编辑功能；消除一层套一层的多余边框。

## 1. 目标与范围

2026-10-23 价格矩阵展示回归：移除单元格内直接渲染 `differences` 的原始区间／变量／左右价格红字列表，避免技术字段和大量明细撑高整行。保留正常价格、差异高亮、亏损徽标与场景比较提示；后台差异计算、筛选、改价风险确认及 API 字段不变。新增实际价格矩阵渲染回归，验证输入／输出价格和亏损提示仍可见，原始差异行不再展示。无新增共享资源、数据库行为或 relay 调用。

价格巡检中的「改价」「批量改价」统一生成表达式定价。用户通过模型定价同款可视化编辑器完成操作，无需编写表达式、理解倍率或输入 JSON。

本次入口以用户截图中的价格巡检为准。复用现有模型定价可视化编辑器、转换和保存能力，不重做整个模型管理页面，不批量迁移未操作的模型。已有模型管理员覆盖优先于内置默认。

## 2. 代码核对及现有差异（实施前现状）

1. 改价表单曾存在「按 token ↔ 按次」计费方式切换，会写 `billing_mode=ratio`、`ModelPrice` 或静默空表达式；进入规则卡片时将按次金额乘一百万作为裸常量。这些隐式写入路径已全部移除。
2. `price-monitor-pricing-draft.ts` 的旧模型改价与批量操作曾写 `ModelRatio`、`CompletionRatio` 等字段；现已全部改为表达式，旧字段写入分支已删除。
3. 管理端工具链曾不支持 `fixed()`/`image_count`/`img_cr`（relay 引擎早已支持）：`CompilePreview`/`RunAt` 白名单拒绝、`DescribeEditor` 无法描述、规则文档 writer 不含对应标识符、巡检试算无法评估。已按第 2.1 节清单扩展。
4. 2026-10-13 的无代码规则文档曾将 fixed/image_count 等写为当时不支持；该文档的能力说明已同步更新。

### 2.1 管理端扩展清单（已落地，不改 relay 执行语义）

1. `CompilePreview` 的 `validatePreviewAST` 白名单与 `RunAt` 运行时环境（`pkg/billingexpr/preview.go`）：放行 `fixed()`，提供 `image_count`（默认 1，范围校验同 relay）与 `img_cr`，并镜像 relay 的 `validateFixedPricingTree` 不变式。
2. `DescribeEditor`：新增 `kind:"fixed"` 与分支可选 `unit`/`price`/`quantity` 字段；img_cr 的 custom 闸门保留（其巡检往返由前端本地解析器承担）。
3. 规则文档 writer 白名单（`pkg/billingexpr/rule_document.go`）：放行 `fixed`/`img_cr`/`image_count`。
4. 巡检试算（`/api/price_monitor/evaluate`）从场景请求体 `n` 提取 `image_count`。
5. 前端本地解析器（`price-monitor-expression-form.ts`）接受 fixed 家族与 `img_cr`，供草稿操作和变更摘要使用；实际巡检可视化编辑能力由共享编辑器决定，按张数量表达式等不支持结构按第 3 节保护。
6. `AnalyzeStandard` 与巡检比较器不扩展：含 `fixed()` 的模型在风险预览中保持「未知覆盖」，沿用现有确认流程。

## 3. 默认界面（2026-10-22 重构后）

点击「改价」直接打开编辑窗口。表达式是唯一计费方式，**没有计费方式切换**。

布局保持扁平，无盒中盒：

- 多模型时顶部为模型标签；转换失败或转换中的状态以 Alert/状态行呈现。
- 参考来源与价格摘要放在默认收起的参考价格区域，不再有每个单元格的参考价格列和嵌套表格。
- 编辑面复用模型定价的 `TieredPricingEditor`，巡检启用 `pricingOnly`：只显示可视化档位、价格项和条件，隐藏模式选择、源码、模板、估算器及请求倍率编辑区。原有请求倍率规则原样保留，模型定价页保持完整编辑能力。
- 顶部“新增档位”在兜底档位前插入并列条件档位，支持连续新增、编辑、删除。一次展开一档；新档自动聚焦阈值，首次不标红，离开输入区后显示校验结果。缓存价格区不保留空控件占位，不增加包围边框。
- 保存、取消、恢复默认固定于窗口底部。未完成档位阻止保存、批量调整和切换模型，并提示先补全当前档位；删除未完成档位后可继续操作。关闭时清除会话快照，重开重新读取价格和版本。
- 试算（用量示例）默认收起；价格变更摘要、批量调整、风险预览、恢复默认沿用现有能力。

编辑器能力边界：标准 token 线性、长度/时间条件分支、`tier(name, fixed(金额))` 按次价格均可视化往返；`* image_count` 与探测条件（param/header）等不可视化结构在巡检显示前往模型定价编辑的提示并禁用保存，原表达式保持不变。

## 4. 单模型、旧配置与批量操作

### 打开即自动转换

会话打开时，对每一个旧配置模型（effective 含 `ModelRatio`/`ModelPrice` 等旧字段且非 `tiered_expr`）自动调用 `/api/option/model_pricing/convert`，静默应用为表达式草稿：保留全部已配置字段（旧字段作为历史配置），仅更新 `billing_setting.billing_mode="tiered_expr"` 与 `billing_setting.billing_expr`。无确认弹窗；最终保存仍走巡检风险预览与原子保存。

- 有界并发（每批 5 个）；请求绑定模型与当前完整草稿，响应返回时按指纹复核草稿未变，过期结果丢弃并记录问题。
- 返回 `unsupported_reason` 或失败时保留原配置，模型列入问题清单并显示具体原因；清单内模型被选中时保存保持禁用，可移除后重新预览；不手写近似表达式、不回退为倍率改价。
- 完全未定价的模型（effective 为空）不触发转换，走编辑器新建表达式路径。
- 主动「恢复默认」仍走现有 reset 契约（撤销管理员覆盖），并清除该模型的转换问题。

### 已有表达式

读取 configured/effective 后填入可视化编辑器；只改价格与规则，保留版本、`|||` 附加规则及未编辑文本（编辑器按源码区间局部写回）。无操作时原文保持不变，不把 effective 自动写回 configured。未知版本或未支持结构保留原价，提示具体原因，不允许静默降级。

### 批量改价

支持「统一设置单价」（价格项含 token 变量与每次价格 `fixed`）「上涨百分比」「下调百分比」。所有目标先完成表达式草稿（自动转换），再应用操作。

提交前逐模型显示修改范围及前后价格；不同单位、缺价、不支持转换和不能安全局部编辑的模型显示明确原因。存在未解决项时整批不保存，可明确移除这些模型后重新预览；不静默跳过。无实际变化的模型不提交。批量整体涨跌保留全部条件、固定价格及请求倍率含义；不能对含 `fixed(` 的不可解析表达式包乘。沿用最多 100 模型限制。

## 5. 数据流与 API 契约

读取选中模型 → 保留 configured/effective/version → 自动转换旧草稿 → 可视化编辑 → 风险预览 → 原子保存 → 刷新巡检。

不新增路由。以下管理接口沿用 `AdminAuth`，读配置另需 `SystemSettingsView("billing.model-pricing")`，写入、转换、预览与试算需 `SystemSettingsEdit("billing.model-pricing")`：

| 接口 | 请求与响应关键字段 |
| --- | --- |
| `GET /api/option/model_pricing?model=…` | 返回 `entries[{model_name, configured, effective, version}]` 等现有字段 |
| `POST /api/option/model_pricing/convert` | `{model_name, pricing}` → `{effective, expression?, unsupported_reason?, cache_write_mode?, billing_details?}` |
| `POST /api/option/model_pricing/preview` | `{model_name, pricing, rule_document?, source_hash?}` → `{pricing, effective, editor?, rule_document?, …}` |
| `POST /api/price_monitor/evaluate` | `{model_name, expected_version, pricing, source_keys, scenarios}` → `{results, coverage, checked_at}`（不返回 `context_version`；试算结果不参与失效判定） |
| `POST /api/price_monitor/preview_price` | `{checked_at, changes}` → `{context_version, models}` |
| `POST /api/price_monitor/apply_price` | `{checked_at, context_version, changes, force_below_floor, acknowledge_unknown}` → `{updated_models, refreshed}` |

`changes` 继续为 `{model_name, expected_version, pricing, reset?}[]`。注意后端保存是整模型替换（`replaceModelPricing` 先删后写，不做合并），字段保留完全是客户端责任：草稿必须始终携带全部 configured 字段，包括转换后保留为历史配置的旧倍率／旧按次字段。

点击保存自动预览；无风险直接保存，有亏损或未知覆盖时沿用现有确认。草稿、报价上下文或模型版本变化后，旧确认立即失效。保存后只刷新相关查询；刷新失败明确显示“已保存，巡检结果待刷新”。

## 6. 业务边界与错误处理

- 非负有限金额，保留小数精度；空值、0、继承值各自独立。非法数字在对应字段提示，不提交上一个有效值冒充当前输入。
- 长度阈值为有效整数；测试 271,999、272,000、272,001 的实际分支。
- 解析失败不创建默认免费模板；版本和 `|||` 附加规则不得因局部改价丢失。
- 切模型保留各自草稿；异步响应绑定模型与草稿版本，过期结果丢弃。保存中禁用重复提交；失败保留输入，冲突给出重载操作并保护草稿。编辑器存在无效字段时保存禁用。
- 试算采用真实管理接口，不模拟费用。样例结果不代表所有请求都保本，未核验来源继续显示未知。
- 后端沿用 `ApiErrorI18n` 并记录底层错误；新增用户文案同步前端七语言，后端新增消息同步中英文。

## 7. 数据模型、配置与子系统

不新增表、列、索引、迁移、配置项或持久化图形规则 JSON。表达式仍为唯一计费事实来源，继续经 `setting/` 与统一模型定价服务保存到现有 options。

既有模型版本、原子事务、价格发布与缓存失效机制保持原契约。预扣和结算继续使用原有快照；修改价格仅按已有发布行为作用于后续请求。模型定价页、价格巡检和实际计费读取同一配置。

## 8. Main Chain Impact

所有新增描述、转换和表单编译仅在管理请求中执行；relay goroutine 无新增同步调用，也不新增异步观察者。表达式使用已有执行语义，不修改 `relay/`、结算归一化或扣费算法。没有新增 relay 执行分支，因此无新增热路径功能开关。

### Shared Resource Audit

| 资源 | 与 relay 共享情况及约束 |
| --- | --- |
| options、模型定价版本及现有定价发布状态 | 沿用现有管理事务和发布路径；不新增查询种类、锁或写频率，不逐按键保存 |
| 已发布价格内存快照 | relay 现有读取路径；图形编辑只持有浏览器草稿，保存后按原机制发布 |

### Concurrency Analysis

30k 及 100k RPM relay 流量下，新增 DB=0、Redis=0、锁=0、goroutine=0／请求。已有表达式执行成本不因图形界面改变；描述与编译保留现有大小、深度和分支限制，不为降低编辑门槛放宽运行复杂度。

前端仅加载选中模型，试算按需展开。数字输入期间局部更新草稿，后端预览在提交时调用。无新增大表查询或索引要求。

## 9. 实施与验证计划（已执行）

1. 两档示例改输出价格，其他价格、272,000 阈值、标签及前后分支不变；覆盖边界 ±1。
2. 单／批量、按 token／按次操作最终都提交表达式模式；不新增旧倍率价格写入。固定价格使用 `fixed()`，单位与实际试算一致；按次模型保存表达式后重新打开仍在可视化界面往返。按张数量表达式保留原文，巡检提示前往模型定价编辑；管理端试算覆盖图片数量。
3. 已有表达式原文无改动往返一致；新增图片缓存、跨档新增变量、显式零和省略变量不混淆；保留请求规则、版本、固定价格和数量因子。
4. 打开自动转换成功与不支持两类；不支持无数据库写入，旧字段保留；未选模型不变。草稿变化使转换结果失效；最终保存才生效。
5. 批量混合单位、缺价、百分比 -100/0/正值、非法数；失败不部分保存。
6. 草稿变化使旧风险确认失效；并发版本冲突、过期响应、保存失败和保存后刷新失败均可恢复。
7. Vitest 覆盖实际表单交互：打开即转换并可编辑、不要求写公式；类型检查、lint、生产构建及七语言检查。
8. 管理描述／编译扩展运行相关 billingexpr/controller/model 测试，不调用真实 AI。本设计不修改数据库行为，无需三库实例验证。

## 11. 第二轮截图反馈修复
