# 请求日志单条下载

状态：用户已确认，代码已实现并部署到香港测试服务器；真实浏览器点击下载待验收。

## 目标与范围

在请求日志详情弹窗增加“下载 JSON”按钮，将当前日志保存到本地，便于排障和分享。首期范围为当前单条日志，格式为 JSON；不包含批量下载、按筛选导出、ZIP 打包或使用日志导出中心改造。

用户已确认目标为请求日志，即此前支持多用户名筛选的请求/响应正文。入口复用 `web/src/features/request-logs/request-log-detail-dialog.tsx`。存储与权限背景参考 [请求日志存储设计](request-log-memory-index-disk-store.md)，具体字段及脱敏行为以当前代码为准。

## 数据流

1. 用户从列表打开详情，现有 `getRequestLogDetail(id)` 调用受权限保护的详情接口。
2. 详情成功加载后启用下载按钮。按钮使用当前详情数据，不再次请求接口。
3. 浏览器以 `JSON.stringify(data, null, 2)` 序列化为 UTF-8 JSON，通过 Blob、临时链接和 download 属性发起下载。
4. 文件名使用 `request-log-<id>.json`，仅使用数值 ID，避免用户名、URL 或 request ID 中的特殊字符影响文件名。
5. 下载触发后等待 1 秒，在 finally 中移除临时链接、释放 object URL 并恢复状态；即使弹窗期间卸载，异步函数仍执行清理，避免长期持有大正文。

## 文件内容

导出当前接口返回的单条详情对象，不包括 success/message 外层响应。保留原有字段，包括日志 ID、时间、用户、模型、渠道、方法、URL、状态、request ID、耗时、流式标识、请求/响应体积，以及请求头、请求体、响应头、响应体和可选 `headers_withheld`。

请求头和正文仍为接口中的字符串，不把其中 JSON、SSE 或文本再次解析成嵌套对象，不丢弃空字符串、不去除截断标记、不补写未采集的内容。下载反映已保存的日志，不能还原采集时已截断的部分。耗时保持毫秒，时间戳保持接口原始单位。

## API 契约与权限

不新增接口，复用 `GET /api/request-log/:id`：成功返回 `{success:true,data:RequestLogItem}`，业务错误沿用现有错误响应。

路由位于 `router/request-log-router.go`，现有 AdminAuth、请求日志 view 和 view_detail 权限保持不变。无详情权限的用户不能通过本按钮发起详情读取。导出只使用已经获准返回给当前用户的数据：

- 超级管理员保留当前详情接口允许返回的原始内容。
- 其他管理员保留服务端已执行的凭据遮蔽；无法可靠遮蔽的头部继续缺失，并保留 `headers_withheld`。
- 当前控制器对非超级管理员的请求/响应正文还会执行凭据文本遮蔽，下载不得改为读取原始磁盘文件来绕过该处理。

前端没有新的权限判断来源，不改上游托管的认证、HTTP client、API re-export 或错误映射文件。

## 数据模型与配置

不新增表、列、索引、迁移、配置参数或开关。无需数据库兼容分支或大表查询。文件仅下载到用户浏览器，不在服务器新增导出文件或导出任务。

## 交互与错误处理

按钮放在详情弹窗的操作区，复用当前 Button、Dialog 及临近弹窗的操作区布局，不压缩正文或遮挡关闭按钮。

加载中、接口失败、没有详情或详情 ID 与当前弹窗 ID 不一致时禁用下载；避免切换日志时下载旧记录。点击后用下载中状态防止重复操作，创建 JSON/Blob 或触发下载异常时使用国际化 toast 提示重试，并在 finally 恢复状态、清理资源。

浏览器只能确认下载已发起，不能确认用户是否最终保存文件；如展示成功提示，文案必须是“下载已开始”，不能声称已保存。文件已被服务器清理但当前详情仍完整可见时，允许下载已经加载的内容。

新增按钮及反馈文案覆盖 en、zh、zh-TW、fr、ru、ja、vi。实施前遵循项目 i18n、shadcn-ui 和 React 技能，保持源文件 UTF-8 无 BOM。

## Main Chain Impact

本改动不进入 AI relay goroutine。JSON 序列化、Blob 和下载触发全部在浏览器按需执行；没有新增同步/异步 relay 操作，也不新建服务器 goroutine。

## Shared Resource Audit

| 资源 | 影响 |
| --- | --- |
| 数据库和 Redis | 下载按钮无新增访问 |
| 日志内存索引与磁盘文件 | 仅沿用打开详情时已有的一次读取，点击下载不再读取 |
| 服务器连接池、worker 池、文件句柄 | 无新增使用 |
| 浏览器查询缓存 | 读取当前详情对象，不改变缓存键或权限语义 |
| 浏览器内存、Blob、object URL | 单次下载产生与单条日志大小相关的临时副本，下载发起后释放资源，不聚合多条日志 |

不增加 relay 侧 DB/Redis 调用、锁或 goroutine；不改变计费、日志采集、多用户筛选、保留数量及后台清理。单条日志较大时浏览器 JSON 序列化可能产生短暂卡顿，测试需覆盖接近当前采集上限的正文，不据此扩展为无上限批量导出。

## 验证计划

这是浏览器单条下载操作，不新增测试框架。编码前确定下列用例，实施后运行 `bun run typecheck`、`bun run lint` 和受影响文件格式检查；浏览器验证：

1. 普通 JSON、中文、换行、引号、纯文本和 SSE 正文下载后可被 JSON 解析，四段原始字符串与接口逐字一致。
2. 两个不同用户名的日志分别下载，文件名、日志 ID、用户名、request ID 与正文一一对应，不混用缓存。
3. 空字段、截断内容和 `headers_withheld` 不被伪造或丢弃。
4. 加载、接口错误、日志不可用时按钮禁用；切换详情不下载上一条。
5. 无详情权限无法取得下载数据；非超级管理员下载保持遮蔽，超级管理员与其详情可见内容一致。
6. 连续下载、关闭弹窗、大正文及下载异常后状态恢复，临时链接和 object URL 正确释放。
7. 七语言按钮、反馈文案及移动端布局正常。
