# 价格巡检：无需编写公式的完整定价操作

日期：2026-10-13。状态：已实现并部署香港测试服，接口及资源验收通过；浏览器交互验收限制见文末。替代上一版将复杂操作留在“高级表达式”中的交互方案，一次完整交付，不分期。

## 目标与范围

用户只需选择条件、填写价格和检查试算；创建、编辑、批量调整、复制、对比、试算和保存均不要求输入公式、变量或 JSON。价格巡检内移除表达式编辑框、“转换表达式”“重新解析”等技术操作。底层继续使用现有计费表达式作为唯一持久化事实，不改变计费执行引擎。

当前实现只对标准长度阶梯提供数字表单，复杂规则要求原文编辑，试算请求上下文要求 JSON。这是本次必须解决的缺口，不能仅改文案或折叠编辑框。

“功能不能少”的验收基准是当前引擎及管理端实际支持的能力和已有配置。2026-10-22 更新：管理端预览、描述和试算已支持 `fixed()`，试算支持 `image_count` 与 `img_cr`；巡检已改用模型定价的可视化编辑器，原独立规则卡片已移除。按次图形编辑可往返，按张数量表达式等可视化未支持结构保留原价并提示前往模型定价编辑，不得伪装成按 token。请求规则后缀保留原文，不在巡检内编辑；任务插件表达式仍按实际支持能力处理。当前完整行为见[表达式改价设计](price-monitor-expression-first-editing.md)。

## 操作界面

默认只展示三块：计费方式（按用量／按次）、基础价格、费用试算。输入和输出首先出现，缓存、图片、音频通过“添加收费项”加入，明确显示美元／百万 token 或美元／次。未填和免费 0 分开；没有参考报价也能手填。

“添加特殊规则”按实际需要展开，不将所有选项同时堆到页面：

| 选择的需求 | 用户填写 | 页面自动说明 |
| --- | --- | --- |
| 长输入使用另一套价格 | 输入长度、各项单价 | 输入超过 200,000 token 时使用以下价格 |
| 特定时段优惠 | 时区、日期／星期、起止时间、优惠百分比 | 周一至周五 09:00–18:00，费用下调 10% |
| 特定请求使用另一套价格 | 参数或请求头名称、判断方式、值、各项单价 | 参数 quality 等于 high 时使用以下价格 |
| 满足条件调整费用 | 条件、上涨／下调百分比 | 符合此条件的请求费用上涨 20% |
| 最低收费／最高收费 | 每次金额 | 每次至少收取／最多收取指定美元金额 |
| 其他既有计算规则 | 选择取值、计算动作、数值及作用范围 | 按中文步骤显示计算过程，无源码输入 |

条件支持“全部满足／任一满足／不满足”、嵌套条件组、比较、包含、存在判断。收费项选择使用输入、输出、缓存等全称，保留现有使用计价输入量而非上下文总长的旧条件语义；新增长度规则默认使用完整输入长度。参数支持字符串、数值、布尔值、空值，数值与字符串不混淆。

规则顺序明确显示：价格分支首先匹配，未命中使用基础价；费用调整明确按顺序或嵌套关系作用，不能将任意旧嵌套运算改成简单相加。提供复制、删除、排序；改变优先级前展示受影响范围。跨午夜时段、周末、月日与时区均由表单生成条件。

不将内部 AST 原样显示给用户。常用条件和动作显示业务卡片；仅对实际存在的复杂组合按需展开“更多计算选项”，支持现有加减乘除、余数／幂、取绝对值、上下取整、取较大／较小值等计算节点，节点名称采用自然语言。无公式编辑作为兜底。

## 旧配置与功能保留

后端完整解析现有合法规则，将条件、分支、取值、金额操作、版本、标签和全部变量映射为结构化描述；新规则由相同结构生成。无修改时原文保持字节不变；修改后保持未修改分支及归一化语义。不可达分支不得静默删除；规则顺序、短路判断、缺失参数、大小写及单位不能漂移。

标准表单只是一种呈现方式，底层描述必须容纳当前受限管理预览接受的完整语法。不能对复杂配置只提供整体涨跌而取消局部编辑。未知版本或当前引擎无法识别的配置保留原值，显示原因且禁止覆盖；这属于兼容异常，不能宣称已经完成转换。交付前按当前引擎白名单及既有配置分类证明覆盖，不能以未支持卡片替代已支持功能。

缓存／图片／音频首次独立计价会改变全式变量集合：操作时要求填齐受影响分支或明确继承规则，展示影响及样例，不自动补零。按次／按量切换展示将替换的规则并保留未提交草稿。价格未配置、免费、继承价格分别显示。

批量设置金额、涨跌百分比、参考价复制、原价／新价对比继续保留，明确作用模型、收费项和条件范围。不同范围或单位不能直接覆盖。缺价不能参与百分比运算，逐项提示补填。

## 试算与保存

试算全部表单化：完整输入量、输出量、缓存／图片／音频等收费量、来源格式、时间和时区；请求参数和请求头采用名称／类型／值的可增删行，支持嵌套参数路径及结构化对象／数组输入，不要求 JSON。从规则条件预填需要测试的字段名，不伪造值。

展示命中规则、当前费用、新费用、差额，并支持自动生成阶梯边界和条件命中／未命中样例。有限样例不等于完整保本，未知比较仍显示未核验。

保存继续自动风险预览，亏损和未知覆盖分别确认；确认绑定完整草稿、报价上下文和模型版本。失败保留草稿，冲突提示重新加载，取消时保护未保存输入，保存成功后的刷新错误不得误报保存失败。

## 数据流与 API 契约

读取现有模型配置 → 后端完整 AST 描述 → 前端业务卡片 → 结构化草稿编译及验证 → 现有试算／风险预览 → 原子保存。

沿用 GET/PATCH `/api/option/model_pricing`、POST `/api/price_monitor/evaluate`、`preview_price`、`apply_price` 的现有权限和写入契约。扩展 POST `/api/option/model_pricing/preview`：

- 读取请求 `{model_name, pricing}` 返回原有 effective/editor，同时增加版本化 `rule_document`，携带 source_hash、源版本及稳定节点 ID。
- 编译请求 `{model_name, pricing, rule_document, source_hash}` 返回生成的候选 pricing、完整验证结果与更新描述；仅生成草稿，不写数据库。source_hash 必须匹配请求的基准原文，结构版本和节点类型严格校验。
- 读取和编译共用 AdminAuth + SystemSettingsEdit(billing.model-pricing)，不新增公开接口。最终保存仍执行模型版本校验、全量草稿校验和事务提交。
- AST 联合类型覆盖字面值、用量、参数、请求头、时间取值、条件组、分支及计算动作；字符串由后端安全转义，不拼接用户输入为代码。

后端现已实现完整 rule_document 和反向生成。实际文档结构为 `{schema_version:1, expression_version:1, source_hash, root}`；节点 `{id, kind, value?, name?, operator?, args?}`。kind 支持 number/string/boolean/null/usage/unary/binary/conditional/call，数字以十进制字符串传递以保留整数精度；条件分支 args 顺序为条件、命中值、未命中值。所有节点重新验证，不允许提交原始源码片段。HTTP 编译请求上限 2 MiB，最终表达式仍限 32 KiB。没有引入任何仅前端有效的计费规则。

## 数据、配置与错误处理

无新增数据库表、迁移、索引或配置参数；只读写既有 options／版本，结构化文档属于临时编辑状态，不新增第二份定价存储。解析及编译沿用 32 KiB、4096 节点、64 深度等限额，限制对象／数组和条件节点总量，禁止无限展开。

表单错误定位到规则、条件和字段，说明如何修改；后端使用既有 ApiErrorI18n，底层细节写日志。新增前端七语言及后端实际 locale 同步，保留完整错误处理。加载失败可重试，过期请求结果丢弃，不逐键请求服务器。

## Main Chain Impact

所有转换发生在管理界面和管理请求中。relay 同步新增 DB=0、Redis=0、锁=0、goroutine=0；后台也不注入 relay 任务。不修改计费引擎、归一化、结算或在途快照。

### Shared Resource Audit

沿用 options、定价版本行、已有报价快照和管理 API 的 DB 连接池；relay 读取既有内存定价快照，不新增热路径访问。描述和编译使用隔离预览，不写 relay 编译缓存。不增加 Redis 命名空间、连接池、共享 map 或 worker；写入复用原子定价服务，不增加协调锁。

### Concurrency Analysis

30k／100k RPM relay 请求新增工作均为零。管理端转换有大小、深度及节点上限；批量仍受 100 模型限制，试算最多 32 场景／10 来源。解析按加载及显式操作执行，输入时本地维护结构，提交前统一校验。
