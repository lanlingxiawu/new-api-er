# 审计安全监控：完整排查与 IP 情报

2026-11-16。用户已确认“全部进行实现，不要分期”，随后确认多数据源自动轮换及免费自建方案。本文件记录统一实现；后端字段、迁移和清理合同见 [后端设计](audit-security-triage-backend.md)，独立提供端见 [自建设计](audit-ip-selfhost.md)。没有部署生产或启用真实外部情报查询。

## 目标与范围

让排查者直接判断发生了什么、为何命中、证据是否完整、谁正在处理，以及去哪里回查。一次实现覆盖：证据修复、规则快照、状态与负责人、通知决策、关联查询、历史访问、保留与归档、导出、多数据源 IP 情报及三个新增规则。不增加自动封禁。

## Existing Logic and Related-Path Findings

以下是实施前沿调用链核验的问题及对应改动，不能将旧行为理解为当前合同。

| 路径 | 核验结果及处理 |
| --- | --- |
| `rules.go` → `store.go` | 检测按资源隔离，旧合并键没有资源；登录成功后的失败证据被 action 相等条件过滤。四类规则版本升级，合并加资源/版本，选择成功事件及最新 19 条有效失败。 |
| `main.go` → `model/audit_query.go` → 控制器 | 启动已有独立审计池，旧控制器依赖可能未初始化的 worker 池。历史读取/处理改用控制面池，前端不再以检测 ready 阻断读取。 |
| `store.go`、`notify.go` | last_seen 是事件时间，不能代表人工处理或迟到事件的修改时间。增加 updated_at/revision，详情分别检查告警版本和投递变化。 |
| 告警清理路径 | 原 last_seen 清理会删除未结案；先删 actions 再重算关闭资格不可重入。改用 closed_at、持久进度及删除状态。 |
| `monitor.tsx`、事件卡片 | 处理表单原在长详情底部，成功/失败、角色、资源、原因等未展示。处理移至列表，详情只读并显示已记录参数。 |
| `ip_risk.go`、IP 单元格 | 原因原先仅显示第一条且有截断。增加可分页原因入口，保持事件权限及覆盖说明。 |
| 生产环境文档 | MySQL 主库、PostgreSQL 独立日志库。通过 event_id/request_id/IP+时间在应用层回查，禁止跨库 SQL JOIN。 |

## 数据流与完整生命周期

管理/认证操作 → 既有异步采集 → worker 归一化 → 规则匹配 → 同事务保存告警、逐次 finding、证据/IP 关联及通知决策 → 独立控制面读取 → 列表处理 → 动作和更新时间/revision → 结案/归档 → 从关闭时间判断保留期 → 有界、可重入清理。

成功登录的公网 IP 可由 worker 查询情报，全局开关默认关闭。按缺失能力、优先级、预算、缓存和熔断选源，同优先级轮换，失败切换。缺字段、过期或缺精度不补造结论。异地判断要求可靠坐标与精度，同时超过距离及速度阈值；迟到事件不覆盖较新基线。

未结案和关闭时间未知的历史记录保守保留。系统重开清除关闭/归档时间，保存触发事件与检测时间。清理持久保存资格和推进位置，处理跨批删除、重启、人工操作、重开、发送中的通知；精确状态转移见后端设计。

## 前端实现与交互

### 列表与处理

`security/monitor.tsx` 使用项目 Combobox、CompactDateTimeRangePicker、StaticDataTable、主题 token 及既有错误/加载组件。筛选包含视图、资源、状态、规则、级别、历史口径、时间、IP、操作者和负责人。历史口径与具体资源互斥，归档只提供关闭状态。条件变化重置游标。

列表展示风险、规则/编号、操作者、资源、触发次数、最大命中数、首次/最近事件、负责人和状态。`alert-status-cell.tsx` 的列表面板支持状态、备注、负责人、结论、归档/取消归档；保存使用打开时的 version，冲突保留输入。只有 manage 权限可操作。

| 视图 | 排序与范围 | 翻页 |
| --- | --- | --- |
| 全部告警 | ID 倒序，默认近 24 小时且不含归档 | before，固定同一 start/end |
| 最近命中 | last_seen/id，最多 20 条 | 不分页，整页刷新 |
| 最近更新 | updated_at/id，修订号绑定筛选 | cursor；修订变化重查 |
| 未结案 | open/investigating，默认全部时间 | before |
| 已归档 | 已关闭且归档，默认全部时间 | before |

ID 分页不是冻结快照。主动刷新默认时间窗推进到最新，手工范围保留。导出在 ID/未结案/归档视图可用，最多 100 条；其他视图不悄悄转换查询语义。

### 只读详情与证据

`security-alert-dialog.tsx` 展示概要、历史口径/证据缺口、逐次快照、最多 20 条事件样本、关联、处理历史、通知。finding 展示当时阈值/窗口、统计维度、版本、触发事件、主体、IP、请求 ID、来源和截断。旧记录无快照时明确无法还原，不用当前配置补历史值。

事件卡片复用普通审计全部字段及值映射，展示成功/失败、操作者/角色、资源/目标、影响数、原因、请求 ID、IP 和完整已记录参数。零和 false 保留，未知不冒充正常，匿名不冒充用户 0，自定义模型名/协议字段保留原值。新增界面文案覆盖七种语言。

详情每 15 秒读取，缓存按用户/角色/权限/告警隔离。版本或投递改变时提示刷新，保留阅读快照和滚动位置；主动刷新记录加载时间。处理时间线显示系统/人工来源、状态前后、负责人、结论和事件/检测时间。通知显示创建/更新/发送/下次重试及原因；没有历史记录不猜测。

### 关联与 IP

`security-relations.tsx` 按账户/IP/请求分页加载 SecurityRelation，不能当作 Alert。默认围绕最近事件前后各 15 天，所有页固定窗口；仅代表保留数据，不称完整攻击链。关联告警在同一弹窗切换，可返回原告警。

`ip-risk-reasons.tsx` 分页展示某事件全部可见 IP 风险原因，沿用日志库验证及 RiskCoverage。普通归属地仍按悬停查询，不冒充地理异常检测。回查原始审计切换“全部”页签并重置游标，优先 request_id，否则 IP，加事件前后 15 分钟。源日志可独立到期，空结果不证明无行为。

### 设置与健康

设置复用 Root 二次验证；结构化编辑数据源、能力、优先级、每日预算、HTTPS 地址、精确私网主机及密钥，最多 20 个。预置 ipapi.is、proxycheck.io、IPinfo Lite、自建兼容接口。稳定 ID 支持留空保留旧密钥，显式清除才删除；配置解析失败阻止保存。

健康区分检测、认证采集、历史存储、扫描进度、丢弃与覆盖。数据源显示当日预留量、上限（0 不限）、熔断和可读错误；仅 Root 可见，不输出 endpoint/key。容量明确有界/截断，显示未结案、归档和关闭时间未知。

## API、鉴权、数据与设置

精确合同见 [后端设计](audit-security-triage-backend.md)。读接口保持 AdminAuth + audit:read + audit_security:read，认证证据 Root-only。actions/archive 另需 manage 与浏览器身份，export 另需 audit_security:export 与浏览器身份。所有列表/详情/关联/导出保持相同可见性。

新增或扩展 alerts 视图/筛选、findings、actions/archive、assignees、relations、ip-reasons、export、健康和脱敏设置。数据模型包含 closed_at/updated_at/归档/负责人/结论、finding、清理进度、数据源配额及地理基线。索引覆盖合并、时间读取、资源/历史口径和关联；Root 与非 Root 分别检查 EXPLAIN。配置纳入 setting 包，后台编辑复用现有 options API，不新增环境变量业务开关。

## 错误与边界

- 查询失败提供重试；无权限和不存在不泄露对象存在性。非法组合不默默更换筛选。
- 写入防重复提交，冲突保留输入；设置 proof 绑定原始值。
- 关联、导出、证据和容量均有界并标范围；revision 失效不伪装空页。
- 密钥不回显、不进入日志/审计/导出；HTTPS、禁重定向、解析后 SSRF 校验，私网仅精确主机放行。
- IPinfo Lite 国家信息、自建无可靠精度坐标不能单独支撑异地判断；VPN/Tor 信号不等同恶意。

## Main Chain Impact

主 AI 转发 goroutine 新增 DB、Redis、HTTP 和 goroutine 调用均为 0。采集复用既有有界队列，新增检测和第三方调用在 worker；管理 API 使用独立审计池，情报使用独立 HTTP transport。不修改凭据判定、计费、渠道路由或流式响应。

## Shared Resource Audit / Concurrency Analysis

独立监控表/缓存/池不供 relay 访问，不新增共享 Redis 命名空间。负责人查询只做有界用户读取，不修改用户表或持有业务写锁。物理 CPU/I/O 仍共享，因此周期预算、缓存、外呼、超时和清理批量均有限制。按 100k RPM 主链计算，新增每请求 DB/Redis/锁/goroutine 为 0。自建端独立容器/文件卷/固定 worker，无网关数据库连接。

前端覆盖历史读取、固定窗口/游标、列表处理/冲突、权限、只读详情、完整参数、数据源密钥、关联/IP 原因分页。自建端覆盖鉴权/公网输入/大小、过期未知、Tor、坐标、更新失败保留及真实 WSGI HTTP。

## 联合评审决策

与 Kimi“审计方案”交叉评审并共同实现。关键结论：last_seen 不是更新时间；Root 查询不能假设 visibility 前缀索引覆盖；旧样本不能重建完整历史；通知更新独立检测；未结案不能按最后事件时间删除；跨批清理不能依赖即将删除的 actions。此前分期和无新列过渡建议已撤销，按完整生命周期实施。
