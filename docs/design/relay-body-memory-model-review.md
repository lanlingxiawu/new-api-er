| 来源 | 具体意见 | 裁定与验证 |
|---|---|---|
| Qwen | reader panic 时以 err 判断清理会漏掉磁盘资源 | 采纳，改为成功移交所有权标记；panic 回归先失败后通过 |

| Kimi、Copilot | distributor 包装丢失容量 sentinel，错误返回 400 | 采纳，JSON、非 JSON、MJ 保留原分类；回归复现 400 后修复为 503/body_cache_capacity |
| Copilot | 中途关闭治理后继续读取/写入会放开旧预算 | 采纳，存储操作与文件租约携带创建时快照；内存读取及磁盘写入切换配置测试先红后绿 |

## 分歧与处理

| 意见来源 | 意见 | 裁定及依据 |
|---|---|---|
| Qwen 首轮 | 当前稿仍承诺无限兜底和永不 OOM | 不采纳：它把“原方案错误、不能承诺”的否定句误读为现方案承诺；已反馈，第二轮更正 |
| Qwen / Copilot | SDK 前置读取、内部重试、解码工作区需要明确预算契约 | 采纳。AWS 实际 SDK mock transport 测试证实完整缓存 4MiB；标准 Retryer 一次调用可以发起三次 503 尝试 |
| Qwen 第二轮 | Base64 解码膨胀两倍 | 不采纳：解码结果通常约为编码长度的 3/4；应计入源、目标及解析副本共驻。Kimi/Copilot也反对虚构固定系数 |
| Kimi | 解压后 Content-Length 仍为压缩长度，预留可能失真 | 采纳。实际 gzip 中间件+存储测试：3087 压缩字节解压 3MiB，通过 2MiB 磁盘预算；重复验证通过 |
| Kimi | 全部关闭 AWS SDK 内部重试 | 不采纳。会改变正常临时错误恢复行为；Copilot第二轮支持只禁止明确本地资源错误的 SDK 重试，并保留错误包装后的可识别性 |
| Copilot | 配置整体校验并不自动保证原子生效 | 采纳。已核查项目现有 `config.Snapshot[T]` 和 `SaveConfigGroup` 事务/Replace 模式，方案要求所有入口整体发布、深复制映射、失败不生效 |
| Kimi / Copilot | 慢上传、无限长请求和慢下游可能永久耗尽在途名额 | 采纳。治理池要求有限上传/执行/写入期限，断连执行仍占原用户名额；不凭空释放尚未结束的工作 |
| Kimi | 全局准入 503 应统一改为 429 才能避免重试放大 | 不采纳统一替换。用户限额 429、全局资源不足 503，提供 Retry-After；两者都不能保证外部客户端不重试。Copilot第二轮支持此区分 |
| Kimi | 超限体仍应保留 quota 渠道禁用分类 | 未纳入首版。完整解析之前不能可靠假设截断片段是真实最终分类；本地超限独立分类、不自动禁用渠道。阈值内完整错误保持既有语义 |
| Kimi | 80% 水位自动异步抓 heap 应成为 P0 | 不采纳默认自动触发。异步并不消除 CPU/磁盘/GC 代价；改为限频、可选诊断，不把没有事故堆快照视为不能修复已复现缺陷 |
| Copilot | “确认孤儿”缺乏跨进程机制 | 采纳。首版不自动删跨重启/其他实例目录；只处理当前实例确认关闭的自有文件。后续跨进程清理另行验证所有权锁与路径安全 |
| Kimi / Copilot | 流式工具参数、thinking、诊断累积不能遗漏 | 采纳为发布门槛。单帧上限不代表累计工作集上限；不擅自丢弃计费所需数据 |

## 讨论后新增或补充的测试

1. `common/body_storage_failure_diagnostic_test.go`：声明长度与真实长度不一致，2MiB 磁盘预算实际写入 3MiB，Windows 三次通过。
2. `middleware/body_compression_memory_diagnostic_test.go`：真实 gzip 中间件压缩长度失真，Windows/Linux 各三次通过；并非仅自制 reader 的假场景。
3. `relay/channel/aws/body_memory_diagnostic_test.go`：标准 Retryer 连续 503，三次内部尝试、三次关闭，Windows/Linux 各三次通过。退避设零，仅验证次数与生命周期，不模拟生产等待时长。
4. 同文件以及 `relay/provider_memory_diagnostic_test.go`：大响应完整缓冲、畸形正文、读取失败、256KiB 边界；详见 [测试记录](relay-body-memory-validation.md)。

这些用例证明现状和潜在风险，没有修改生产实现。尚不能验证“修复后的本地资源错误不会在 SDK 内部重试”，因为该错误类型及 Retryer 改造尚未实现；已列为强制验收。

## 收敛结果

最终建议是清理正确性 → 原子资源租约/有限生命周期/用户隔离 → 多厂商响应和 SDK 治理 → 经测试的对象生命周期优化。首版默认不开新增 spill，不使用无界内存兜底；资源耗尽允许有界拒绝。配置、计费、错误分类及上线门槛见 [最终修复方案](relay-body-memory-governance.md)。

当前状态：方案及验证完成，待用户批准实施；不是生产修复完成或事故根因全部证实。
