# 请求体缓存：页面简要说明与状态建议

状态：用户已回复“编写”批准；2026-10-18 已实现并完成下述本地验证。本方案只补齐现有性能设置页，不改 AI 请求处理、计费或缓存生命周期。

## 目标与范围

- 在现有性能页字段下写一句说明，详细计算依据放在展开内容中。
- 补齐已存在的 `body_governance_enabled`、`body_memory_budget_mb` 配置控件、默认值与类型，目前前端尚未接入。
- 展示当前值、建议值、建议原因、采样时间；数据不足时明确显示“暂无可靠建议”。
- 建议仅供管理员参考。“填入建议值”只更新表单，沿用原保存确认流程后才生效；不自动开关保护、不自动调整运行中的配置。
- 不增加生产压测、自动 GC、自动清理、后台调参任务或新的配置项。

## 页面简短说明（文案含义，实施时国际化）

| 字段/区域 | 简短说明 |
|---|---|
| 请求体缓存 | 暂存请求内容供解析和重试使用，请求结束后释放；不同于模型提示词缓存。 |
| 缓存容量保护 | 限制受管缓存总量；可用容量不足时请求可能返回 503。 |
| 内存缓存预算（MiB） | 按分配容量计量，包含扩容临时空间；不是整个进程的内存上限。 |
| 磁盘缓存阈值（MiB） | 请求体达到此大小时优先落盘；降低阈值可减少内存占用，但会增加磁盘读写。 |
| 磁盘缓存额度（MiB） | 约束本进程受管缓存字节；请为数据库、日志和历史残留文件留出空间。 |
| 系统内存阈值（%） | 按系统内存使用率采样判断；不等于缓存预算，也不能保证避免 OOM。 |
| 清理缓存 | 仅清理本进程已关闭且可确认归属的缓存，不删除仍在使用的文件。 |
| 状态建议 | 根据当前资源估算起始值，仅填入表单，保存后生效。 |

统一使用 MiB/GiB 表示二进制单位，持久化字段名仍兼容现有 `_mb`。

## 数据流与 API 契约

管理员打开页面或点击刷新 → 现有 `GET /api/performance/stats` → 采集资源与读取现有原子计数 → 纯函数生成建议 → 前端显示 → 管理员填入并保存。

沿用 `AdminAuth` 与 `operations.performance` 查看权限；保存沿用对应编辑权限及已有配置分组保存接口，不新增路由、不修改上游所有的 `web/src/lib/api.ts` 等文件。

统计响应新增 `guidance.resources`（采样时间、主机内存 total/available、memory_scope、实际缓存路径及文件系统容量），以及 `guidance.memory/disk/threshold`（value_mib 或 null、reason、below_usage）。`config` 增加现有预算开关及额度。前端将新增字段视为可选，兼容旧响应。Go `Alloc/Sys` 不冒充主机总量/可用内存。

现有页面只在打开、保存及部分操作后刷新；首版沿用该模式并提供显式刷新，不增加自动轮询和共享历史队列。“动态”指随最新状态重新计算，不声称具有历史峰值或趋势预测能力。采样超过 30 秒即标为过期并禁止一键填入，刷新后再评估。表单修改缓存目录后，原目录的磁盘建议失效，保存新路径并刷新后重算。

## 建议规则与边界

以下比例是可解释的保守起始策略，不是经过生产容量验证的最优值，也不承诺没有拒绝或 OOM。使用整数字节运算，统一向下取整，不能因最小值钳位而向上突破安全余量。

1. 内存候选：`min(有效总内存 / 10, 当前受管内存预留 + 有效可用内存 / 4)`，向下取整到 16MiB。小于 16MiB 时不给可应用数值，提示资源不足。有效容量必须考虑实际 cgroup 限额；首版不新增复杂 cgroup 解析器，发现容器/受限环境或不能确认容量范围时不给内存数值，只展示说明。实施时测试资源识别失败必须降级，不能按宿主机容量猜测。
2. 磁盘候选：令 `保留空间=max(2GiB, 文件系统总量/10)`，`新增余量=max(0, 可用空间-保留空间)`；候选为 `min(文件系统总量/10, 当前受管磁盘预留+新增余量/4)`，向下取整到 64MiB。无新增余量或候选不足现有合法输入下限时，不提供可应用值。指标必须对应实际缓存目录所在文件系统；统计失败、路径未确定时不提供数字。
3. 候选低于当前预留：标记“当前占用高于建议额度，降低可能增加新请求拒绝”，不误导为立即释放内存；新旧请求使用各自配置快照，调低不是即时回收。
4. 落盘阈值不伪装成精确最优值：仅在内存预算接近耗尽（预留达到预算 80%）且磁盘有余量时，展示“可试用 1MiB 并观察磁盘延迟”。未采集 I/O 延迟，必须标明需验证；不自动开启磁盘缓存，也不因失败计数增加就盲目扩大额度。
5. 不根据单次快照自动推荐系统 CPU/内存/磁盘百分比阈值。先解释含义，保留管理员原值，避免套用所有机器统一 70% 的未经验证建议。
6. `body_capacity_rejects` 是预算预留失败尝试数，成功回退也可能增加；页面称“预算预留失败次数”，不称“请求失败数”。缓存条目数不等于在途请求数，缓存命中次数不等于模型提示词缓存命中。
7. 缺字段、零总量、负数、溢出、采集失败、受限容量未知或过期，返回不可用原因而不是伪造 0 或默认建议。只支持单实例建议，不拿某台机器的状态替整个集群调参。

## 配置保存与业务交互

现有页面逐键保存，不适合同时开启保护和设置正数预算：首版接入项目现有分组保存流程，使两者整体校验、持久化、发布。必须先核实其鉴权和字段白名单，不另造保存 API。

建议生成本身不持久化。用户保存后仍执行现有性能配置校验。启用保护必须有正数内存预算；禁用保护不误显示“已保护”。数据库无新增表、列、索引或迁移。计费、退款、渠道选择与上游 usage 不变。

## Main Chain Impact

新增计算及资源读取仅在管理接口执行，relay goroutine 同步/异步均无新增工作。建议失败不改变 relay 响应。只有管理员明确保存已有保护配置后，按已批准的容量保护语义影响后续请求。

## Concurrency Analysis

30k/100k RPM relay 流量下，新增 relay DB/Redis 调用、锁和 goroutine 均为零。每次管理员显式刷新运行常数复杂度计算及少量本地系统读取；不维护请求历史。配置写入仍在管理面已有互斥和事务内完成。
