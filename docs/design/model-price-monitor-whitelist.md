# 模型价格巡检白名单设计

状态：已实现并部署测试服务器。

## 1. 目标与范围

为现有模型价格巡检增加“免检模型白名单”，让管理员排除不需要巡检的模型。最终巡检集合为：

```text
模型广场模型 - 免检模型白名单
```

- 白名单为空：检查模型广场全部模型，保持现有行为。
- 白名单非空：名单内模型不检查，其余模型广场模型继续检查。
- 官方价格仍对最终巡检集合中的每个模型强制比较。
- 启用渠道仍只对自身 `Channel.Models` 中已启用、且属于最终巡检集合的模型比较。
- 不支持通配符或正则表达式，采用模型名精确匹配，避免误选相似模型。
- 本功能只控制巡检范围，不改变模型广场展示、渠道配置、平台定价或中继请求。

## 2. 配置与数据模型

在 `setting/price_monitor_setting.PriceMonitorSetting` 增加：

```go
ModelWhitelist string `json:"model_whitelist"`
```

配置键为 `price_monitor_setting.model_whitelist`，继续通过现有系统设置接口和 ConfigManager 持久化，不新增数据表、JSON 快照字段或独立保存接口。

选择字符串而不是数组，是为了与当前逐项系统设置保存方式保持一致。输入支持逗号、换行两种分隔方式；运行时执行去首尾空格、过滤空项、去重，模型名保持原始大小写并按精确值匹配。

## 3. 数据流

1. 定时任务读取 `PriceMonitorSetting.Normalized()`。
2. 从 `model.GetPricing()` 获取模型广场模型集合。
3. 解析 `ModelWhitelist`，从模型广场集合中删除名单内模型。
4. 若排除后集合为空，本次运行记录可读错误并保留上一份成功快照，避免用空结果覆盖有效数据。
5. 加载启用渠道及各渠道启用模型集合，抓取渠道与官方价格。
6. 仅对最终集合生成字段级差异与价格矩阵，保存最新 JSON 快照并刷新动态密码。
7. `/results`、`/inconsistencies`、`public_query` 无需新增参数，自动返回白名单生效后的最新快照。

## 4. 管理后台交互

在“价格巡检”设置卡中增加“免检模型白名单”多行输入框：

- 占位提示：每行一个模型，也可用逗号分隔。
- 辅助说明：留空检查模型广场全部模型；名单内模型不参与巡检。
- 保存时只做格式归一化，不静默添加不存在的模型。
- 保存成功后，新白名单在下一次定时巡检或手动“立即检查”时生效；不会修改当前快照。
- 页面只展示配置文本，不一次性加载庞大模型选项列表，避免大数据量下多选组件卡顿。

## 5. API 契约与鉴权

不新增接口。沿用 AdminAuth 下现有设置读写接口：

- 读取：现有 scoped system options 返回 `price_monitor_setting.model_whitelist`。
- 保存：现有 `PUT /api/option/`，请求键为 `price_monitor_setting.model_whitelist`。
- 状态：`GET /api/price_monitor/status` 的 `config` 增加 `model_whitelist`，供后台刷新后显示一致配置。

公开分享接口不返回白名单配置，避免泄露无关管理配置。

## 6. 边界与错误处理

- 重复名称、连续分隔符、首尾空白：解析时归一化并去重。
- 大小写不同：视为不同模型，遵循现有模型 ID 语义。
- 白名单包含非广场模型：忽略该项，其余广场模型继续巡检。
- 白名单排除了全部广场模型：本次巡检失败，保留旧快照；后台状态显示“免检白名单已排除全部可巡检模型”。
- 白名单配置更新不主动触发外部网络请求；管理员可点击“立即检查”即时生成新快照。
- 所有用户可见错误继续使用现有 i18n 规则，不返回内部错误细节。

## 7. Main Chain Impact 与共享资源审计

该配置仅由后台巡检 goroutine 和管理设置页面使用，不进入 AI 中继主链路。

- DB：仍只使用 ConfigManager 已有 options 存储，没有新表和新查询模式。
- JSON 文件：继续覆盖现有 `price_monitor/snapshot.json`，不新增文件。
- 内存：每次巡检临时建立白名单集合，规模与模型数量线性相关；任务结束后释放。
- Redis、连接池、中继 goroutine：无新增访问或占用。

- 非空白名单排除名单内模型，并保留其余广场模型。
- 大小写精确匹配。
- 无交集时不覆盖旧快照并记录运行错误。
- 官方仍覆盖最终集合全部模型；渠道仍只覆盖自身启用模型。
