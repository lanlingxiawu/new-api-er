# Realtime 工具定义输入估算修复

## 已确认目标与范围

按本轮审计推荐修复受管 Realtime 路径的一类计量回归：正常后续轮次缺少上游 usage 时遗漏工具定义输入；客户端部分 session.update 省略 tools 时误清空已有工具配置。仅修改新流式流程，保持非流式、开关关闭、未成功握手及 HTTP 非 200 的原路径。

## 当前问题与推荐方案

- 新处理器只在客户端消息上调用旧输入计数器，遗漏了上游 response.done 的工具计数分支。
- 正常完成且最终选择 estimated 时，复用 CountTokenRealtime 的 response.done 分支：后续轮次每个工具按 8 + CountTokenInput 计入文本输入。保留首轮不追加工具定义的既有口径；在本轮用量选择后才将 IsFirstRequest 置为 false。
- 工具计数同步更新选定输入总量、文本输入明细、总 token、估算提示量及诊断估算映射，再合并到连接账本并调用既有预留方法。确认用量（包括显式零）优先，不叠加估算。
- 仅显式携带非 nil tools 的 session.update 更新工具配置；省略/null 保留，显式 [] 清空，非空数组替换。沿用旧 DTO 与计数算法，不扩大为新的会话配置解释器。
- 未正常完成的异常轮次仍按现有异常计费矩阵选择确认/已交付估算/零用量，本次不为此类轮次新增工具定义估算。重复 response.done 保留原透传与账本去重行为。

## 数据流与既有系统交互

客户端 session.update 原样写入上游并维护连接局部工具状态 → 上游消息原样写入下游 → 正常 response.done 选择用量 → 必要时恢复工具定义输入估算 → 同步累计到连接账本/既有资金预留 → 连接结束后既有流程执行最终结算和日志入队。不增加实际扣款次数，不采集客户端请求正文。

## API、数据模型、配置、权限与错误处理

无新端点、表、索引、迁移、依赖、配置或公开字段。继续使用 stream_error_setting、成功握手门控及 RootAuth 诊断接口。原始响应和错误事件保持逐字节透传；估算明细沿用已有诊断字段与权限。资金预留失败继续已有处理，原生上游 error 的补发规则不变。

## Main Chain Impact

同步新增工作仅在正常结束且选用估算的后续轮次发生，调用既有工具文本计数器。上游帧已经成功写给下游才执行，未增加首字或帧聚合等待；同一连接后续消息仍会等待该次 CPU 计数完成，成本随工具定义长度增长，不宣称完全无延迟。确认 usage 的轮次及普通 delta 不执行新增工具计数。异步日志与统计沿用已有队列，无新增任务。

## Shared Resource Audit

工具列表与账本为连接局部内存，单个处理器所有者维护，不引入跨请求锁或新缓存。复用旧 CountTextToken 的 tokenizer 缓存/模型估算配置，只读既有数据；不改变其初始化与锁策略。既有资金会话预留目标随正确输入量调整，调用次数不变；其 DB/Redis 访问方式不变。新增 DB 表、Redis 命名空间、连接池、工作池、文件句柄、goroutine 均为零。

## Concurrency Analysis

在 30k/100k RPM 下新增 DB/Redis 调用与 goroutine 为零。正常结束轮次中，仅缺确认用量且配置工具的后续轮次增加 O(工具定义总长度) 的旧计数器开销；帧大小沿用既有 8 MiB 限制，不缓存每轮完整输出。tokenizer 内部计算可能产生临时分配，复用既有缓存但不新增长期工具 token 缓存。预留、结算及日志队列频率保持原状；本地回归不替代生产吞吐/p99 压测。

## 风险、可选项与验证

- 估算不代表供应商确认账单，本次保留旧首轮边界与工具定义格式，不改历史 tokenizer 算法或音频定价。
- 单元回归覆盖首轮/后续、无工具/多工具、usage 缺失/null/正数/显式零、异常无交付、异常已交付及客户端断开；验证输入细分、总量、诊断和预留目标一致。
- 本地 WS 回归覆盖多轮工具保留/清空/替换、部分更新、重复结束帧及确认/估算混合；断言上下游实际帧原样传输、每轮预留一次且处理器不执行最终扣款。
- 使用 httptest 与内存资金替身，不调用供应商或真实资金。执行相关 Go 测试、根构建、gofmt、UTF-8 无 BOM 和差异检查。
