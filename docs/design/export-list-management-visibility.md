# 导出列表管理可见范围

日期：2026-10-26
状态：用户已确认并要求开始实现；功能已实现，验证记录见文末。

## 目标与范围

- 管理员（含普通管理员和超级管理员）默认看到所有人的使用日志导出任务，包括管理员、员工及客户自助导出，可切换仅看本人。
- 员工看到本人发起的员工导出，以及当前归属自己的客户发起的自助导出。客户归属使用 `users.inviter_id` 和普通用户角色，与现有客户管理一致。
- 普通用户仍只看到自己的自助导出。
- 本方案的“所有”指保留期内的全部使用日志导出任务，提供翻页，不再固定只返回最近 20 条。不合并充值、佣金、成本台账等独立导出系统，不恢复已过期历史。
- 管理员可下载、取消和删除全部使用日志导出任务，包括其他管理员、员工及客户创建的任务。该授权包括 Root 创建的导出文件；下载文件不做按访问者重写，可能包含创建时导出的 Root 专属字段，这是用户明确要求的管理员全量文件管理权限。
- 员工通过独立的“允许员工管理客户导出”开关获得当前所属客户自助任务的下载、取消和删除权限，默认关闭；关闭时仍可查看客户列表。本人发起的员工任务维持原有操作权限。返回能力标识控制按钮，服务端独立校验。
- 导出列表提供服务端组合筛选：创建者、客户、导出来源、输出模式、任务状态、创建时间及任务 ID。筛选作用于保留期内全部可见任务，不限于当前已加载的一页。

相关设计：`usage-log-export.md`、`usage-log-export-unification.md`、`employee-customer-log-export.md`。列表与管理授权以本文为准。

## 已核对的当前行为

- `GetLogExportJobs` 只有 `all=true` 且为 Root 才读取全局任务索引；其他情况读取本人索引，固定取 20 条后再按路由过滤。
- 员工路由只显示本人员工任务，不显示客户自助导出。详情与操作共用 `loadOwnedLogExportJob`，不能直接放宽该函数导致操作权限一并扩大。
- 任务在 Redis `logexport:*` 下保存，文件写入执行节点的系统临时目录；不是长期归档。
- `log_export_setting.job_ttl_hours` 默认 24，支持 1–720 小时。每次任务状态保存重设 Redis TTL，因此成功任务通常从完成时开始计时；普通读取和下载不续期。
- 任务过期后接口无法取得任务，下载失效。磁盘孤儿文件由 `CleanupOrphanLogExportFiles` 清理，现有调用点为管理员/自助新建任务流程和启动恢复流程；没有固定周期清理。物理文件可能超过配置时间才删除，Redis 不可用时也不会执行清理。
- 设置入口为系统调优的使用日志导出设置中的任务保留时长。这里只确认代码默认值，未读取线上服务器的实际配置。

## 数据流与生命周期

登录请求 → 路由认证及员工导出资格校验 → 校验筛选参数并根据路由确定可见范围 → 按创建时间和创建者缩小 Redis 候选范围 → 有界读取任务并应用组合筛选 → 批量复核候选客户当前归属 → 投影允许展示的任务字段及操作能力 → 返回列表与游标 → 前端展示及翻页。筛选条件始终与权限范围取交集，不能覆盖权限条件。

任务创建、后台扫描、生成文件、结束、取消、下载和到期清理沿用现有流程。客户转移后，旧员工不能继续查看该客户自助任务，新员工可查看该客户仍在保留期内的自助任务。每次列表及详情请求都复核当前归属，不信任前端传入的员工 ID 或客户清单。

本人发起的历史员工任务保持可追踪；员工下载本人任务继续受现有模板、客户归属及开关检查限制。客户自助任务必须满足 `IsSelfExportFor(job.UserID)`，不能把客户曾任管理员时生成的文件当成自助任务。

管理员管理权限按当前访问者的启用状态及管理员角色校验，不再以任务创建者的当前角色、员工状态或模板启用状态代替访问者授权。员工对客户自助任务的每次下载签发、实际下载/续传、取消和删除，都校验当前员工资格、管理开关和客户归属；转移客户、关闭开关或停用员工后，后续请求立即按当前状态拒绝。已传出的字节无法撤回。

未结束任务支持取消，终态任务支持删除，只有已完成且文件可用的任务支持下载。删除影响原创建者与其他查看者的任务列表及文件，操作前明确提示；不删除原始日志或客户数据。

## API 合约

不新增公开接口，不改变认证基础文件。复用以下路由：

| 接口 | 权限与行为 |
| --- | --- |
| GET `/api/log/export/jobs` | `AdminAuth`；默认全部，`scope=mine` 仅本人；兼容旧 `all=true` |
| GET `/api/user/employee/export/jobs` | `UserAuth` + `EmployeeExportGuard`；默认本人及当前客户，`scope=mine` 仅本人员工任务 |
| GET `/api/log/self/export/jobs` | `UserAuth`；固定本人自助范围，拒绝扩大范围 |
| GET 上述路径下的 `/:job_id` | 应用与列表一致的查看权限；读取别人任务时返回受限的管理视图 |
| DELETE、GET `/:job_id/download-url` | 管理员入口允许全量任务操作；员工入口在管理开关开启时允许当前客户自助任务操作，本人员工任务沿用现有权限；自助入口固定本人 |

列表增加 `cursor` 和 `limit`（默认 20，上限 100），非法范围或游标返回本地化参数错误。响应保留原 `jobs`、`enabled`、`max_range_sec`，增加 `next_cursor`、`has_more`；每个任务增加 `can_download`、`can_cancel`、`can_delete`。任务创建者继续使用已有 `user_id`、`username`。

### 列表筛选契约

三个列表入口复用筛选参数解析，但由各入口限定可选范围：

| 参数 | 规则 |
| --- | --- |
| `creator_id` | 正整数，精确匹配任务创建者；管理员可选全体创建者，员工只可选本人或当前所属客户，自助入口仅允许本人 |
| `creator_keyword` | 创建者名称关键词，去除首尾空格后最多 64 个字符，按任务保存的创建者名称做普通字符串包含匹配；不支持正则或 SQL 通配符 |
| `customer_id` | 正整数，精确匹配自助任务所有者，或员工任务快照中的客户 ID；员工只能指定当前所属客户 |
| `source` | `admin`、`employee`、`self`，缺省为当前权限范围内全部；按任务类型标记分类，不按创建者今天的角色分类 |
| `mode` | `detail`、`summary`、`both`；历史空值按 `detail` |
| `status` | `pending`、`running`、`ready`、`failed`、`canceled`；缺省为全部。已过期任务记录不存在，不提供虚假的“已过期历史”选项 |
| `created_after`、`created_before` | Unix 秒，分别限定任务创建时间下界与上界，均含边界；可单独提供，均提供时要求下界不晚于上界。与文件包含的日志时间范围明确区分 |
| `job_id` | 完整任务 ID，精确查找；仍验证其他筛选条件与访问权限，不允许猜测 ID 绕过范围 |

不同字段按 AND 组合。空值表示不限制，非法枚举、负数、超长文本或反向时间范围返回参数错误，不静默忽略。客户筛选只匹配具有可靠客户 ID 范围的自助/员工任务；管理员按任意日志条件生成的混合任务，不能凭用户名片段或“全部用户”推断包含某客户。界面在客户筛选旁说明这一范围。

创建者与客户筛选优先复用已有受权限约束的可搜索用户/客户选择器；关键词搜索也可独立使用，不要求先加载全部用户。不得为了填充筛选项一次拉取全体客户或读取日志表。若需新增选项接口，应在实现前补充其路由、权限、分页与查询验证，不使用无权限的通用用户列表。

游标绑定规范化后的筛选条件、访问者、入口范围和排序方式；切换条件须从首页开始，不接受把旧游标用于另一组条件。游标使用 AES-GCM 随机 nonce 加密和认证，密钥从既有 `common.CryptoSecret` 按导出用途派生，不向员工暴露扫描中遇到的无权查看的任务 ID 或时间。多节点沿用既有共享密钥配置。服务端仍逐页复核当前角色与客户归属，不能信任游标中的权限快照。

返回标准 `{"success":true,"data":{...}}` 包装。详情沿用任务数据结构及能力字段。跨用户只提供管理需要的创建者、类型、状态、时间、进度、数量、大小及安全摘要；不返回本地路径、内部错误或完整内部任务快照。员工视图不返回管理员筛选与诊断元数据；管理员按本方案具有完整导出文件的下载权，列表摘要不需要展开文件内容。

读取他人列表/详情的权限与文件操作权限分开。客户端按钮只是展示，服务端操作仍须独立验证。下载 URL 的外部响应形状不变，Redis 令牌内容升级为版本化结构，记录任务 ID、实际下载者 ID、入口范围和分片，而非把任务创建者当成下载者。实际兑换与每次 Range 续传均重新检查下载者当前账号、角色或员工资格以及范围；下载名额按实际下载者计数。使用 `common.*` 编解码。

旧格式令牌仅按原本的创建者授权语义验证，不获得新跨用户权限；令牌过期与续传窗口保持原值。权限降低、开关关闭和客户转移后，已签发的新令牌也不能绕过检查。不能在签发时校验一次后永久信任令牌中的角色快照。

## 数据模型、查询与索引

不新增 SQL 表、列或迁移。新增一个由现有设置系统持久化的权限开关；任务仍在现有 Redis 记录中存储，展示字段在响应时计算，不把当前权限固化进任务。下载令牌使用版本化载荷，兼容现存短期令牌。

复用全局有序集合 `logexport:jobs` 和本人集合 `logexport:user:jobs:*`。按创建顺序倒序分页，游标包含排序位置与任务 ID，覆盖同时间戳任务的稳定排序；兼容旧任务时间精度。Lua 在现有有序集合上按分值/成员二分定位，锚点被删除时仍能继续；至多读取 201 个候选 ID（其中一个用于判断后续页），批量读取至多 200 个任务。读取时删除当前索引中已过期的成员，防止后续请求反复扫描残留。

明确指定创建者时优先使用对应的创建者有序集合；创建时间边界使用有序集合分数范围裁剪。状态、来源、模式、名称关键词与客户快照条件在有界任务元数据中匹配，不创建每个筛选组合的缓存或全局索引。完整任务 ID 查询直接读取单个任务，再验证权限与其他筛选条件。所有路径保持每次最多 200 个候选，不能因筛选稀疏无限读取 Redis，也不能先把第一批截成一页再在浏览器过滤。

员工跨客户列表从全局索引读取有界候选，仅检查合法客户自助任务及本人员工任务。每次最多检查 200 个候选，使用一次有界 `id IN (...)` 查询获取候选客户的 `id`、`inviter_id`、`role`；使用现有主键索引，不扫描所有客户或日志表。游标按最后实际检查的候选推进，避免“先取 20 条再过滤”使任务永久不可见。稀疏结果允许空页带下一页游标，前端提供继续加载，不误报全部为空，也不自动无限请求。

对新列表查询在 SQLite、MySQL、PostgreSQL 上验证归属筛选及执行计划。任何实际需要的索引变更必须补充三库迁移验证后再实施。

## 配置与文件保留

新增 `log_export_setting.employee_customer_manage_enabled`，默认 `false`，由现有设置 API 保存。在使用日志导出设置中展示“允许员工管理客户导出”，说明开启后在职员工可以下载、取消及删除当前所属客户的自助导出。依赖既有员工导出总开关和员工资格；关闭本开关不收回原有本人员工任务权限。管理员不受此员工开关限制。

本次不改变保留策略，复用 `log_export_setting.job_ttl_hours`。默认 24 小时，上限 30 天；配置更改在之后保存任务状态时应用，不保证追溯调整已有完成任务。

页面说明导出为临时文件、过期后需要重新导出。不要仅用“当前配置 + 完成时间”声称已有任务的精确到期时间，因为任务可能按旧配置设置 TTL。如展示精确倒计时，应使用 Redis 实际剩余 TTL，并在实现时补充相应契约与测试。

定时物理清理、跨节点文件共享、长期历史归档不在本次范围。部署重建清空临时目录可能使文件提前不可用，继续沿用现有文件缺失反馈。

## 交互

- 管理员导出中心默认展示全部，提供全部/本人切换、创建者及任务类型，保留现有任务状态和下载区域样式。
- 员工导出历史增加客户自助任务，区分本人发起与客户发起，并显示创建者。
- 筛选栏复用现有同模块布局：常用的创建者/客户、状态、创建时间直接可见；导出来源、输出模式和任务 ID 放入更多筛选。员工只显示其可用选项，自助入口隐藏无意义的跨用户筛选。
- 创建时间提供今天、最近 24 小时、最近 7 天及自定义范围，默认不额外限制保留期内任务。时间按浏览器本地时区选取并转换为 Unix 时间；日期结束边界包括所选当天，不能遗漏最后一秒的任务。
- 提供“查询”和“重置”，回车可提交文本搜索；重置恢复默认权限范围并清空全部条件及游标。展示当前生效条件，空结果提示调整筛选或重置；扫描尚未结束时提示继续查找，不提前显示无匹配结果。
- 筛选值、范围和分页状态进入查询缓存键；提交筛选、切换范围或重置时清空旧页，避免旧请求较晚返回后覆盖新结果。轮询沿用当前已提交条件，不自动清空筛选。管理员页面通过路由查询参数保留筛选，员工抽屉在本次打开期间保留，不将客户信息写入全局本地存储。
- 按服务端能力和任务状态显示操作；管理员可管理所有任务，员工管理开关开启后提供当前客户任务的下载、取消、删除按钮，关闭时只读。
- 删除确认说明会删除导出任务和服务器上的导出文件，并影响创建者下载。取消和删除期间禁用重复操作，完成后刷新列表；失败提供明确重试反馈。
- 翻页加载期间防止重复提交，失败保留已加载列表并提供重试；范围切换重置游标。只有可见的进行中任务需要轮询，窗口后台时停止轮询。
- 复用同模块现有组件；实际实现前读取对应 UI、React 和 i18n 技能，新增文案覆盖七种前端语言。

## 错误处理与边界

未认证走认证中间件，越权返回 403；参数错误、任务不存在或过期使用现有本地化错误辅助函数，Redis 和数据库错误记录内部原因后返回可操作提示。不把无法读取或无法确认归属的任务当作已授权任务。

覆盖任务在翻页期间过期或删除、同毫秒创建、索引残留、客户转移或删除、员工停用、导出开关关闭、双重角色访问员工入口、Root 任务的普通管理员投影、客户历史特权任务等情况。禁止跨客户泄露筛选与文件信息。

## Main Chain Impact

本次修改管理查询、展示及导出操作授权，中继 goroutine 上新增同步和异步工作均为零，不新增中继中间件、钩子或计费行为。任务生成扫描器、原有节流和并发槽不变。

## Concurrency Analysis

在 30k–100k RPM 中继流量下，每个 AI 请求新增 DB/Redis 调用、锁及协程数均为零。管理列表每次为有界 Redis 索引/批量记录读取，员工跨客户请求至多追加一次客户归属批量查询（另有既有入口资格检查）。不持事务、不使用分布式锁。Redis 与主库连接池仍共享，需靠超时、页大小和前端轮询约束管理负载；这属于设计分析，并非已完成压测。

## 实现前测试设计与验收

先补现有 controller/model 导出测试，后写实现：

1. 权限决策：普通管理员全部可见、Root 全部可见、普通用户仅本人；员工可见本人员工任务和当前客户自助任务，不可见其他客户、其他员工及客户历史特权任务。
2. 操作权限：管理员能下载/取消/删除其他管理员（含 Root）、员工和客户任务；员工管理开关关闭时拒绝操作客户任务，开启时允许当前客户任务，其他客户始终拒绝；原有本人操作不回退。
3. 生命周期与下载：客户转移、员工停用、模板停用、开关关闭、管理员降权/停用、任务过期和删除；覆盖签发后撤权、Range 续传、旧令牌兼容、实际下载者名额及创建者停用后管理员仍可管理；管理摘要不包含文件路径与内部错误，员工不可取得管理员文件，能力标识与服务端结果一致。
4. 分页边界：0/1/20/21/100 条、非法 limit、同时间戳、过期索引、连续无权限候选、空页带游标、翻页期间插入；不遗漏可达任务，不陷入重复游标循环。
5. 筛选：逐字段验证及多字段 AND 组合；创建者与目标客户不同、员工多客户快照、客户转移、历史空模式、创建者角色改变、创建时间两个边界及同秒毫秒精度、错误枚举、超长关键词、非法时间、精确任务 ID 越权、越权客户选择。覆盖匹配任务位于前 200 个候选之后，确保可继续查找；旧游标与新筛选不混用。
6. 前端：默认范围、创建者与类型、查询/回车/重置、时间快捷项、更多筛选、继续查找与真正空结果、权限按钮、旧请求竞态、错误重试及带筛选轮询行为。

## 实现说明

- `model/log_export_management.go` 统一筛选、可见范围、操作能力、游标分页、下载授权和管理操作；控制器保留原路由及成功响应包装。
- 管理员默认全部；员工查看本人任务及当前客户自助任务，操作由独立开关控制。跨用户列表/详情只返回安全摘要，文件仍按创建时的内容下载。
- 下载令牌 v2 记录实际访问者及入口；实际下载直接读取当前账户状态，员工额外复核总开关、档案和客户归属。旧令牌仍限定原创建者。取消/删除遇到 Redis 或文件操作错误时返回失败，不向页面虚报完成。
- 创建者提供名称关键词及精确 ID；客户复用已有 `ExportFilterSelect` 和权限限定的 `/options`，没有增加选项接口或全量用户查询。时间选择复用 `CompactDateTimeRangePicker`，增加最近 24 小时快捷操作。共用筛选组件承载业务条件，通用输入、日期、下拉及删除确认均复用现有封装。
- 管理员筛选使用路由查询参数，员工筛选使用组件状态；React Query 的键包含访问者、入口和筛选条件。分页使用显式继续查找按钮，不因结果稀疏无限自动请求。
- 新增 22 个前端文案，七种语言同步；按 i18n 技能脚本写入并运行同步，随后保持仓库已有排序和转义，避免无关改动。
- 文件保留时长及清理触发方式不变。本次没有解决既有多节点本地临时文件定位问题：跨节点下载仍要求请求到达文件所在节点；删除共享任务元数据后，其他节点残留文件依赖其孤儿文件清理。没有新增跨节点文件传输或长期存储。
