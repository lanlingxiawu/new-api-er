# 原生语音完成校验与图片出站张数修复

## 目标与已确认范围

按本轮审计及用户“按推荐修复”的确认，修复两个新增回归：MiniMax 语音完整 JSON 被通用校验误拒；MiniMax / Ali 图片实际出站张数未同步到完成校验。仅作用于已启用的统一流式流程，不改变非流式、关闭开关、初始非 200 或未收到 HTTP 响应的旧流程。

## 数据流与关键边界

1. 每次流式尝试保存请求模式；完整 JSON 观察同时检查 MiniMax 渠道与语音合成模式，避免其他渠道或聊天接口因含有 `data.audio` 而误判成功。
2. 原生语音要求成功状态和非空音频；可选 `data.status` 若出现须为完成值 2，缺失时兼容既有完整 JSON/URL 响应。JSON 语法、读取错误继续由原观察器处理，不把异常 EOF 变成成功。
3. 保留 MiniMax 原有 hex 解码、音频输出、URL 跳转及正常用量返回；DTO 类型错误和 hex 解码失败在受管路径记录上游原因，再使用已有错误补发和结算矩阵。受管音频写出前覆盖请求阶段的 SSE 占位 Content-Type，跳转前删除该占位头，防止音频误入 SSE 半帧缓存；非受管响应头处理不变。字符数不直接冒充 token，不扩展新的计费单位转换。
4. 图片转换及参数覆盖完成后，按实际协议选择计数字段：MiniMax/标准图片/xAI 为 `n`，Ali 为 `parameters.n`。缺省、null、非法值采用原有完成约束默认值 1，参数合法性仍由旧校验/上游负责。
5. Ali 透传从已解析入口 DTO 的原生 `parameters` 中取 `n`，不重新读请求流、不重新序列化、不改写出站正文；其余透传及实际仍为 multipart 的出站请求保持既有入口张数，转为已知原生 JSON 的表单仍按最终 JSON 同步。每次重试重新同步，未持有上次覆盖值。
6. 最终图片响应仍须达到同步后的期望张数；不足仍为上游异常。原始诊断只在已有上游异常判定下落库，Root 权限、首尾截断、响应头/下游正文规则均不变。

## 接口、配置与数据模型

不新增 API、配置、数据表、列、迁移或索引。沿用 `stream_error_setting`、已有私有诊断结构及 Root 查询接口。请求局部会话增加模式字段；图片计数方法显式接收 JSON 字段路径，所有调用者同步更新。无前端或 relaykit 公共 API 变更。

## 实施步骤与涉及模块

先添加 MiniMax 真实适配器语音夹具、原生图片实际出站参数与响应完整性夹具，运行确认旧实现失败；再修改 `relay/common/stream_session.go`、`relay/common/stream_request.go`、`service/stream_lifecycle.go`、`relay/image_handler.go`、`relay/channel/minimax/tts.go`。新增/修改方法及参数补中文说明，最后回归并核对文档。

## Main Chain Impact

同步操作仅为现有 JSON 的少量字段检查、请求局部模式/整数赋值；音频仍由原适配器一次解码，图片仍按原响应完成时机检查。不新增网络请求、计时等待、整流缓冲或额外请求正文读取。

异步日志和结算持久化沿用现有通路；本次不增加后台工作。

## Shared Resource Audit

无新增 Redis/数据库访问、共享缓存、连接池、worker pool 或文件句柄。修改会话中的请求私有状态，沿用现有短锁，不跨网络 I/O。已有 HTTP 客户端与日志/计费通路的访问次数不变，不引入共享资源竞争。

## Concurrency Analysis

30k / 100k RPM 下每请求新增 DB 调用 0、Redis 调用 0、goroutine 0。语音仅在已有完整 JSON 的观察阶段检查几个字段；图片在发送前解析一个计数字段。请求内增加一个整数，无新增响应副本；不改变正常 SSE 首帧/逐帧发送时机。

## 风险与验证

- 渠道与模式严格限定，不全局放宽 JSON 完整性；不修改原计价策略及参数覆盖行为。
- 语音覆盖 hex、URL、空/缺少音频、未完成状态、类型错误、畸形 JSON、读取错误、客户端写入失败、原始错误，以及非流式/开关关闭隔离。
- 图片覆盖张数增减、删除、null、默认、Ali 原生 Extra 优先、透传及重试；同时验证一张结果的接受/拒绝随最终请求变化。
- 测试只用内存/本地 HTTP，不调用真实 AI 或真实扣款；相关 Go 包回归、根模块构建及既有外部 overlay 的数据库无关流式测试。实际生产容量与数据库集成不由这些夹具替代。

## 实施结果

两个问题已修复，未提交或部署。

- 测试先行复现 MiniMax 正常语音被误拒，以及 MiniMax/Ali 原生出站张数与入口值不一致；修复后同一组夹具通过。
- 实际 HTTP 包装夹具还检出 SSE 占位响应头使音频误进流式半帧缓存，已在受管 MiniMax 音频/跳转写出前修正，不影响非流式及关闭开关。
- 图片覆盖 n 的增减、删除、null、缺省、原生 Extra 优先、字节不变的透传和同 info 多次尝试；以实际出站正文确定预期，再验证一张原生结果的成功/不足判断。
- 语音覆盖正常 hex/URL、类型及格式错误、底层读取错误、空/缺损/中间态响应、原始 SSE error 逐字节单次透传、客户端写入失败、渠道/模式隔离及开关边界。正常与用户断开不持久化原始诊断。
- 新增/修改方法、参数、状态字段已补中文说明；完成对照核查。新增模式是请求私有整数，不增加共享资源或等待。
