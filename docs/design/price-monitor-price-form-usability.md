# 价格巡检：直接填价与可读规则

日期：2026-10-13。
状态：已按用户确认的“简单上手、便于理解”标准完成实现；部署验证记录见第 10 节。
前置实现：[动态计费适配](price-monitor-dynamic-billing-adaptation.md)。本次作为一次完整体验改造交付。

## 1. 问题与目标

代码核对发现，当前弹窗将表达式文本放在数字输入前面，批量选择直接显示 p/c/cr 等变量，试算默认展示 JSON。更直接的缺陷是前端 `expressionPriceFields` 要求存在 `tier(...)` 包装，导致 `p*2+c*4` 和不带 tier 的普通阶梯也无法使用数字表单；后端 AnalyzeStandard 已能识别这些形式，前后端能力不一致。

目标：常见改价只需要认识输入价、输出价、缓存价和适用长度，不需要阅读公式，也不要求先理解倍率与表达式的存储区别。复杂自定义规则保持完整，不通过猜测简化。

## 2. 默认交互

打开模型后直接显示价格表，单位统一显示在表头：USD / 百万 token（按次则为 USD / 次）。默认展示输入、输出及当前已单独计价的分项，其他项目通过“添加价格项”加入；未定价模型直接给出输入与输出的空输入框，空值不自动变成零。

示例仅展示交互，不代表实际模型报价：

| 价格项 | 当前价格 | 新价格 | 参考来源 |
| --- | ---: | ---: | --- |
| 输入 | 2.00 | 可填写 2.20 | 选择渠道或官方报价，填入本项 |
| 输出 | 8.00 | 可填写 8.50 | 选择渠道或官方报价，填入本项 |
| 缓存读取 | 未单独设置 | 添加并填写 | 无参考价时仍可填写 |

- 多阶梯用“输入长度不超过 200,000 token”“输入长度超过 200,000 token”等可读条件展示，显示当前档及其价格，不只显示任意 tier 名称。保留原阶梯名称作为辅助信息。
- 普通定价可添加阶梯；用数字输入阈值，区间连续、无重叠、无空洞。删除阶梯明确展示受影响的范围；不可把删除理解成免费。
- 参考来源紧邻价格表，通过一个来源选择器切换，不再把每个来源整张表顺序堆在主操作下方。来源缺价不禁用填写。
- 修改某个数字只改变该价格；旧倍率模型若存在联动，要将被影响的其他价格一并列入变更摘要，不能只高亮一个字段。受锁定规则限制的价格显示原因和可用操作。
- 普通编辑区不出现 p/c/cr、倍率字段名或 JSON。“高级：查看/编辑表达式”默认收起，只有主动打开时才显示原文。
- 按次和按量切换是明确的定价方式操作，必须先展示会被替换的价格与规则，不能因复制参考价而悄悄切换。

## 3. 批量调整与复杂规则

批量入口用“统一设置价格”“上涨百分比”“下调百分比”，选择项用输入、输出、缓存读取等用户可读名称。操作后展示每个模型的当前值、新值、受影响档位；无价字段不能参与百分比计算，列明需补价项，不自动设成零或静默跳过。

对于完整 AST 能证明是标准线性/长度阶梯的规则，直接提供数字表单，无论是否带 tier 包装。对于请求参数、请求头、时间等复杂规则，展示“自定义定价规则”及能确认的条件摘要；不能确认的部分明确标为自定义。

复杂规则仍可在同一界面做明确的整体涨跌百分比调整，保留原条件与版本，并展示样例费用变化。仅在 AST 能证明某一叶节点价格是独立系数时开放局部数字修改；否则保留高级原文入口，不能伪造可编辑价格。未知引擎版本或本地不支持的语法继续拒绝保存。

## 4. 试算和保存

默认试算为表单：输入 token、输出 token、缓存 token、usage 格式、参考来源。时间固定并显示，可按需修改。请求参数、请求头和原始 JSON 放在高级试算中。结果以“当前费用 → 修改后费用（差额/百分比）”展示，区分本模型与参考来源；样例不宣称完整保本。

底部主按钮为“保存修改”。点击后自动请求现有预览接口：无风险时直接提交；有已知亏损或未知覆盖时弹出简洁确认层，逐项说明涉及哪些价格和未核验来源，再保存。不再要求用户先寻找“预览”按钮来解锁保存；保留独立的费用试算入口。

所有确认绑定完整草稿、报价上下文和数据库版本。确认期间改价后重新校验，冲突保留草稿并提供重新载入；重载前提示未保存内容。保存失败保留输入，已保存但巡检刷新失败单独提示，禁止误报保存失败并重复提交。

## 5. 数据流与 API 契约

读取模型草稿 → 管理端完整 AST 分析 → 生成表单描述 → 用户改数字/阶梯 → 生成并校验候选草稿 → 原有风险预览 → 原有原子保存 → 刷新巡检结果。

复用现有接口及权限：

- `GET /api/option/model_pricing`：AdminAuth + `SystemSettingsView(billing.model-pricing)`，继续返回 configured/effective/version/capabilities。
- `POST /api/option/model_pricing/preview`：AdminAuth + `SystemSettingsEdit(billing.model-pricing)`。保持 `{model_name, pricing}` 请求兼容，在响应 `{effective}` 上新增可选 `editor` 描述：`kind`（flat/tiered/custom）、`schema_version`、有序分支及可读条件数据、价格项、全式 used_vars、无法表单编辑的原因。结构基于管理端 AST，不由前端正则推测；不返回其他模型或敏感设置。
- 表单生成使用明确的标准分支结构，生成的候选表达式重新通过同一后端分析和现有验证。原文无改动不重写；无法完整保持原条件、tier 标记和变量集合时不做自动重建。原始高级编辑改变后，作废旧表单描述，重新解析后再开放数字编辑。
- `POST /api/price_monitor/evaluate`、`preview_price`、`apply_price` 以及模型 PATCH 原子写入契约保持不变。UI 表单负责组装当前已支持的场景字段，不伪造试算响应。

接口已实现 `editor` 描述，包含 source/source_hash、版本、完整变量集合及原始顺序分支。前端只有在服务端分析结果与当前原文一致、且本地受限解析器能够完整识别时才开放数字编辑。局部价格编辑保留原文位置与条件；结构操作检查区间连续性、不可达分支和全局变量集合。普通价格添加阶梯先调用现有转换接口生成草稿，不直接保存。复杂规则保留整体百分比调整和高级编辑，不提供伪造的局部价格表。

## 6. 业务边界

- 显式 0 表示免费，未填表示未配置；未单独计价的分项不能统一描述为免费，也不能无条件声称在所有供应商格式下都计入输入。
- 首次增加缓存/图片/音频独立价格可能改变全式归一化。用跨档价格表一次明确全部档位，不自动补 0；展示影响范围，必要时用 OpenAI/Claude 两套样例说明。
- 不把尾部额外算术、未知函数或自定义条件丢弃后当标准规则处理。完整源码都必须被解析验证，包括不可达分支。
- 改价不改变阶梯条件；改阶梯是单独操作。比较两侧按各自原始 usage 归一化，不共用已扣除缓存的 token。
- 不支持的来源或未知归一化继续显示未核验。来源价格的单位/适用区间不一致时不提供误导的一键覆盖。
- 多模型切换保留各自草稿和校验错误；所有批量错误必须定位到模型、档位和价格项。

## 7. 数据、配置与错误处理

不新增数据库表、字段、迁移或配置项。表达式仍是计费事实来源，不增加第二套可漂移的价格存储。继续使用 options、版本行及现有事务写入。

前端普通错误描述可采取的动作，不直接展示编译器堆栈；技术详情仅在高级区域按需展示经过处理的原因。后端记录底层错误，使用项目 ApiErrorI18n；七种前端语言及需要新增的后端语言一起补齐。加载失败提供重试，试算/保存进行时禁用冲突操作，丢弃过期异步结果。

## 8. Main Chain Impact

新增解析、表单转换和试算仅在管理请求中执行；relay 同步执行新增 DB=0、Redis=0、锁=0、goroutine=0。沿用已实现的动态定价原子快照，不更改实际结算和在途请求快照。

Shared Resource Audit：沿用管理接口读 options/价格版本和已有报价快照；写入仍由统一定价事务服务完成。管理解析不进入 relay 编译缓存。没有新的表、Redis 命名空间、连接池或 worker 池。现有 DB 池共享，表单分析按单模型显式操作调用，输入期间不逐字符查库；批量继续受 100 模型上限保护。

Concurrency Analysis：30k/100k RPM 的 relay 请求无新增工作。管理 AST 沿用 32 KiB、4096 节点、64 深度、128 分段边界，场景继续限制 32 个和 10 个来源。编辑器保持按需加载，隐藏的高级编辑和试算不加载重型依赖，不重复查询所有模型。

## 9. 实施前测试与验收

先增加回归用例，再写实现：

1. 裸线性 `p*2+c*4`、裸三元阶梯、tier 包装、v1 前缀、合法括号与等价乘法顺序均可数字编辑；后端拒绝的完整表达式不进入表单。
2. 未修改原文往返不变；只修改输出价格时输入、缓存、条件及 tier 标记不变；高级编辑后不使用旧的字段位置。
3. 阶梯边界测试 t-1/t/t+1，新增和删除档位无空洞或重复，旧条件未被价格操作修改。
4. 显式零/缺价、跨档新变量、OpenAI/Claude 缓存语义、locked 输出、非默认 token_price_factor。
5. 批量设置和涨跌价正确定位受影响项目；不能把无价字段百分比调整成免费；不支持项明确显示且不部分提交。
6. 点击保存自动预览，风险确认不可绕过；草稿变化使旧确认失效；版本冲突、网络失败、刷新失败、重复点击保持正确状态。
7. 基础试算无需填写 JSON；普通改价无需看到表达式或变量名；窄屏、键盘操作、来源切换和多模型切换可用。浏览器交互验收目前受环境限制，不能将代码检查当作已完成的人工验收。
8. 相关 Go 测试、现有前端纯函数测试、typecheck/lint/build、七语言检查。获批后在香港测试服复用独立账号/模型验收，保留原价格配置；浏览器不可用时明确记录界面验收限制。
