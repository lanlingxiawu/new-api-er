# 价格巡检独立管理菜单与统一授权设计

## 目标和范围

将“系统设置 > 计费与支付 > 模型定价”中的“价格巡检”标签页移出，改为左侧“管理员”分组下的独立“价格巡检”菜单。页面、读取接口、设置保存和立即巡检统一由新的 `admin_menu.price_monitor` 授权资源管理，不再依赖 `system_settings.billing.model-pricing` 权限。

本次只调整价格巡检的管理入口和授权边界，不修改巡检算法、来源抓取、价格换算、快照格式、公开分享页、动态密码规则、定时调度或 AI 转发链路。公开分享地址 `/price_monitor/view` 和公开查询接口保持不变。

## 页面与交互设计

- 左侧“管理员”分组新增“价格巡检”，与“真伪检测”等四字菜单集中排列，路由为 `/price-monitor`。
- 新页面复用现有价格巡检设置区、统计卡、分享信息、筛选区和价格矩阵，不重新设计一套平行界面。
- “系统设置 > 模型定价”删除“价格巡检”标签，保留模型价格、未设置价格模型、第三方 SD2 定价、工具价格和上游价格同步。
- 有查看权限但没有编辑权限的管理员可以查看状态、统计、分享凭据和价格矩阵；设置控件、“保存设置”和“立即巡检”不可操作。
- 没有查看权限时，侧栏不显示菜单；直接访问 `/price-monitor` 跳转到 403；直接调用管理 API 返回 403。
- 页面继续使用现有 Base UI、Tailwind 设计令牌和 `SectionPageLayout`，不新增硬编码颜色或新的布局体系。

### 设置与分享信息弹窗收纳

为减少结果页面首屏占用，将页面顶部的“巡检设置”和“分享页面”两个常驻区块收纳到标题栏按钮弹窗中：

- 标题栏右侧显示“巡检设置”和“分享页面”两个次要按钮，分别使用设置和分享图标。
- “巡检设置”弹窗承载启用开关、巡检间隔、来源超时、官方价格说明、models.dev 开关和免检模型白名单。
- 设置弹窗底部统一放置“取消”“立即巡检”“保存设置”。“立即巡检”继续遵守主节点、运行状态和 `edit` 权限；“保存设置”继续执行二次确认。
- 仅有 `view` 权限时仍可打开设置弹窗查看当前配置，但所有配置控件及写操作按钮禁用。
- “分享页面”弹窗显示只读分享地址和当前访问密码，分别提供复制按钮；弹窗底部保留“打开分享页面”。
- 复制、打开分享页、保存和立即巡检继续沿用现有反馈，不改变接口或权限。
- 两个弹窗均使用项目现有 `Dialog` 组合组件，包含可访问标题；桌面端采用紧凑宽度，移动端限制最大高度并允许内容区滚动。
- 原两个常驻区块删除后，页面标题下直接显示巡检统计卡、筛选区和价格矩阵，结果区获得更多垂直空间。

### 管理员菜单命名与排序

- 原“检测”菜单统一改名为“真伪检测”，前端使用已有 `Authenticity Detection` 国际化键，后端授权目录也使用同一文案键；真伪检测页面标题、渠道行操作和系统任务名称保持同一口径。
- 管理员菜单按中文名称长度重新排列：先放二至三字菜单，再放四字菜单，避免“真伪检测”和“价格巡检”夹在短名称菜单之间。
- 最终可见顺序为：`渠道 → 模型 → 用户 → 兑换码 → 订阅 → 真伪检测 → 价格巡检 → 号池节点 → 员工管理 → 业务概览 → 请求日志 → 系统信息 → 系统设置`。
- `号池节点` 继续仅超级管理员可见；`真伪检测`、`价格巡检`、`请求日志`、`系统信息` 继续按各自授权过滤。某项因角色或权限隐藏时，其余菜单保持上述相对顺序。
- 后端授权编辑器中的菜单资源顺序同步调整为：`渠道 → 模型 → 用户 → 兑换码 → 订阅 → 真伪检测 → 价格巡检 → 员工管理 → 业务概览 → 请求日志 → 系统信息`。授权资源标识和既有策略不变，仅调整显示名称与排序值。
- 系统设置中的侧栏模块名称同步使用“真伪检测”，不改动路由 `/channels/detection` 或资源 `admin_menu.veridrop_detection`。

## 统一授权模型

新增资源：`admin_menu.price_monitor`，归入“菜单访问”权限组，包含两个动作：

| 动作 | 用途 |
| --- | --- |
| `view` | 显示左侧菜单、进入页面、读取状态/结果/分享摘要 |
| `edit` | 保存价格巡检设置、手动触发立即巡检 |

授权约束：

- `edit=true` 自动包含 `view=true`。
- `view=false` 时强制 `edit=false`。
- 超级管理员继续拥有全部权限。
- 新资源不默认授予普通管理员，避免将原本属于系统设置细粒度授权的能力扩大给所有管理员。
- 权限编辑器继续从后端授权目录动态读取资源和动作，不在前端复制权限目录。

### 存量权限迁移

主节点启动时执行一次事务迁移，将用户在 `system_settings.billing.model-pricing` 上与价格巡检相关的存量授权复制到新资源：

- 旧 `view` 的显式 allow/deny 复制为新 `view`。
- 旧 `edit` 的显式 allow/deny 复制为新 `edit`；显式允许编辑时同时保证新 `view` 被允许。
- 如果用户已经存在新资源的显式配置，以新配置为准，不覆盖。
- 只迁移 `user:*` 主体，不复制内置角色策略；内置角色策略仍由启动时基线重建。
- 迁移与完成标记在同一事务内写入；失败时整体回滚，下次启动重试。

旧的模型定价权限继续控制模型定价页面及其余价格配置，不因迁移被删除或修改。

## 数据流

### 页面加载

1. 前端路由在加载前检查 `admin_menu.price_monitor:view`。
2. 页面并行请求价格巡检状态和结果矩阵。
3. 状态响应中的 `config` 初始化设置表单，避免再通过通用系统设置接口读取价格巡检配置。
4. React Query 分别缓存状态和结果；现有轮询、筛选和分页行为保持不变。

### 保存设置

1. 前端检查 `admin_menu.price_monitor:edit`，无权限时不提供可操作的保存入口。
2. 用户确认保存后，前端一次提交完整的可编辑价格巡检配置。
3. 后端再次校验 `edit` 权限、字段范围和类型。
4. 后端通过现有 `setting/price_monitor_setting` 与 ConfigManager 保存并发布不可变配置快照。
5. 成功后前端刷新状态；失败时显示现有用户可理解的保存失败提示。

### 手动巡检

1. 前端提交立即巡检请求。
2. 后端校验 `admin_menu.price_monitor:edit` 和主节点条件。
3. 复用现有异步巡检触发逻辑并立即返回。
4. 前端轮询状态，完成后刷新状态和结果矩阵。

## API 契约

管理接口统一位于现有 `/api/price_monitor` 路由组，并先经过 `AdminAuth()`：

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/price_monitor/status` | `admin_menu.price_monitor:view` | 返回配置、运行状态、快照统计和分享凭据 |
| GET | `/api/price_monitor/results` | `admin_menu.price_monitor:view` | 返回筛选、分页后的价格矩阵 |
| GET | `/api/price_monitor/inconsistencies` | `admin_menu.price_monitor:view` | 返回兼容统计与分享摘要 |
| PUT | `/api/price_monitor/settings` | `admin_menu.price_monitor:edit` | 保存价格巡检设置 |
| POST | `/api/price_monitor/run` | `admin_menu.price_monitor:edit` | 触发一次异步巡检 |

`PUT /api/price_monitor/settings` 请求：

```json
{
  "enabled": true,
  "interval_minutes": 360,
  "timeout_seconds": 10,
  "include_models_dev": false,
  "model_whitelist": ""
}
```

响应沿用管理 API 约定：

```json
{
  "success": true,
  "message": "",
  "data": {
    "applied": true
  }
}
```

字段约束继续采用现有配置边界：巡检间隔至少 5 分钟，来源超时为 1 至 120 秒，白名单按现有标准化逻辑处理。参数错误使用 `ApiErrorI18n`；数据库或配置发布失败记录底层错误并返回可重试提示，不向前端暴露内部错误。

以下公开接口保持原授权和契约：

- `GET /price_monitor/view`：公开只读 HTML，继续使用动态密码和 CSP。
- `POST /api/price_monitor/public_query`：继续使用动态密码、限流、请求体上限和禁用缓存。

## 通用系统设置接口调整

- 从 `billing.model-pricing` 的可读写键中移除 `price_monitor_setting.*`。
- 模型定价页面不再读取或构造价格巡检默认值。
- 价格巡检保存不再调用通用 `/api/option/`，避免用户同时需要菜单权限和系统设置权限。
- 超级管理员无 scope 访问通用设置接口的既有行为不变。

## 数据模型、配置和迁移

不新增业务表、字段、索引或价格快照格式。继续使用：

- `setting/price_monitor_setting.PriceMonitorSetting`
- ConfigManager 中的 `price_monitor_setting.*` 配置键
- `price_monitor/snapshot.json`
- `casbin_rule` 中现有授权策略结构

唯一持久化变化是新增授权资源对应的 Casbin 策略，以及一次性权限迁移标记。不引入数据库方言相关 SQL，迁移使用 GORM 事务和冲突忽略，兼容 SQLite、MySQL 与 PostgreSQL。

## 关键边界和错误处理

- 仅有旧模型定价查看权限的用户迁移后只能查看价格巡检，不能保存或立即巡检。
- 仅有旧编辑允许的异常存量策略迁移后会同时获得新查看权限，满足“编辑必含查看”的约束。
- 新资源已有显式规则时不被迁移覆盖。
- 查看权限撤销后，菜单、路由和所有读取 API 同时失效；仅隐藏菜单不能替代后端鉴权。
- 编辑权限撤销后，前端立即禁用修改入口，后端仍作为最终授权边界拒绝写请求。
- 非主节点调用立即巡检继续返回现有国际化错误。
- 状态或结果加载失败继续保留可重试反馈，分享密码不写入日志。

## 与现有子系统的关系

- 模型定价：保留原页面和权限，只移除价格巡检标签与配置键。
- 授权管理：新资源进入现有权限目录、用户权限编辑器和登录态权限快照。
- 侧栏配置：价格巡检由 `admin_menu.price_monitor:view` 单独控制，不再增加另一套“侧栏模块”开关，避免两个开关互相冲突。
- 定时任务与快照：实现保持不变，只改变管理端配置写入入口。
- 公开分享：路径、密码和查询契约保持不变。

## Main Chain Impact

AI relay 请求协程不执行任何新增代码。本次修改只影响管理页面、管理 API 和启动时一次性授权迁移。每个 relay 请求新增 DB 查询、Redis 操作、锁和 goroutine 数量均为 0。

## Shared Resource Audit

- `casbin_rule`：主节点启动时执行一次短事务迁移；授权运行时本来就读取该表。迁移发生在服务启动阶段，不在 relay 热路径加锁。
- `channel_veridrop_detections`：不访问。
- `channels` 与模型价格配置：巡检任务继续按原逻辑读取；本次不增加查询次数、不改变索引或锁行为。relay 会读取渠道与价格配置，但本次管理入口迁移不新增共享协调锁。
- `price_monitor/snapshot.json`：继续由价格巡检后台任务原子覆盖，管理页只读取既有内存快照；relay 不访问。
- React Query：使用独立 `price-monitor-*` 查询键，不与 relay 或其它管理页面共享缓存。
- Redis、连接池、goroutine 池和文件句柄：无新增资源。
