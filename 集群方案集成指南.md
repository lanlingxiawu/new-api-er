## 2. 核心改动点总结

### 2.1 从旧方案升级到集群方案

**旧设计** (main.go中的定时任务):
```go
// 直接启动任务，多节点会重复执行 ❌
go StartGroupStatusAggregationTask()
go StartAlertsGenerationTask()
go controller.AutomaticallyTestChannels()
```

**新设计** (统一的任务调度器):
```go
// 1. 初始化任务管理器
service.InitTaskScheduler()

// 2. 统一注册任务
service.RegisterTask("GroupStatusAggregation", true, handler)
service.RegisterTask("AlertsGeneration", true, handler)

// 3. 启动调度器（自动处理分布式锁和配置加载）
service.taskScheduler.Start()
```

### 2.2 新增的表和字段

| 表 | 用途 | 关键字段 |
|---|------|---------|
| `distributed_lock` | 分布式锁 | lock_key, owner, expires_at |
| `scheduler_config` | 任务配置 | task_name, interval_seconds, enabled |

### 2.3 新增的API端点

```
/api/admin/scheduler/config                 - 查看所有任务配置
/api/admin/scheduler/config/:task_name      - 查看单个任务配置  [PUT更新]
/api/admin/scheduler/status                 - 查看所有任务状态
/api/admin/scheduler/locks                  - 查看当前分布式锁
/api/admin/scheduler/execute/:task_name     - 手动执行任务
```

**Step 1.3：创建 `service/distributed_lock.go`**

```go
package service

import (
    "time"
    "new-api-er/model"
    "new-api-er/common"
)

type DistributedLockService struct{}

var distributedLock = &DistributedLockService{}

// 尝试获取锁
func (s *DistributedLockService) TryAcquire(lockKey, ownerID string, ttlSeconds int) (bool, error) {
    now := time.Now().Unix()
    expiresAt := now + int64(ttlSeconds)
    
    // 删除过期的锁
    common.DB.Where("lock_key = ? AND expires_at < ?", lockKey, now).
        Delete(&model.DistributedLock{})
    
    // 尝试插入新锁
    lock := &model.DistributedLock{
        LockKey:   lockKey,
        Owner:     ownerID,
        AcquiredAt: now,
        ExpiresAt: expiresAt,
        CreatedAt: now,
        UpdatedAt: now,
    }
    
    result := common.DB.Create(lock)
    if result.Error != nil {
        return false, nil  // 锁已被持有，这不是错误
    }
    
    return true, nil
}

// 释放锁
func (s *DistributedLockService) Release(lockKey, ownerID string) error {
    return common.DB.Where("lock_key = ? AND owner = ?", lockKey, ownerID).
        Delete(&model.DistributedLock{}).Error
}
```

### 阶段4：添加配置管理API

**Step 4.1：创建 `controller/scheduler.go`**

```go
package controller

import (
    "net/http"
    "github.com/gin-gonic/gin"
    "new-api-er/service"
    "new-api-er/model"
)

// GET /api/admin/scheduler/config
func GetSchedulerConfigs(c *gin.Context) {
    var configs []model.SchedulerConfig
    
    err := common.DB.Find(&configs).Error
    if err != nil {
        c.JSON(http.StatusInternalServerError, gin.H{"error": err.Error()})
        return
    }
    
    c.JSON(http.StatusOK, gin.H{
        "success": true,
        "data":    configs,
    })
}

// GET /api/admin/scheduler/config/:task_name
func GetSchedulerConfig(c *gin.Context) {
    taskName := c.Param("task_name")
    config, err := service.schedulerConfigService.GetConfig(taskName)
    
    if err != nil {
        c.JSON(http.StatusNotFound, gin.H{"error": "Task not found"})
        return
    }
    
    c.JSON(http.StatusOK, gin.H{
        "success": true,
        "data":    config,
    })
}

// PUT /api/admin/scheduler/config/:task_name
func UpdateSchedulerConfig(c *gin.Context) {
    taskName := c.Param("task_name")
    
    var req struct {
        Enabled         *int `json:"enabled"`
        IntervalSeconds *int `json:"interval_seconds"`
        TimeoutSeconds  *int `json:"timeout_seconds"`
    }
    
    if err := c.BindJSON(&req); err != nil {
        c.JSON(http.StatusBadRequest, gin.H{"error": err.Error()})
        return
    }
    
    updates := make(map[string]interface{})
    if req.Enabled != nil {
        updates["enabled"] = *req.Enabled
    }
    if req.IntervalSeconds != nil {
        updates["interval_seconds"] = *req.IntervalSeconds
    }
    if req.TimeoutSeconds != nil {
        updates["timeout_seconds"] = *req.TimeoutSeconds
    }
    
    err := service.schedulerConfigService.UpdateConfig(taskName, updates)
    if err != nil {
        c.JSON(http.StatusInternalServerError, gin.H{"error": err.Error()})
        return
    }
    
    c.JSON(http.StatusOK, gin.H{"success": true})
}
```

## 5. 关键实现细节

### 5.1 节点ID生成

```go
// 必须保证集群中每个节点的ID唯一
func getNodeID() string {
    hostname, _ := os.Hostname()
    pid := os.Getpid()
    return fmt.Sprintf("%s:%d", hostname, pid)
}

// 或使用环境变量
func getNodeID() string {
    nodeID := os.Getenv("NODE_ID")
    if nodeID == "" {
        hostname, _ := os.Hostname()
        pid := os.Getpid()
        nodeID = fmt.Sprintf("%s:%d", hostname, pid)
    }
    return nodeID
}
```

### 5.2 锁的TTL设置

关键原则：**锁的超时时间 ≥ 任务的最大执行时间**

```go
// 获取锁时，TTL应该设置为任务的超时时间 + 安全余量
lockTTL := config.TimeoutSeconds + 60  // +60秒安全余量

acquired, _ := distributedLock.TryAcquire(
    lockKey,
    nodeID,
    lockTTL,
)
```

### 5.3 配置缓存机制

```go
// 配置读取流程：缓存 -> 数据库 -> 缓存
// 缓存TTL = 1分钟，确保配置更新及时生效

func (s *SchedulerConfigService) GetConfig(taskName string) (*model.SchedulerConfig, error) {
    s.cacheLock.RLock()
    if time.Since(s.cacheTime) < s.cacheTTL {  // 1分钟
        if config, ok := s.cache[taskName]; ok {
            defer s.cacheLock.RUnlock()
            return config, nil
        }
    }
    s.cacheLock.RUnlock()
    
    // 缓存过期，重新加载
    return s.LoadConfigFromDB(taskName)
}
```

## 9. 常见问题

**Q: 单机部署还需要这套系统吗？**  
A: 不需要。可以保持原来的简单方式。这套系统为集群场景而设计。

**Q: 如何在单机测试多节点场景？**  
A: 使用不同的 `NODE_ID` 启动多个实例：
```bash
NODE_ID=test-node-1 go run main.go --port 8080
NODE_ID=test-node-2 go run main.go --port 8081
NODE_ID=test-node-3 go run main.go --port 8082
```

**Q: 分布式锁故障了怎么办？**  
A: 通过API手动释放或等待超时自动释放：
```sql
-- 手动清理过期的锁
DELETE FROM distributed_lock WHERE expires_at < UNIX_TIMESTAMP();
```

**Q: 配置更新后什么时候生效？**  
A: 最多等待 60 秒（缓存TTL）。或者调用API立即刷新缓存。
